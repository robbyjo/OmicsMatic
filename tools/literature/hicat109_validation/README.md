# HICAT workflow evidence and fresh original replay

The [workflow guide](../scrattchhicat109/README.md) describes the exact private
source profile, constructor recipes, installation permissions, warnings and
recovery. The Java [cutoff API](../doublet_score_threshold/README.md) classifies
already supplied scores and computes no HICAT score. No family credit is added
until a separate catalog admission passes.

`replay.py` checks every archived payload and qualified source identity, then
regenerates all 26 complete project requests, including actual RNG states. It
makes fresh original calls and compares complete original returns, conditions,
errors and RNG with the frozen worker records. It also checks the public-runner
and both installed-runtime analyses against fresh original results. Both the
independent IEEE-754 oracle and all 13,824 successful original control scores
are checked through Java. This replay performs synthetic scoring; it does not
reproduce the paper or establish whole-package validity.

```sh
python3 -B tools/literature/hicat109_validation/replay.py \
  --runtime /private/completed-provider --out /results/NEW-hicat-replay
```

The provider requires unchanged upstream HICAT and RANN installed privately,
the exact locked dependencies and the complete original sources. Java and
javac must also be permitted. The verifier installs and downloads nothing.
**SKIP3 skips dependent verification; FAIL2 admits no complete qualification.**
Read the named cause and warnings, retain all partial/original files, provide
the exact permitted requirement or fix the named recording error, and retry
NEW paths. A numeric score file cannot override an error or skip.

Complete scientific R objects, original conditions, raw analysis consoles and
RNG are retained without deleting source fields. Project driver phase labels
are outside the original condition object. Comparisons never replace, rename,
round or impute scientific values. Complete objects and comparison differences
are kept alongside the derived checks.

The public numeric/control bundle contains no original HICAT source trees,
archives, installed libraries or runtime binaries. An audit of the original 368
scientific/provider RDS files found no original HICAT function bodies, saved
environments or external pointers. **Native compilation consoles remain
private and unchanged** because their diagnostics reproduce source excerpts.
`PRIVATE-COMPILATION-RECORDS.json` gives each whole withheld console's path,
byte count and SHA-256. These are not edited logs or omitted analysis
conditions. Run a permitted private installation to inspect its full native
compiler diagnostics; preserve its original help warnings and compiler
warnings. No native diagnostic total is asserted to be zero.

The selected upstream DESCRIPTION and LICENSE labels remain unresolved. All
original sources, build trees, runtime files and full compile consoles remain
in the private installation. The source adapter, independent Java predicate,
source identities and generated synthetic numeric records are separate project
artifacts. Hashes establish integrity rather than signatures or proof of a
biological result.

The semantic guards accept two unchanged copies and reject six deliberately
fabricated copies after rebuilding their complete logical file inventories.
Both saved direct and worker objects are changed in these negative fixtures;
they are compared with separately executed fresh original calls. The six
changes affect real scores, artificial scores, literal names, RNG, warnings and
an original failure falsely labelled successful. These are labelled negative
fixtures, not admitted scientific results. This tests the shared semantic
comparer after logical inventory resealing; it does not claim that the ZIP
envelope was rebuilt in those tests.
