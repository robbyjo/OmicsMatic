# Monocle catalog admission protocol

This owner adds one bounded upstream family. It revises nine existing Monocle
implementation scopes and one related P024 py-monocle use-category note, without
adding observations/reviews, crediting native helpers again or changing separate
Cicero/Batchelor/py-monocle implementation statuses. Read the
[source crosswalk](../../../docs/literature/MONOCLE_CATALOG_INTEGRATION.md).

`close_monocle_catalog.py --plan` requires NEW output, --primary-cache and
--checks-root containing the actual current original/native/source-control
receipts. It checks exact predecessor Git bytes and manifest, fresh250 XML/DOI
identities, the actual unchanged P99 owner, current scientific source and41
model/transaction plus8 source controls per host. It writes exact-before metadata,
qualification, source census and a complete preview. Canonical files stay untouched.

`--inspect --plan-dir PLAN` verifies all planned source, data and preview bytes.
Supplying --primary-cache and --checks-root repeats the relevant fresh source and
current-evidence checks. `--apply` requires all three arguments and repeats them
before writing. Its owned transaction restores old bytes on failure, retains
failed new files and preserves concurrent foreign edits. It refuses an existing
admission owner. Do not reset or overwrite failed evidence to reuse its path.

`--verify` checks the installed exact-before/after transition, full current
manifest, source/evidence fingerprints and review-only inverse. --primary-cache
adds a fresh all250/nine-role audit. Scientific analyses are not rerun. The current
registry provider is monocle_catalog.model.registry; older providers remain frozen.
The 485 definitions, paper membership and literal source identities are preserved.

The inverse affects only reviewed-uses.json scope strings for the ten identified
existing records. No dispatcher/scientific-source inverse or fingerprint waiver
is used. The actual predecessor is checked in its unchanged owner, not through
an overlay. Source provider, native helper and whole-paper boundaries remain
explicit. No new release or website deployment is authorized by these commands.

SKIP3 requires the named exact permitted cache/runtime/path or retention of the
dependent skip. If installation is prohibited, name the affected analysis and
what the user must supply. FAIL2 requires preserved diagnostics, correction of
the named source/data/numeric/integrity/ownership cause and NEW output. Read the
crosswalk's prominent warnings and required actions. Preserve all worktrees and
separately transfer ignored private runtimes/JARs/full text/evidence before machine
retirement; SHA256 provides integrity, not producer authentication.
