OmicsMatic v0.4.0 toolset freeze

The frozen tool boundary, software validation and known catalog qualification limitation.

The v0.4.0 release candidate is isolated on codex/release-v0.4.0-frozen. Its integration base is f87564288cf6e9d73a7d30164a96689b6ed861da, captured on 2026-11-15. Completed, validated additions are included; ongoing tool development continues independently. The original freeze created no public tag or release. Publication is now authorized for v0.4.0 with the known catalog limitation disclosed in the release guide.

Known catalog qualification limitation. The merged-source catalog verifier refuses the historical SingleR predecessor baseline after the study/manuscript changes. The original tool-specific qualifications remain preserved, but they do not establish a newly qualified whole catalog on this merged release tree. The recorded classifications below describe those existing scoped qualifications.

Release validation

The isolated software build/test gate passed on Windows with JDK 21.0.4: gradlew.bat check assemble --no-daemon --no-parallel --no-build-cache --max-workers=2 --console=plain. Across 878 suites, 25,519 tests were reported: 25,078 passed, 441 skipped, zero failures and zero errors. The skips include Linux-only controls, optional original runtimes and explicitly gated live or fixture checks; they are not fresh upstream validation. The test receipt retains all skip reasons, suite counts and raw-result hashes. Raw XML and HTML reports remain under build/test-results/test and build/reports/tests/test in the release checkout.

The packaged executable reports 0.4.0; its six-sample synthetic OLS coefficients and standard errors match an independent NumPy calculation to relative/absolute tolerance 1e-12. FUMA, SuSiE and study help entry points work. All 5,839 compiled library classes use Java class-file major version 61 (Java 17). Executable, library and source and Javadoc JAR ZIP integrity checks passed. These checks do not install or execute every optional upstream runtime.

The initial packaging attempt exposed Javadoc's implicit source lookup through resource directories. A resource Java launcher requires its private IGV runtime and is not a library API source. The release build now explicitly limits Javadoc source lookup to src/main/java; upstream resource bytes are unchanged. The corrected check assemble completed successfully, reusing the completed full-suite test results. Two existing Javadoc text warnings remain. Both build attempts and artifact hashes are recorded in the software-build receipt.

Linux release checks

The first tagged Linux/Java 17 run reported 25,519 tests, 15 failures and 377 skips and did not publish assets. Fourteen failures required private Nextflow runtimes absent from the hosted runner; the remaining test selected an unrelated decision.yaml using filesystem iteration order. The release correction changes test setup and artifact selection, not application code or the frozen toolset.

Unconfigured Nextflow original-runtime checks now report explicit skips. Supply -Djlinalg.nextflow.home.21.04.1=..., -Djlinalg.nextflow.home.22.10.6=... and -Djlinalg.nextflow.home.24.04.4=... to Gradle to exercise exact managed runtimes and their sibling setup reports. Explicitly configured invalid runtimes still fail. Runtime integrity assertions and the scientific comparison controls remain active when their prerequisites are provided. The sensitivity test selects the decision beside sensitivity-comparison.tsv explicitly.

The initial Linux run and its failure count remain part of the release history. Subsequent tagged builds retain their XML and HTML test reports as workflow artifacts. The initial tag target abf19f30f177e6122966c2ca4e4c0d3e9d03aeea produced no release assets; the corrected tag includes these test-harness and CI-reporting changes.

Full catalog verification requires a separate predecessor integration accounting for the merged study/manuscript/cleanup changes and release packaging changes.
