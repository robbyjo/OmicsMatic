Source-build tutorial. This walkthrough runs the checked-in, result-first two-cohort example through validation, resolution, plan approval, execution, verification, and resumable reuse. It also shows where an optional LLM may assist and how to keep patient-level data outside a remote LLM boundary.

What you will build

The example begins with two association-result tables rather than participant matrices. JLinAlg will standardize the inputs, compare discovery and replication effects, perform fixed-effect meta-analysis, run deterministic diagnostics, and write a traceable report. Every committed step is represented in the event ledger and the readable research notebook.

The tutorial is intentionally small enough to inspect by hand. The same contract and audit structure apply when a project begins with processed molecular matrices, has more cohorts or tissues, or stops at a later evidence stage.

The checked-in fixture uses analysis.mode: manual to stay small and completely offline. In a production study, omit that field or set mode: auto. Explicit goals then become the minimum requested work, and JLinAlg adds eligible association, replication, meta-analysis, enrichment, genetic-evidence, literature, diagnostic, prioritization, and report branches from the objective and declared inputs.

The default pipeline does not contact an LLM. An explicitly enabled assistance block defaults to an audited manual browser handoff for bounded advice, literature review and a first manuscript draft. Explicit alternatives include OpenAI Responses, Gemini GenerateContent and OpenAI-compatible Chat Completions with an API key or provider-issued OAuth bearer token. Browser transcripts and citations are human-attested, not authenticated provider output. JLinAlg retains control. MCP, provider-specific OAuth login/refresh, general pipeline local-model adapters and autonomous LLM orchestration remain future work. The llm actor option alone never enables a call.

Reuse completed analyses and run missing work

The current source accepts completed analyses under each hypothesis's analysis.supplied_results. These are scoped analysis artifacts, separate from the original cohort datasets. Use datasets: [] when only completed results are available. This feature is local source-build behavior beyond release v0.3.7; an enum naming a later dataset stage is not an import adapter.

For example, reuse an external meta-analysis and request only missing GO work:

yaml
schema_version: 1
project:
  id: completed-meta
  title: Complete GO from an existing meta-analysis
  description: External estimates with a declared full tested family.
resources:
  directory: project-resources
  network: offline
  downloads: deny
datasets: []
hypotheses:
  - id: H1
    description: Interpret the supplied BMI association estimates.
    outcome: BMI
    analysis:
      mode: manual
      goals: [gene_ontology]
      supplied_results:
        - id: external-meta
          kind: meta_analysis
          role: primary
          files:
            results: inputs/meta.tsv
            feature_annotation: inputs/feature-annotation.tsv
          columns:
            feature_id: gene
            beta: effect
            se: standard_error
            p_value: P
            adjusted_p: FDR
          scope:
            phenotype: BMI
            cohorts: [FHS, CARDIA]
            feature_id_type: ensembl_gene_id
            species: human
          method:
            name: Externally fitted meta-analysis
            software: your-analysis-software
            version: your-recorded-version
          family:
            id: complete-bmi-family
            coverage: complete
            tested_count: 20000
            adjustment: BH
            adjusted_p_from_full_family: true
          provenance:
            producer: your-analysis-team
          limitations:
            - Original participant QC and model calibration were not reproduced here.

Replace the example's count and metadata with the actual source records. Place the verified GO resource in this explicit project-local resource directory, or configure an existing verified resource location. Offline mode does not acquire missing resources. feature_annotation needs unique feature_id and gene IDs or symbols; optional locations also require scope.coordinate_system and a compatible build. GO uses the mapped complete eligible background and its declared selection threshold. A selected-only source cannot establish that background and leaves native enrichment waiting for the missing universe.

To import completed enrichment too, add a kind: gene_ontology artifact with files.results, its scope/method/family and optionally depends_on: [external-meta]. The planner reuses that artifact instead of rerunning GO. List all requested completed stages to build an all-results project. With mode: manual, goals define the requested missing computations; with mode: auto, eligible downstream goals are also inferred. A supplied primary meta-analysis removes inferred upstream association fits unless a missing declared validation branch needs them; explicit association goals still request those fits.

Mappings rename source headers to canonical names. Network mappings can be nested under the file roles nodes, edges and modules. Graph endpoints and module members must exist in the node table; signed weights and overlapping memberships are retained. Imported rare-set rows without beta/SE remain unsigned_set; no beta or direction is invented. The declared complete mask/test family determines correction, including nonprimary tests. Generic literature/source/investigation YAML summaries can also be retained as external evidence, but that is not independent source appraisal or complete claim binding.

The importer checks typed identities and numerical ranges, retains originals under supplied/, writes normalized tables and supplied-analysis.yaml, and records hashes, methods, family, source limitations and external attribution. Unknown table columns remain in the immutable raw snapshot, outside normalized AI evidence previews. Missing files or unresolved correction scope produce waiting_for_input; independent imports can continue. Invalid tables fail their import rather than triggering an unrequested replacement analysis.

Complete P-value families can receive declared BH/Bonferroni correction when tested_count matches their estimable tests. Existing source adjusted P values are preserved by default for complete families. For selected-only rows, declare coverage: selected_only, the original tested_count and adjusted_p_from_full_family: true, and supply adjusted_p. Downstream selection preserves those original values; significant-only rows never become a new BH family. An undeclared denominator is a missing input.

Use role: sensitivity for alternative external analyses. They cannot replace the primary or publish its canonical filename. Native omission/unfiltered comparisons against an imported meta-analysis require complete matching feature and cohort/source scopes, effect contracts, model/inference/confidence settings, source versions in provenance.input_sha256, and the exact sampling matrix when applicable. Otherwise that comparison waits. Neither a completed import nor matching metadata independently certifies the original scientific analysis.

For a thresholded coloc export, use evidence_grade: exploratory_partial_region_major_limitation and describe the missing variants/coverage in limitations. The mandatory caveat follows the import and evidence summary: conditional selected-variant evidence is limited, and a null result cannot establish absence of a shared causal variant.

Preserve supplied discovery FDR during validation

Register a completed discovery pool as kind: discovery_meta_analysis in analysis.supplied_results, with its original discovery scope, method and testing family. It replaces the discovery-pooling operation. The separate discovery_replication operation can then perform the missing validation work. Use analysis.mode: manual and goals: [discovery_replication] when that is the requested scope; automatic mode can request other applicable analyses. Native all-cohort meta-analysis still needs compatible cohort estimates.

A selected-only export must retain the original complete-family adjusted_p, declare family.coverage: selected_only, the original tested_count, correction method and adjusted_p_from_full_family: true. For example, a row with p_value: 0.000001 and source adjusted_p: 0.4 remains unselected at 0.05. JLinAlg must not recompute BH on the selected rows or on their overlap with validation results. Complete imported families preserve their source correction, including BY, Bonferroni or NONE, even when validation uses BH.

The source family and the validation family are distinct. With replication.adjustment_scope: discovery_subset, validation correction covers the available validation tests in the frozen discovery-selected subset. With all_results, it covers all available validation tests. A validation effect cannot change discovery eligibility. The registered sign and threshold rules still apply; significant opposite-direction effects do not satisfy a required same-sign replication rule.

primary-result-selection.yaml records the discovery producer, canonical table hash, source metadata hash, original denominator and adjustment origin. The selection is marked official_primary: false: a discovery-only pool does not become the official all-cohort meta-analysis. Producer-manifest and metadata snapshots remain in the operation, and its Methods record includes the two correction scopes. Changed, missing, incomplete or statistically unresolved source artifacts cannot silently select validation candidates or trigger a replacement discovery fit. Imported scope and scientific completeness remain source declarations requiring review; normalization does not independently reproduce or certify the original analysis.

Discovery cohorts represented by supplied pools

study operations lists analysis_reference as a supported context for harmonization and discovery/replication. Native meta-analysis still advertises cohort-estimate stages, because a reference cannot replace those estimates.

A completed discovery pool can support missing validation work even when the original discovery matrices and cohort result tables are unavailable. Register those discovery datasets with stage: analysis_reference, their real cohort membership, a supplied_result_id, and files: {}. The ID names a supplied primary supplied analysis in each hypothesis using the reference. For discovery validation, that owner is meta_analysis or discovery_meta_analysis; network-only reuse can instead name a network_analysis. The supplied scope must own that dataset or its declared cohort membership. A reference carries metadata; it contains no reconstructed cohort estimate or participant-QC evidence.

For example, these fields connect a supplied discovery pool to raw validation data in an otherwise complete study contract:

yaml
datasets:
  - id: discovery_a
    cohort: A
    type: expression
    stage: analysis_reference
    supplied_result_id: discovery_pool
    files: {}
  - id: discovery_b
    cohort: B
    type: expression
    stage: analysis_reference
    supplied_result_id: discovery_pool
    files: {}
  - id: validation
    cohort: V
    type: expression
    stage: processed_matrix
    files: {matrix: validation-expression.tsv, phenotype: validation-phenotypes.tsv}
    columns: {sample_id: id}
hypotheses:
  - id: H
    description: Validate the frozen external discovery findings.
    outcome: BMI
    inputs: {discovery: [discovery_a, discovery_b], replication: [validation]}
    analysis:
      mode: manual
      goals: [association, discovery_replication]
      association: {model: ols}
      supplied_results:
        - id: discovery_pool
          kind: discovery_meta_analysis
          files: {results: discovery-pool.tsv}
          scope:
            datasets: [discovery_a, discovery_b]
            cohorts: [A, B]
            phenotype: BMI
          method: {name: Original discovery meta-analysis}
          family:
            id: original-discovery-family
            coverage: selected_only
            tested_count: 400000
            adjustment: BH
            adjusted_p_from_full_family: true

The pool table must contain the validated original adjusted_p values. Declare the actual cohort relationships in the study; missing independence declarations remain review needs. The example OLS route is only appropriate for its registered outcome/design. A supplied pool does not choose or validate the missing model.

For this contract, association/QC execute for the validation matrix. Neither discovery reference requires a placeholder file, a reconstructed association fit or retrospective participant QC. analysis-references.tsv records reference ownership separately from actual harmonized cohort tables. Ordinary dataset stages retain their file requirements. A missing supplied file holds its import while independent work can proceed; JLinAlg does not select a native discovery replacement.

Before validation uses an imported discovery pool, discovery-scope-audit.yaml checks exact discovery dataset/cohort sets, reference ownership, the registered trait key and discovery/validation separation. If both source membership lists are supplied, both must agree with the study. Trait keys match the registered outcome/exposure exactly; aliases are not inferred. Known cohort relationships, shared cohort identities and sampling-matrix links are checked using all role metadata, including discovery cohorts without tables.

Known source/registered effect, units, assay, tissue, modality, species, build or feature-namespace conflicts hold selection. Units preserve case, including scientifically meaningful prefixes. Existing registered assay/tissue/modality context exceptions retain their rationale; they do not waive cohort independence or effect-unit conflicts. Incomplete effect contracts remain explicitly uncertified by default; pooling.require_complete_contract: true requires complete source declarations as well. Genomic source/validation comparisons check available allele and coordinate coding on shared eligible variants; conflicts hold without automatic allele flips or sign changes. Missing coding remains a limitation and holds the strict profile.

A pooled reference cannot supply an independent validation estimate. It also cannot be substituted for its constituent cohorts in a new native all-cohort meta-analysis: that requested fit waits for the actual cohort estimates rather than pooling only whichever validation tables happen to be available. Reusing a supplied all-cohort primary meta-analysis remains a separate typed import.

GWAS QQ and Manhattan diagnostics

The source build adds gwas_diagnostics after available association and pooled results. Automatic studies request it for compatible genomic association/raw inputs or genomic supplied pools. Rare-set-only and later evidence-only inputs do not imply missing upstream SNP scans; the SNP-based GWAS enrichment trigger uses the same input distinction or an explicit SNP-summary file. Manual studies can request the goal explicitly; gwas_diagnostics.enabled: false suppresses the automatic goal. A supplied primary diagnostic artifact satisfies that stage without refitting its external analysis.

yaml
# Inside an existing hypothesis.analysis:
mode: manual
goals: [gwas_diagnostics]
gwas_diagnostics:
  minimum_lambda_tests: 20
  dataset_coverage: {cohort_a: complete, cohort_b: unknown}
  maf_breaks: [0.01, 0.05]
  mac_breaks: [20, 100]
  info_breaks: [0.8, 0.9]
  maximum_rows: 2000000
  maximum_plot_points: 100000
  maximum_strata: 200
  plot_y_limit: 1000

Coverage declarations name selected genomic dataset IDs. complete means the declared original eligible export is available, including nonsignificant tests; the declaration does not independently reproduce source QC or calibration. Unannotated external cohort exports default to unknown. Completed native association producers establish their observed export scope. Native pools have a complete diagnostic scope only when all expected constituent dataset scopes are complete. A typed supplied pool retains its authoritative source family: selected-only exports or a tested denominator larger than available eligible rows cannot become complete genomes merely because original FDR values exist. Incomplete source producers retain observed diagnostics with an explicit limit.

Each source has an immutable statistics snapshot, producer-manifest snapshot, original supplied-metadata snapshot when applicable, and a row disposition table. The diagnostics keep cohorts, pooled/discovery results, model contrasts and available pre-effect-QC companions separate. They do not combine P values across cohorts or choose the least-inflated source as the primary result.

QQ numerical tables retain every eligible finite-log P value. The displayed uniform reference uses order means i/(n+1) within the named source/contrast or stratum. The summary's lambda_p_chisq1 is the median one-degree-of-freedom chi-square transform of those P values divided by the chi-square median. For even counts it averages the two middle transformed statistics, rather than transforming the median P value. This is a descriptive P transform; it is not a model-specific raw-statistic inflation estimate, an LD-adjusted confidence band or a calibration certificate. Selected, unknown, unresolved or too-small exports have no reported lambda. Partial exports use an observed-rank display without a null-reference line.

Finite nonpositive natural-log P values preserve underflowed or rounded zero exports. A zero without a usable log P stays unresolved. Conflicting positive P/log-P pairs are retained in the row audit and prevent a complete calibration summary. No minimum floating-point P is silently substituted. Source exclusions and failed fits remain distinct from unresolved eligible tests.

Separate summaries/QQ plots stratify available MAF, MAC, INFO and source test/calibration labels using the registered breaks. Unknown fields remain unknown; INFO interpretation depends on its provider. The strata are diagnostic descriptions, not new association tests or retrospective SNP exclusions. Source counts and historical filters must still be reviewed before accepting imported results as compliant with a registered single-marker MAC policy.

Manhattan tables retain available declared chromosome/position coordinates and their observed chromosome offsets. Registered source builds can supply missing row context; known row/source build conflicts hold that coordinate plot without liftover or inferred alleles. Mixed builds, missing coordinates and unknown builds are reported separately. Coordinates are not guessed from rsIDs or gene names, and missing-coordinate coverage is not called a genome-wide null result. Native pooled plots can project coordinates from their sealed fitted-contributor metadata ledger when contributor identities/counts and known coordinates/builds agree. Missing/conflicting contributors retain explicit dispositions. That projection never copies cohort P values, MAC, MAF or INFO into pooled statistics; the pooled P distribution and unavailable pooled strata remain separate.

PNG/PDF rendering has explicit point and Y-axis limits. QQ rendering preserves the strongest tail before thinning the remaining full-universe ranks. Manhattan rendering retains the minimum-P peak in each consecutive coordinate bin. Numerical tables retain all eligible rows and uncapped values. Crossing a row or stratum budget holds the affected work instead of analyzing only top hits. The current adapter bounds in-memory row processing; raising the budget does not establish genome-wide scale or memory suitability on a particular host.

Inflation or deflation can reflect polygenicity, LD, ascertainment, discrete tests, model behavior and confounding. This branch does not perform genomic control, replace original P values, alter FDR, certify ancestry adjustment or change the official primary source. Interpret it with the LD Score regression paper and the actual study design; probability plotting is described in the NIST handbook.

To reuse externally completed diagnostics, supply a gwas_diagnostics artifact with files.results and the normal scope/method/provenance fields. Its TSV has source_id, contrast, stratum, testing_coverage, observed_tests, diagnostic_tests, unresolved_tests, lambda_p_chisq1, lambda_status, coordinate_tests and coordinate_status. Counts and lambda dispositions must agree; an incomplete/selected export cannot claim an available lambda. Extra figure files can be retained under named file roles. External numbers remain externally attributed and are not independently recalculated from missing data. Aggregate source summaries enter finding dossiers and Methods with their limitations; they provide study context rather than independent replication.

Scientific scope and missing cohort networks

Each typed import writes supplied-scope-validation.yaml and supplied-scope-comparisons.tsv. These compare declared traits, populations and available effect/context metadata with the registered hypothesis. A known conflict holds the import and prevents canonical statistical selection. The original files remain available locally, including a normalized supplied-results-scope-limited.tsv when table rows conflict with their declared build or sequence. Missing context is recorded as partially_declared_not_certified; it is not inferred from prose or treated as an independently verified scientific match.

Trait keys match hypothesis.outcome exactly, with the registered score outcome and related phenotype columns used for score work. A primary supplied meta-analysis can provide an explicit registered target when no outcome key is available. Primary population-bound association, diagnostic and enrichment artifacts require matching known dataset/cohort sets; sensitivity imports may cover a subset. Discovery-only imports use the discovery inputs. External MR, colocalization, fine-mapping and score evaluation populations can differ from the association cohorts. Annotation, structure and literature context do not inherit the association phenotype; their own declared build/sequence checks still apply. These comparisons are input checks, not source reproduction or scientific certification.

A known incompatible declared upstream source holds its downstream import. An unavailable upstream file alone does not require rerunning an independently supplied downstream analysis: the missing lineage remains a review limitation. Before consumers use a completed parent, its sealed metadata and hash must agree. No conflicting import silently triggers a native replacement.

For networks, reuse is scoped by dataset/cohort rather than suppressing the whole stage. For example, supply A's graph and retain B's raw molecular matrix:

yaml
# Inside the existing hypothesis.analysis:
mode: manual
goals: [network_modules, module_gene_ontology]
network:
  complete_missing: true
  correlation: pearson
  threshold: 0.7
  preprocessing: Record the actual assay-specific normalization here.
supplied_results:
  - id: graph_a
    kind: network_analysis
    files:
      nodes: A-nodes.tsv
      edges: A-edges.tsv
      modules: A-modules.tsv
      feature_annotation: A-annotation.tsv
    scope: {datasets: [a], cohorts: [A], phenotype: BMI, species: human}
    method: {name: Original cohort A graph, edge_direction: undirected}

With dataset a bound to graph_a as an analysis_reference and a processed matrix dataset b in cohort B, JLinAlg reuses A's graph/memberships and fits only B's graph. It plans modules and module GO separately for each source. Available raw data for A do not cause its supplied graph to be refitted. A single supplied graph covering A and C remains one graph; its edges are not reconstructed as separate cohort graphs. Multiple primary graph imports need explicit comparable disjoint dataset or cohort scopes. Use separate hypotheses or sensitivity roles for overlapping alternatives.

network.complete_missing defaults to true. If scope cannot be mapped and native matrices are present, the source waits for review and the planner does not guess which matrices to fit. A held source reserves its declared coverage; clearly uncovered independent B work can still finish. Set complete_missing: false to process only supplied graphs/modules when any primary graphs are supplied. This is an explicit supplied-only choice, not evidence that omitted cohorts were analyzed. It does not waive known source conflicts.

Original source methods, parameters, provenance, family rationale and free-text limitations stay in local supplied-analysis.yaml. Automatic Methods records and finding dossiers use aggregate scope flags and testing-family facts, with a mandatory source-review caveat. Scientists must review the retained original limitations before writing scientific conclusions. This boundary is not a general disclosure or scientific-validity certification.

Molecular networks, pathway overlap, modules and module GO

The source build registers network_analysis, pathway_network, network_modules and module_gene_ontology as separate study operations. Correlation networks use one supported bulk molecular matrix per dataset, preserving cohort-specific populations. Pathway networks connect completed enrichment/GSEA terms by gene overlap; the separate ranked_gsea operation fits native preranked enrichment. Pathway overlap does not measure molecular correlation. Automatic mode infers correlation/module/GO branches for supported bulk matrices, unless network.enabled: false. A supplied enrichment source matching network.source_kind can infer pathway/module/GO work. In manual mode, request desired missing stages explicitly:

yaml
analysis:
  mode: manual
  goals: [network_analysis, network_modules, module_gene_ontology]
  network:
    correlation: spearman
    threshold: 0.7
    thresholds: [0.6, 0.7, 0.8]
    categorical_covariates: [sex, batch]
    preprocessing: Log-normalized expression after the recorded assay QC.
    bootstraps: 100
    independent_samples: true
    minimum_clique_size: 3
    max_cliques: 10000
    max_search_states: 1000000
    max_clique_depth: 128
    go_min_module_genes: 3
    go_min_size: 10
    go_max_size: 500
    go_adjustment: BH

Use actual preprocessing records and an appropriate independent biological unit; unique sample labels do not certify independence. Related samples, repeated visits, cells/spots and compositional data require an appropriate supported model or external graph. Explicit goals still request work when automatic inference is disabled.

Correlation input is a feature-by-sample matrix. Sample selection is listwise over that complete matrix and hypothesis covariates; outcome values and association-hit selection are not used. Network populations can therefore differ from association populations. Numeric covariates and explicitly named categorical covariates enter an intercept plus full-rank OLS design, using the dataset phenotype/sample mappings. Categorical reference levels are recorded. Pearson or average-tie Spearman correlations are computed after residualization. The latter is Spearman correlation of residuals, not rank-first partial-Spearman equivalence. Rank-deficient designs fail rather than silently drop covariates. Constant/fully explained or numerically unresolved features have dispositions and a recorded numerical-variation rule.

Edges retain signs and use abs(rho) >= threshold. Prespecified threshold-range edge/Jaccard diagnostics do not select a new primary cutoff. Row bootstraps resample the frozen residual matrix and require independent_samples: true; frequencies measure conditional stability, not edge P values/FDR or uncertainty in fitted preprocessing. Degenerate resamples count as nonselection. Bootstrap defaults to zero and is explicitly reported as unassessed. Signed tables, feature QC, local sample audits, stability tables and GraphML are retained. Participant-audit contents do not enter bounded network evidence summaries.

Dense work is bounded at 2,000 features, 20 million stored values and registered max_pair_work (100 million by default, at most two billion pair-observation-replicate units). max_samples defaults to 10,000 and minimum_samples to 10. Exceeding a bound waits; no top-hit or top-variance subset is invented. Register an outcome-independent universe or an external scalable adapter.

Module analysis distinguishes connected components, including isolates, from overlapping maximal cliques. Its pivoted Bron–Kerbosch search has count, search-state, feature and depth bounds because maximal clique lists can grow exponentially. Reaching a bound retains partial memberships with an incomplete status. Joint module GO waits rather than correcting an incomplete prefix. Topology does not establish biological function or a unique module partition.

For supplied graphs, files.modules is reused when present. Otherwise the module branch computes topology from supplied nodes/edges. Declare method.edge_direction: undirected; directed/multilayer graphs require an explicit supported projection. Supply files.feature_annotation for gene mapping and scope.species. Source caveats follow module and GO evidence. Requesting only network_analysis in manual mode does not force module work.

Native ranked GSEA and leading-edge pathway networks

The source build now executes ranked_gsea natively, using the public RankedEnrichment API. It supports complete gene-level ranking files and complete scoped signed association/meta-analysis results. This is preranked gene-set permutation analysis. It does not silently replace requested phenotype, pedigree or block-aware permutation with a gene-set null. See the GSEAPreranked documentation and the original GSEA paper for the method distinction. The later phenotype-null guide adds native independent OLS residual permutations and complete model-null ranking reuse.

Replace the example's count/provenance with the actual source records. The file needs unique gene IDs, finite statistics, declared complete coverage and a tested_genes count matching its rows. Selected/significant-only lists and unknown denominators wait. Table counts do not independently reproduce the original model, QC or true universe. Align gene namespaces/releases upstream; the program does not infer gene symbols or biological contrasts from arbitrary IDs. A provided GMT defaults to collection GMT; without one, the default collection is human GO. Supported built-in GO/Reactome packages require matching species and namespaces and retain verified manifests/releases. Otherwise supply a compatible local GMT; MSigDB files are user-supplied under their access terms.

Without gsea.ranking, the planner reuses the completed primary all-feature meta-analysis, or creates separate GSEA operations for individual cohort association results when no primary pool exists. It does not silently pool cohorts. The default statistic is signed beta/se; an explicit statistic: column with statistic_column selects another preserved numeric statistic. Every valid eligible feature is considered, including nonsignificant features; no association-FDR selection precedes ranking. Source exclusions/unestimable statistics and unmapped genes retain dispositions. Supplied selected-only meta results cannot establish a complete ranking. A declared full tested denominator larger than the available feature table also waits, even if an export has been relabeled coverage: complete.

Multiple features mapping to the same gene require an explicit coherent collapse: mean|median; the default require_unique waits. No best-P probe is chosen. Isoform/probe effects with different meanings should not be averaged without a scientifically appropriate protocol. Source gene mapping can use symbols or Ensembl gene IDs; other namespaces may require a prepared ranking. Variant-level GWAS beta/SE or nearest-gene SNP assignments are not treated as independent gene scores: supply an appropriate gene-based, LD-aware ranking. Preranked gene-position inference is still distinct from LD-aware GWAS enrichment and does not perform MAGMA or stratified-LD-score analysis.

Tied statistics default to an explicit prerequisite, following the ranking ambiguity described by the GSEA documentation. tie_policy: gene_id permits deterministic lexical ordering with a mandatory caveat; it does not resolve the biological ordering. Gene IDs and source inputs are preserved as immutable, hash-checked snapshots. weight_exponent: 0 is classic uniform-hit scoring; 1 is the default weighted score, and 2 is supported. The chosen weight must fit the interpretation of the ranking metric.

The running sum adds normalized absolute-statistic weights for hits and uniform decrements for misses. ES is its signed largest absolute excursion; extrema within 1e-12 choose the positive direction. Positive leading edges end at the maximum; negative leading edges follow the minimum. Null memberships retain the observed set size within the complete ranked universe. If their complete combination count is at most maximum_exact_states, all memberships are enumerated. Otherwise seeded sampling without replacement generates the registered number of null draws, shared by set size. NES divides ES by the mean absolute same-sign null ES. Exact P values use same-sign tail counts; Monte Carlo P values use (tail + 1)/(same_sign_draws + 1) and never claim zero.

Outputs retain actual null/tail counts, conditional P resolution and 95% Wilson intervals for Monte Carlo tail probabilities. Those intervals exclude ranking, null-model and multiplicity uncertainty. BH/BY/NONE applies to the complete eligible term family; it is not Broad's pooled-NES empirical GSEA FDR. Terms with undefined zero hit weights or insufficient same-sign nulls leave the family incomplete, produce retained limited results and block official pathway selection. Terms excluded by prespecified size/universe rules have separate dispositions. A valid collection with no eligible terms completes with zero tests; an empty/missing resource is a different input problem.

Native limits default to 50,000 ranked genes, 20,000 sets and 250 million estimated hit/null work units, including each term's tail comparison against shared null draws. Hard limits and a five-million-membership collection bound prevent unbounded dense work. Exceeding a bound waits or rejects invalid resource input without choosing favorable terms. Registered precision/work tradeoffs remain visible; reducing permutations cannot be presented as strong evidence below the resulting simulation resolution.

ranked-gsea.tsv, ranked-genes.tsv, leading-edge.tsv, term/mapping dispositions and gsea-analysis.yaml preserve the full analysis. Up to curve_plots diagnostic curves are written as numeric TSV plus PNG/PDF, ordered by adjusted P, absolute NES and term ID. This plot budget does not truncate testing or select manuscript findings. tested-gene-sets.gmt preserves matched membership and feeds the pathway network automatically. To connect leading edges instead, explicitly set network.membership_column: leading_edge_genes. The graph preserves GSEA's actual correction and species/namespace, and downstream modules/GO retain the conditional-null caveats. GSEA term dossiers retain NES, leading edges, simulation precision and corresponding pathway-module memberships.

Automatic mode infers GSEA and compatible downstream pathway work for supported molecular matrices/results; gsea.enabled: false suppresses that inference. Explicit goals still request work. Supplied ranked_gsea artifacts satisfy the stage without native refitting. Unsupported phenotype/block nulls require an appropriate external analysis/import; they are not silently downgraded.

Held-out risk scores and missing related-phenotype work

The source build registers native risk_score_evaluation and risk_score_related_phenotypes. The first can develop a quantitative or binary molecular score, apply a frozen model/weights/scores, evaluate held-out performance and test registered related traits. The second completes related-trait testing when performance has already been supplied. Its input is a frozen score/model; it does not rerun development or performance estimation.

The PRS reporting standards provide a framework for describing populations, development, evaluation and limitations. Source study/design suitability still needs scientific appraisal. Training-only preprocessing also applies to feature selection, normalization, imputation and external batch adjustment. A valid file layout cannot certify how upstream data were prepared.

Feature imputation means and standardization use actual development rows only. The default missing-predictor policy is error; training_mean learns means within each fit. Raw binary scores report rank AUC with half credit for ties. The default 200-replicate percentile bootstrap resamples the declared independent units, retaining all rows in each sampled cluster. A window that cannot cover the declared sets, or a capacity limit, cannot silently drop pairs or replace missing covariance with zero. Simulation resolution and approximate calibration limit inference; increase justified budgets or select a supported calibration before interpreting very small P values. See the ACAT method workflow and SAIGE set-test documentation for the distinction between masks, allele counts and calibrated tests.

These are set/mask tests, not an automatically calibrated gene-level omnibus across masks or across phenotypes.

Effect-size quality control before downstream analysis

Numerically finite coefficients can still be extreme: a nearly constant predictor, ill-conditioned design, separation, unit mismatch or unstable fit can produce a very large coefficient and SE. A large raw coefficient is not itself proof of a bad association, and summary statistics cannot establish the cause. Do not hide these points by clipping a plot or choose exclusions to improve correlation or significance. Inspect predictor variation, units and upstream fit diagnostics.

JLinAlg now applies an auditable, conservative effect-size QC screen to supplied association results during harmonization and to newly fitted association results before annotation. The defaults are:

yaml
analysis:
  harmonization:
    effect_outliers:
      enabled: true
      robust_z: 100
      min_features: 20
      # max_abs_effect: 1000  # optional; choose only with known effect units

For each dataset separately, using all numerically eligible association rows, the center is the median beta and the robust scale is 1.482602218505602 * median(abs(beta - median(beta))). If this scale is zero or nonfinite, use (Q75 - Q25) / 1.348979500392164 with linearly interpolated quantiles. Exclude estimates with abs(beta - center) / scale > robust_z. This is a configurable QC heuristic, not a calibrated hypothesis test or a universal biological plausibility cutoff. The conservative default of 100 is intended to catch gross extremes, not trim an ordinary heavy tail. Uniform changes of effect units do not change the relative selection. It uses neither P values nor agreement with other cohorts. Relative screening is explicitly skipped below min_features or without a positive finite robust scale; no epsilon denominator is invented. An optional abs(beta) > max_abs_effect rule still applies to these families. An approved plan with effect QC enabled now includes an automatic, isolated unfiltered sensitivity branch. Set enabled: false only when the declared primary analysis itself omits this screen.

The operation writes effect-outlier-summary.tsv, effect-outlier-exclusions.tsv (dataset, feature, beta, SE, P, robust score and reason) and effect-outlier-qc.yaml (effective settings, counts, fallbacks, skips and caveats), all included in its output manifest and Methods inventory. The source files are untouched. pre-effect-qc-results/*.tsv retains the numerically/status-eligible estimates before effect screening. Primary comparisons/correlations, discovery/replication, FDR, meta-analysis, cohort-omission sensitivities, enrichment, MR and colocalization selection consume QC-eligible estimates. With common_universe: intersection, the intersection is computed after QC within each operation's selected cohort set. Otherwise only the flagged dataset estimate is removed; valid estimates in other datasets remain eligible under the usual minimum-cohort rules. The testing family is the retained eligible family. This rule also applies to later matrix-association outputs through derived branch-specific input tables, without rewriting the upstream association results. Discovery-only pooling computes its family using discovery cohorts; missing validation coverage cannot delete a discovery test.

The sensitivity_analysis operation retains effect-qc-unfiltered/ alongside other sensitivity outputs. It repeats cohort comparisons, any completed primary meta-analysis, discovery-only pooling and validation with only the effect screen disabled. Each branch recomputes its declared eligible universe and full BH/NONE testing family. feature-sensitivity.tsv records retained estimates, adjusted P values, significance and directions; replication-sensitivity.tsv compares discovery selection and validation. decision.yaml records family denominators, the precise scope and primary_unchanged. Upstream sample/genotype QC and invalid or failed estimates remain excluded. No unfiltered finding enters primary enrichment, MR or manuscript selection automatically. Missing/tampered snapshots cannot silently substitute a smaller cohort set.

Because selection uses estimated effects, it is not an independent-filtering procedure that guarantees unchanged FDR calibration merely by avoiding P values. Prespecify the policy where possible and retain an unfiltered sensitivity analysis.

Record a post hoc QC change as an amendment, review exclusion counts and unit/model diagnostics, and review the labeled unfiltered sensitivity before changing scientific conclusions. Entirely excluded primary families are retained as not estimable; the sensitivity does not replace them. New software has a different cache identity and preserves earlier attempts rather than reusing their outputs as current evidence. It does not overwrite sealed results, redraw historical figures or repair an already completed manuscript. Never claim old results used this screen based on the current software defaults.

Publication citations and parameter reporting

Explaining observed results from the study contract

Claim-adjacent references

Native study manuscript revisions use numbered citations in first-appearance order, reuse the same number for repeated references, and link superscript brackets to the References section at the end of the paper. The reference list follows Nature-style numerical ordering and bibliographic fields; the brackets are an explicit display choice, not a claim of exact journal typesetting. The separate reference catalog retains retrieval provenance and uncited candidates.

Every statement drawn from a journal needs a citation, including Methods, bioinformatics context beside Results, and Discussion—not only Introduction. Place the token beside the supported claim, before punctuation:

yaml
citation_policy: strict
sections:
  - id: methods-fdr
    section: methods
    methods_role: discovery_replication
    citation_basis: literature
    text: >-
      We used Benjamini–Hochberg adjustment[[cite:10.1111/j.2517-6161.1995.tb02031.x]],
      with FDR < 0.05.
    sources: [H1.discovery_replication]
    rationale: Cite the performed method without changing the analysis.
    parameters: {method: BH, alpha: 0.05}

citation_basis may be literature, study_results, study_design, interpretation, or not_applicable. Mixed prose containing a journal-derived claim is literature. supporting_evidence entries have the same citation fields for their relationship text. Multiple references in one token are separated by semicolons. DOI, pmid:ID, and retrieved reference IDs are supported.

Strict mode rejects missing classifications, uncited declared literature prose, unplaced reference assignments and unresolved identifiers before creating the revision output. Compatibility mode (citation_policy: review, the default for older requests) preserves older prose, displays assigned references and records gaps in citation-review.yaml. It does not certify the draft as ready. No deterministic checker can establish that a citation supports every sentence or detect all undeclared borrowing; scientist review is still required.

validate checks the versioned structure, IDs, cross-references, analysis goals, and—because --check-files is present—the declared paths. It reads but does not resolve or execute the project.

Before continuing, inspect the input tables. Each row has a feature ID, effect, standard error, and p-value. A result-first meta-analysis requires compatible effect definitions and units; syntactically compatible columns are not evidence that two scientific estimands are interchangeable.

If one physical table contains several phenotypes, declare one logical dataset per phenotype and reuse the file path with different column mappings. The result-first contract vignette shows how to handle R row names, invalid-row exclusion, a strict cross-cohort feature intersection, discovery-subset FDR, and direction-independent validation.

3. Resolve defaults and inspect the contract

Resolve the human contract into an immutable, fully explicit contract:

powershell
java -jar $jar study resolve study.yaml --actor-id scientist-1

This creates:

  • resolved-study.yaml, including expanded defaults and assumptions;
  • ledger/events.jsonl, the append-only machine-readable event history;
  • SESSION_HISTORY.md, the readable research notebook;
  • state/project-status.yaml, a materialized progress view; and
  • AGENTS.md, a derived working brief for a person or future agent.

Review all five. study.yaml remains the human-authored source, while resolved-study.yaml is the exact contract from which the plan is compiled. Directly editing the base study after resolution cannot replace the approved contract; project changes use amendments.

4. Compile and approve the plan

Compile a deterministic operation graph and inspect it before approval:

powershell

java -jar $jar study status --project .
Get-Content plans/*/analysis-plan.yaml

The plan identifies each operation, its datasets, dependencies, executor, configuration, expected outputs, and registered diagnostics. Planning does not run an analysis.

Approval is a separate human event:

powershell

5. Execute the approved operations

Run the plan:

powershell
java -jar $jar study run --project . --actor-id scientist-1

The example completes five operations. Under runs/run-<plan-id>/operations/, inspect:

  • standardized association tables and their source hashes;
  • replication.tsv, including adjusted discovery and replication p-values, sign concordance, and the final replicated indicator;
  • meta-analysis.tsv, its log, and captured console output;
  • diagnostics.yaml, including cross-cohort correlation, OLS scale/slope, sign concordance, discovery-selected and replicated counts, meta-analysis FDR/heterogeneity counts, the unique count replicated in any validation cohort, and the current unusual-observation list; and
  • report.md, whose result IDs link the report to operation manifests.

Every operation directory also has a manifest.yaml with its configuration, inputs, output hashes, timestamps, executor, and state. The run-level run-manifest.yaml summarizes the operation states. The exact directory names come from the plan and should be discovered from the manifest rather than hard-coded in a downstream script.

For mode: auto, functional and genetic follow-up branches are independent. JLinAlg runs local GO and Reactome enrichment when feature mapping is available; annotation_release: GENCODE_v48, for example, permits an audited public GENCODE transcript-ranking and HGNC-symbol mapping download. Public references are fetched by the HTTP client embedded in the executable JAR; curl, Python, and a separate downloader are not required. If eligible variant-level work requires LD, the default is the checksum-verified 1000g-phase3 package with five ancestry panels. It is downloaded only when that branch is eligible, and resources.ld.population: auto waits for an ancestry choice rather than silently assuming EUR. A missing regional molecular-QTL or outcome-GWAS table becomes a precise request.yaml; it does not block enrichment or reporting.

6. Verify and safely resume

Verify the evidence chain:

powershell
java -jar $jar study verify --project .
java -jar $jar study run --project . --resume --actor-id scientist-1
java -jar $jar study verify --project .

Verification recalculates hashes for the base and resolved contracts, plans, amendments, observations, derived notebook files, manifests, and operation outputs. Resume reuses only verified complete artifacts. A changed output is an error, not a cache hit.

--resume is now optional. Both study run and study auto resume by default. Every invocation retains a separate immutable attempt, reusing only completed operations whose input hashes and implementation identity match. Waiting and failed operations are retried; changed upstream outputs invalidate dependants. The index shows the latest attempt by default and offers a historical-attempt toggle; historical blockers do not count as current blockers.

Resume preparation while downstream inputs arrive

Native validate_harmonize, participant_qc and association record the native_cohort_preparation_v1 input scope. They retain the current hypothesis, its referenced dataset metadata, model/covariate/QC settings, scientific root settings, input content hashes, operation/dependency identities and executable identity. Distinct downstream genetic source file roles and downstream analysis settings do not enter these preparation keys. Roles shared with preparation, such as results or annotation, remain conservatively bound. A reporting-policy amendment or a separate hypothesis can therefore reuse an unchanged completed fit. Changed phenotype, matrix, model, covariate, relevant QC or dependency content invalidates it.

The scope remains deliberately conservative: operation IDs and dependencies must match, and changes to root resources, cohort relationships or assumptions can invalidate preparation. Other stages, supplied-result imports, configured commands and third-party executors retain full-study context. A new executable also invalidates reuse. This does not promise minimal recomputation for every possible amendment or arbitrary external command.

study auto accepts unavailable declared dataset files as validation warnings. An absent declared preparation input makes its native stage wait; downstream source files belong to their consuming stages. Independent available work can continue. Malformed contracts, integrity failures and missing data dictionaries needed to resolve the contract still block execution. Use the explicit strict check when every declared file should already be present:

powershell
java -jar $jar study validate study.yaml --check-files

Each run retains input-availability.yaml and its hash in run-manifest.yaml. This receipt records presence and observed size, not consumption or scientific validity. The operation's input_sha256 records its declared content inputs; intake's inputs.tsv covers preparation inputs. Reused manifests retain execution_resolved_study_hash from the original execution and separately record current_resolved_study_hash, context_hash, input_scope and reused_from. Prior attempt bytes remain unchanged. Availability observations cannot replace typed source contracts, complete tested families or scientific review.

The offline examples/study-pipeline/stage-resume-workflow.py source-checkout example exercises native association followed by missing/completed MR, reporting and hypothesis amendments, input revision and forced rerun. Synthetic declarations and source-review flags establish software behavior only.

Use study auto study.yaml --rerun for a complete recomputation, bypassing result reuse without deleting earlier evidence. --overwrite is deliberately not used. --offline (or resources.network: offline) prevents built-in network requests; available local work continues. Missing resources and blocked providers are shown in the index. Repeating without --offline retries unfinished work. An HTTP 403 is recorded as an endpoint/authorization denial, not asserted to be a firewall diagnosis. A timeout or failed search never becomes “no association” or “no literature.” No concurrent execution is allowed in the same project; do not amend it while a run is active.

The rebuilt index has four complementary entry points:

  • index/index.html for interactive search;
  • index/index.json for artifact-level retrieval;
  • index/evidence-summary.json for a portable machine handoff; and
  • index/LLM_CONTEXT.md for paper drafting or drug-prioritization retrieval.

The LLM context embeds the compact deterministic diagnostics and the leading GO, Reactome, or candidate-prioritization rows, while retaining the result ID, artifact path, and SHA-256 needed to verify each value. It deliberately does not embed entire result tables. A drafter should retrieve additional rows from the indexed artifact rather than treating the context file as a new source.

The last file is an index, not a source of truth. Any LLM-generated claim must follow its result ID to the hashed result table and operation manifest.

The command exit statuses are:

Status Meaning
0 Requested work completed or verified.
2 Validation, integrity, or execution failed.
3 The plan is waiting for an explicitly configured operation or resource.

study run --allow-partial converts the last case to process success for batch schedulers, but the project remains visibly waiting_for_input. study auto instead treats documented scientific prerequisite gaps as a successful completion of all currently available work and returns nonzero only for validation, execution, or integrity failures.

Patient-level data and LLM non-egress

What can be claimed today

LLM calls are opt-in. The adapter never uploads an input file or gives the model filesystem, shell, sample-matrix or phenotype-row access. It constructs a small allowlisted result preview; raw feature identifiers, project descriptions, dictionary prose and local paths are omitted. Gene symbols, numeric aggregate results, phenotype labels and retrieved reference metadata can be transmitted. These are still sensitive unpublished findings. The approved input metadata must correctly classify results; this is not general-purpose PHI detection. deny_all blocks every remote advisory request, including topic-only requests, and --offline also blocks built-in reference downloads.

JLinAlg cannot truthfully prove that unrelated software, a separately launched agent, a shell command, or a user copied no data elsewhere. A defensible project claim therefore needs both application evidence and enforcement outside the application.

A controlled aggregate-results disclosure design

A future LLM integration should never give a model process unrestricted access to the study directory. Instead, JLinAlg should implement a release boundary:

text
restricted project data
        |
        v
artifact classification + identifier/DLP checks + small-cell rules
        |
        v
separate disclosure bundle (aggregate, redacted artifacts only)
        |
        v
human approval + immutable disclosure manifest
        |
        v
sandboxed connector with read-only bundle and allowlisted network destination
        |
        v
LLM response, response hash, and provider/model attribution

The implemented adapter uses aggregate_results as the default eligibility policy when explicitly enabled: bounded result previews may be disclosed, but patient/sample-level data may not. This is permission for a controlled artifact class, not blanket permission to upload every file in results/ and not an instruction to transmit results when no LLM operation needs them.

For this policy, an aggregate result is identified by its registered artifact type, schema, content checks, and lineage—not by its filename. Eligible examples include association and meta-analysis summary tables, enrichment and fine-mapping results, summary diagnostics, and redacted figures. Participant matrices, phenotype/covariate rows, sample identifiers, individual residuals or predictions, and per-person scores remain prohibited even if a tool wrote them to a result directory. Prompts and study metadata are also manifested because unpublished hypotheses and findings can be sensitive despite containing no patient rows.

A project may set deny_all so no project content is transmitted to a remote LLM. This is appropriate for embargoed, commercially sensitive, regulated, or otherwise restricted unpublished work. The additional controls below are a future high-assurance contract, not all implemented today:

yaml
project:
  data_policy:
    classification: restricted_patient_level
    llm:
      remote_transmission: aggregate_results  # default; or deny_all
      remote_patient_level_data: deny
      eligible_remote_artifacts:
        - association_results
        - meta_analysis_results
        - enrichment_results
        - fine_mapping_results
        - summary_diagnostics
        - redacted_figures
      require_human_approval: true
      minimum_cell_count: 10

remote_transmission denial and patient-level exclusion are implemented for the bounded adapter. Per-request human approval, artifact-specific disclosure lists, small-cell checks, and OS isolation remain future work. If require_human_approval: true, eligible_remote_artifacts, or minimum_cell_count is present, the current adapter refuses to transmit and records additional_disclosure_review_required; it does not silently ignore these stricter policies. Do not remove a required control merely to get a call to run. Application logs are not an independent non-egress guarantee.

For aggregate_results, the system should create an immutable llm-disclosure-manifest.yaml before each request. It should record:

  • hashes and media types of the exact bytes released;
  • the source result IDs and transformations used for redaction or aggregation;
  • direct-identifier, quasi-identifier, free-text, and minimum-cell checks;
  • destination, provider, reported model, purpose, timestamp, and approver;
  • the policy version and pass/fail decision; and
  • request and response hashes, without duplicating restricted content into an unrestricted log.

Calling a table “aggregate” or “de-identified” is not by itself proof of negligible re-identification risk. For regulated health data, the project should tie release criteria to the applicable legal and institutional process—for example, HIPAA Safe Harbor or Expert Determination in the United States—and retain the determination as evidence. Small cells, rare combinations, genomic variants, dates, geography, and free text require particular care.

Independent enforcement and verification

For high-assurance studies, run the connector in a separate OS account, container, or sandbox that can read only the approved disclosure directory. Use default-deny outbound networking with an allowlist for the selected provider, and retain proxy, DNS, firewall, or equivalent egress logs. Here, default-deny describes connector filesystem and network capabilities; it does not change the project-policy default that verified aggregate results are eligible. A local model should run with networking disabled and record hashes for its weights, runtime, prompt, and supplied artifacts.

Assurance should be tested, not inferred from configuration alone:

  1. Review the connector and its transitive dependencies; publish an SBOM and signed/reproducible release artifacts where practical.
  2. Run integration tests with canary identifiers in forbidden files and verify that requests, logs, crash reports, and telemetry never contain them.
  3. Verify that the connector cannot read outside the disclosure directory and cannot reach an unapproved endpoint.
  4. Reconcile disclosure manifests with network logs and the research ledger.
  5. Periodically obtain an independent security/privacy review for regulated or high-consequence deployments.

Provider agreements, retention controls, training opt-outs, and a BAA or DPA may be necessary, but they complement rather than replace technical data minimization and egress enforcement. If an external tool cannot supply adequate evidence, the project should record a provenance and privacy-assurance gap rather than claim end-to-end non-egress.

Current boundaries

  • Direct deterministic adapters currently cover result standardization, bulk-matrix association, discovery/replication comparison, configurable fixed/random meta-analysis, GENCODE feature mapping, local GO/Reactome enrichment, native variant consequences/contextual scores, diagnostics, transparent candidate evidence tables, and traceable reporting.
  • Configured downstream operations can call declared tools; absent tools or inputs produce a hashed request instead of an invented result. Eligible LD-dependent work automatically resolves the default 1000 Genomes reference.
  • Optional AI provider adapters support bounded advice, retrieval-cited literature review and explicitly permitted unreviewed HTML drafts. AI protocol fixtures and separately recorded public-source retrieval checks do not establish actual scientific AI appraisal.
  • Raw single-cell, spatial, microbiome, and multimodal data wait for a registered modality-specific operation rather than being analyzed as a generic bulk matrix.
  • Full disclosure-bundle isolation, DLP/small-cell certification, general pipeline local models, MCP and provider-specific OAuth login/refresh remain unimplemented. Browser handoff is the default transport when assistance is enabled; optional API adapters accept API keys or provider-issued OAuth access tokens. The separate manuscript editorial command supports exact-payload approval and explicit loopback models; see the bioinformatics vignette. No regulatory compliance or publication-readiness certification is claimed.

For the full contract, amendment, provenance, and operation-registry design, see the auditable omics research pipeline vignette. The runnable files are in the study-pipeline example.

Compatible effects and covariance-aware pooling

Each hypothesis defines a proposed compatible analysis block. Pooling now audits declared estimands, coefficient orientation, effect scale/units, phenotype and feature transformations, modality, species, assay, tissue and genome build. Known conflicts stop pooling or validation and remain in pooling-audit.yaml and pooling-compatibility.tsv. For GWAS, known variant-coordinate or effect-allele conflicts are retained in pooling-variant-compatibility.tsv; no automatic allele flip or unit conversion is inferred. Separate incompatible datasets into suitable hypotheses or supply scientifically harmonized inputs before pooling.

yaml
analysis:
  pooling:
    require_complete_contract: true
    effect_contract:
      estimand: adjusted feature association with the declared phenotype
      orientation: feature_to_phenotype
      effect_scale: linear
      effect_units: phenotype units per common feature unit
      phenotype_transformation: none
      feature_transformation: none
    dependence:
      method: sampling_correlation
      matrix: inputs/sampling-correlations.tsv
      rationale: Explain how these sampling correlations were obtained.
      citation: Cite the covariance derivation and source.
  operations:
    meta_analysis:
      model: random
      tau_squared_estimator: reml
      inference: normal
      confidence_level: 0.95
      min_cohorts: 2

Datasets may declare their own effect_contract; it must agree with the common contract. Assay units do not supply coefficient units. Optional pooling.context_exceptions maps assay, tissue or modality to an explicit scientific rationale. It cannot waive conflicting effect units, estimands, orientation or transformations. Completeness remains an explicit choice: require_complete_contract currently defaults to false for legacy contracts; missing information is audited as partially_declared_not_certified, with a mandatory dossier caveat. Strict mode requires the six effect-contract fields and GWAS effect-allele coding. Automatic partitioning and complete model/source appraisal remain unfinished.

Dependence defaults to independent. Reused cohort/source identities and declared dependence cannot silently become independent estimates. The native sampling_correlation and sampling_covariance routes use supplied matrices in generalized least-squares pooling. The long TSV format uses dataset IDs:

text
feature_id  dataset_a  dataset_b  value
*           a          a          1
*           a          b          0.4
*           b          b          1

The displayed columns are tab-separated in the input file. Supply every required pair, including diagonals and explicit zero cross-source entries. One triangular half is sufficient; duplicate directions must agree. * declares a shared matrix, and feature-specific pairs override it. A correlation matrix is scaled by each feature's source SEs; a covariance diagonal must agree with SE squared within relative tolerance 1e-6. Missing pairs remain unresolved. Singular matrices or scaled Cholesky pivots at or below 1e-12 require review; no jitter, source deletion or independent-model fallback is applied. Actual source subsets are used when a cohort has no estimate for a feature.

Sampling dependence and between-source heterogeneity are separate: random-effects GLS adds tau_squared * I to the supplied sampling covariance. Both independent and GLS adapters honor reml|dl|pm, normal|t|hk|modified-hk, confidence level, maximum iterations and tolerance. Their effective settings are recorded. For GLS, generalized Q and its degrees of freedom are retained; conventional independent-study I-squared and prediction intervals remain unavailable. pooling-feature-audit.tsv, pooling-weights.tsv, sampling-matrix-input.tsv and correlated-pooling.yaml retain coverage, weights, source hashes and caveats. n_sources makes source counts explicit; legacy n_cohorts has the same source count, while n_unique_declared_cohorts describes known cohort labels. Neither participant independence nor a deduplicated/effective N is inferred.

Discovery pooling uses discovery sources alone. It may account for dependence among those sources while retaining an independent validation cohort. A nonzero discovery/validation sampling covariance, reused cohort identity or declared cross-role dependence blocks an independent replication claim. Covariance files participate in operation cache hashes. Cohort omissions and unfiltered-effect sensitivities retain the same sampling model on their actual source subsets; unresolved child fits propagate a waiting state and preserve the primary. Scalar-effect covariance does not implement dependent rare-set score pooling.

For the method and matrix assumptions, see the official metafor GLS documentation and Lin and Sullivan's overlapping-subject GWAS analysis. The packaged pooling-workflow.py example independently checks scalar GLS, Paule–Mandel heterogeneity, conditional intervals/tests and frozen validation.

The supplied FASTA must agree with REF. Large FASTA files require an existing .fai; reference files are never indexed or repaired in place. An indel also requires the explicit normalization declaration. No liftover is inferred. Canonical IDs are BUILD:CHROM:POS:REF:ALT; files.variants can resolve custom feature IDs using feature_id, genome_build, chrom, pos, ref, alt. Conflicting IDs, alleles or builds require review.

Consequences default to vep-rest, using the official build-specific Ensembl host and retaining release metadata and response files. Other engines are annovar, vep and import; imports support canonical, vep and annovar-vcf. Installed ANNOVAR requires executable, perl, database, protocol and operation; installed VEP requires executable, cache, cache_version and fasta. Import/local engines require an explicit release. Canonical import columns are genome_build, chrom, pos, ref, alt, gene, transcript, consequence; VEP/ANNOVAR imports must preserve canonical IDs. An import may contain other variants or builds: exact allele matching selects each batch and retains the source hash and selection counts.

If rare-set masks need annotations and files.variant_annotation is absent, the planner adds variant_annotation before rare_variant_masks. Its verified gene/consequence rows feed masks without applying the single-marker MAC 20 filter. Aggregated/ambiguous genes and missing consequences receive explicit coverage dispositions; high-confidence loss-of-function is never inferred from a consequence name alone. Supplied mask annotations remain supported.

AlphaGenome defaults to Atlas lookup. predict uses the separately installed official Python SDK, while atlas_then_predict tries supported Atlas misses and indels within the separate prediction budget. AVI_SCORE is an Atlas scorer; live prediction uses the separate prediction_scorers list. Native remote scoring accepts human GRCh38 autosomes/X/Y and performs no implicit assembly conversion. A missing SDK, credential, budget, reference or usable response leaves an explicit disposition. Offline or denied-transmission policy is checked before starting a remote provider or reading its credential. Requests contain canonical variant/scorer parameters, without phenotype, association statistics or participant inputs.

For existing scores, use alphagenome: {engine: import, scores: scores.tsv}. The TSV columns are variant_id, mode, resource_version, model_version, scorer, gene_id, transcript_id, ontology_curie, track_id, raw_score, quantile_score, interval, source_record. Source/model versions are required. Preserve raw scores and signed quantiles: signed scorers can have quantiles in [-1,1], while unsigned scorers use [0,1]. Exact conditional tests for sparse binary GWAS

Register binary_test: exact-conditional when the scientific null is an independent individual Bernoulli logit with stratum intercepts and, optionally, fixed known offsets. This route sums the finite conditional distribution of the ALT case-allele score after conditioning on each stratum's case count. It accepts observed integer 0/1/2 genotypes. It does not round dosages or drop continuous covariates. It supplies no kinship, repeated-participant or arbitrary continuous-covariate adjustment. The default route remains efficient-score; MAC 20 alone does not choose a calibrated estimator.

yaml
association:
  model: glm
  family: binomial
  binary_test: exact-conditional
  exact_strata_column: matching_group
  offset_column: known_log_odds
  exact_maximum_states: 200000
  exact_maximum_work: 50000000
  exact_effect_maximum_parameters: 50
  minimum_mac: 20

Omit exact_strata_column for one intercept-only stratum. A named stratum column is categorical, needs at least two observed levels, and enters the study adapter's nuisance formula and prefit complete cases. Native CLI users also include that column in their formula, for example --formula 'case ~ matching_group + offset(known_log_odds) + <omics>' with --exact-strata-column matching_group. Ordinary reference or indicator contrasts must span the declared strata; unsupported design terms fail. Omit offset_column when no scientifically justified fixed offset is available. A fitted risk predictor or LOCO predictor is not automatically a known offset; its estimation, independence and model validity need separate justification.

Within a stratum, each outcome assignment with the observed case count has null weight proportional to the exponential of the sum of its fixed offsets. Constant offsets cancel. The implementation aggregates the 0/1/2 genotype count combinations or uses a bounded elementary-symmetric recursion for varying offsets, then convolves stratum score distributions. The native study route uses a two-sided probability-ordering tail, including masses no greater than the observed mass with relative tie tolerance 1e-7. This is a discrete finite conditional test; no mid-P or asymptotic tail is substituted. Strata with a pure outcome or constant genotype contribute no test information.

The conditional score test is distinct from maximizing an exact conditional likelihood and then using an asymptotic fitted-parameter test. The R survival conditional-logit documentation describes that likelihood. For a single stratum and binary genotype, the score reduces to a fixed-margin hypergeometric test with the probability-ordering rule documented by R Fisher's test. For three genotype levels, this additive-score test is not the omnibus 2-by-3 Fisher independence test.

Missing genotypes are omitted before each variant's case counts and strata are formed. Raw n_samples/n_cases/n_controls and called/missing retain the source QC scope. Canonical n/n_cases/n_controls instead describe the called test sample; canonical qc_n_samples/qc_n_cases/qc_n_controls preserve the pre-omission QC counts. test_n_*, test_strata, informative_strata, method, calibration, score moments, score direction and natural log_p_value survive normalization and finding inventories. statistic_type is conditional_centered_allele_score, with no chi-square numerator df. Finite log tails remain available when ordinary P underflows to zero.

An optional separate unconditional Firth stratum-logit fit supplies an approximate effect and ordinary-Fisher SE. Its coefficient and SE are not finite conditional estimates or a Wald explanation of the exact P value. exact_effect_maximum_parameters counts all stratum intercepts plus genotype; set it to 0 to skip effect estimation. A parameter-budget, singular or nonconverged effect fit retains the valid exact P as result_type: p_value_only, with missing beta and SE. These tests remain eligible for the registered P-based family, official single-source selection, gene-set overlap when the source is an eligible gene-level analysis, and literature/dossier evidence. They establish no effect magnitude or beta direction. exact_score_direction describes the centered test score only. Inverse-variance meta-analysis waits when any eligible P-only test is present; default beta/SE GSEA also waits for a complete supported ranking. Effect correlations use finite signed pairs and record that scope; required replication sign concordance is unavailable for P-only pairs.

The state and work bounds prevent unbounded exact calculations. They are support/table-state and counted recurrence/convolution work limits, not a total heap-memory guarantee. An exhausted bound or unrepresentable conditional normalization produces no P value. Raw partial results remain auditable, every BH value in that native family is withheld, and the study association and downstream official selection wait for resolution. No approximate fallback or incomplete-family FDR is reported. An explicitly unsupported genotype representation or a no-information margin is separately recorded as ineligible/nonestimable. Increasing a resource bound does not repair an unsupported model.

Externally produced P-only association tables may declare columns: {result_mode: p_value_only} and supply feature ID and actual P value without beta/SE columns. For mixed tables, retain beta/SE columns, leave them missing on test-only rows, and explicitly map columns.result_metadata.result_type to a column containing p_value_only or signed_effect. Contradictory effect values on a P-only row are rejected. Missing effects alone never imply a test-only declaration. Imported methods, testing-family completeness and calibration still require source provenance.

Native binary risk-score development and frozen probabilities

Register risk_score.family: binary with individual 0/1 outcomes to train a binomial ridge, lasso or elastic-net molecular score. This source-build route uses the same explicit, group-safe training/tuning/evaluation partitions as the quantitative workflow. It fits a joint feature-plus-covariate probability model and a separate covariate-only comparator. The recipe is distinct from the quantitative residual-outcome model and from the standalone Gaussian score-train command.

yaml
risk_score:
  file: participants.tsv
  family: binary
  outcome: case_status
  features: [protein_A, protein_B]
  covariates: [age, sex]
  categorical_covariates: [sex]
  group_columns: [family_id]
  resampling_group: family_id
  lambdas: [1.0, 0.1, 0.01]
  alpha: 0.5
  binary_baseline_lambda: 1.0
  binary_maximum_iterations: 10000
  binary_tolerance: 1.0e-8
  max_work: 250000000
  missing: training_mean
  refit: true
  bootstraps: 200
  related_phenotypes:
    - {column: BMI, family: quantitative}

The full objective is mean individual Bernoulli negative log likelihood plus lambda * (alpha * sum(abs(beta)) + (1-alpha)/2 * sum(beta^2)) on training-standardized molecular features, and binary_baseline_lambda / 2 * sum(gamma^2) on training-standardized non-intercept covariates. The intercept is unpenalized. The comparator has a separately fitted intercept/covariates with the same registered covariate-ridge penalty. Feature lambdas and the covariate penalty must be positive. This keeps regularization explicit, including for separated development data; a Gaussian likelihood or unregistered unpenalized binary fit is never substituted.

Alpha 0 is ridge, 1 is lasso, and intermediate values are elastic net. The standard elastic-net objective is described by Friedman, Hastie and Tibshirani. JLinAlg uses bounded cyclic coordinate proximal-gradient steps with the global logistic one-quarter curvature bound and a recorded KKT stopping tolerance. This implementation is independently checked against convex SciPy optimization; it is not a claim of complete glmnet path/option parity. Tolerance and KKT residuals refer to the standardized coefficient coordinates. Iteration/work exhaustion or unrepresentable preprocessing/serialization leaves the operation waiting with a reason; no partially optimized frozen model is published.

Each candidate learns imputation means, population-variance feature/covariate scales and both models from the training partition. Tuning log loss selects the feature lambda; exact ties keep the first, stronger value in the descending grid. Both development and tuning partitions need cases and controls. With refit: true, the selected model, comparator, means and scales are fitted again on training plus tuning records; categorical vocabulary remains frozen from the training partition. Evaluation records never affect those fits or choices. max_work also bounds counted optimizer visits across candidates and refits; it is distinct from a wall-clock or total-memory limit. The dense-table bounds and group/identity checks from the quantitative workflow still apply.

tuning.tsv records tuning_log_loss. score-model.yaml uses jlinalg-held-out-binary-score-v1 and retains raw feature weights, imputation means/scales, centered-score intercept, full prediction covariate weights, separate comparator weights, logit link, penalties, categorical levels and hash-linked development identities. The centered molecular score is a log-odds component. Its standalone weight table is insufficient for calibrated probability application; apply the complete model with mode: model and its original identity sidecar. Frozen predictions use the full joint-model covariates plus the molecular component, while comparator predictions use its own covariate-only weights. The two covariate coefficient vectors are different estimators. No evaluation-baseline or probability-model refit is performed. The effective method report uses source-model penalties and preprocessing; unused training defaults in the application configuration are not reported as parameters of a refit.

The default prediction scale is probability for native binary training and complete binary-model reuse. Evaluation log loss and calibration logits clip supplied probabilities to [1e-15, 1-1e-15]; this reported numerical convention can cap more extreme log-loss contributions. Tuning uses the stable, unclipped linear-predictor loss. Aggregate outputs include AUC, molecular-score AUC, comparator AUC, Brier score and log loss, with optional conditional independent-unit bootstrap intervals and subgroup metrics. Raw imported scores keep their original raw-versus-probability contract. Logistic calibration intercept/slope are optional evaluation summaries: complete/quasi separation, constant predictions or failed fits leave them unavailable. Good discrimination alone does not establish calibration. Related-phenotype tests use the frozen molecular score on the declared evaluation population and retain the separate complete BH/BY/NONE family. If a related input is missing, invalid or unestimable, completed performance remains source-linked context in the finding inventory. The related family stays unresolved, with no official adjusted P values or significant related-finding claim. Per-table completion is explicit; the partial operation is never relabeled complete.

For both newly exported quantitative and binary models, the development-ID sidecar includes training and tuning participants and groups even when refit: false. Tuning data were used in selection and cannot later become independent evaluation data. development_rows counts actual final fitting rows, whereas development_identity_rows counts all fitting/selection records. Observed ID/group overlap blocks complete-model reuse. Legacy quantitative models without selection-identity metadata retain an explicit coverage caveat; a source independence statement is not independent software verification of unavailable tuning identities.

All weights are predictive coefficients, not association effect estimates. Case/control sampling prevalence does not establish population absolute risk; independent population evaluation and appropriate recalibration remain necessary. Penalty tuning here is explicit holdout selection, with conditional performance intervals, rather than nested CV or an assessment of training and feature-selection uncertainty. Large genome-wide fitting, censoring-aware survival models and broader transportability analysis remain separate work.

LD-aware GWAS functional-category enrichment

The native gwas_enrichment study stage fits observed-scale stratified LD score regression (S-LDSC) for overlapping binary annotations. It is separate from unpartitioned ldsc, ordinary GO over-representation, preranked molecular GSEA and GWAS Catalog lookups. The implementation follows the partitioned fixed-initial-weight estimator and overlap-aware category contrast described by Finucane et al. (2015), with a pinned upstream numerical reference.

Register the complete GWAS source, ancestry/population and build-matched LD reference, baseline/nuisance annotations, target categories and correction family before looking at enrichment results. A target can represent a prespecified gene set, tissue or regulatory category only when its binary variant annotation, LD scores and reference intersections have actually been constructed. Nearest-gene hit counts do not create those inputs. This stage does not acquire or construct an LD reference automatically.

yaml
analysis:
  mode: manual
  goals: [gwas_enrichment]
  gwas_enrichment:
    summary:
      file: dense-gwas.tsv
      coverage: complete
      tested_snps: 1200000
      population: EUR-reference-population
      genome_build: GRCh38
      statistic: chi_square
      calibration: one_df_chi_square
      ascertainment: quantitative
      model: "Registered calibrated marginal GWAS model and covariates"
      qc: "Source sample/variant QC, ancestry, relatedness, calibration and exclusions"
      provenance: {producer: "source study", release: "registered release"}

      population: EUR-reference-population
      genome_build: GRCh38
      release: "registered LD and annotation release"
      common_variant_definition: "Same common-reference-SNP universe for M and intersections"
      regression_snp_definition: "Prespecified well-imputed regression SNP panel and LD windows"
      annotation_model: "All-SNP baseline plus registered binary nuisance and target annotations"
    ld_scores: ld-scores.tsv

    minimum_chromosomes: 20
    minimum_coverage: 0.9

The full summary defaults to columns variant_id, chromosome, position, ref, alt, chi_square, n; their names are configurable. statistic: z squares the named statistic. statistic: beta_se computes the squared Wald ratio from logical beta and se, and requires the same explicit calibrated one-degree-of-freedom source declaration. An exact-test P value or penalized likelihood-ratio P value does not establish a Wald chi-square statistic. Declare the source model/calibration; do not convert arbitrary P values into chi-squares to bypass that requirement. For case/control GWAS set ascertainment: case_control; outputs remain on the sampled observed scale. Per-SNP n must have the meaning required by the GWAS calibration, rather than substituting an unverified enrollment or effective sample count.

Omit summary.file to consume the registered official complete result from association or supplied meta-analysis. Keep the source declarations and exact row count; the selected result must retain allele, coordinate, sample-size and chosen statistic columns. Set id_column: feature_id when adapting an official table with an explicitly configured summary. A selected-only primary export, ambiguous primary source or unavailable upstream model cannot silently fall back to another cohort. The retained primary-selection receipt identifies the actual producer and its hash.

ld-scores.tsv has variant_id, chromosome, position, ref, alt, weight_ld and one ld_<term_id> column per annotation. Regression weights use LD summed over the regression SNP panel; annotation LD scores use the declared reference and windows. Input row order may vary: matched retained SNPs are sorted by autosome, position and ID before blocking. Only autosomal biallelic SNPs are supported. Matched summary alleles must equal the reference pair, optionally reversed because the statistic is unsigned; build, coordinate or other allele discrepancies are audited. Two IDs for the same physical coordinate/allele pair, including reversed coding, cannot duplicate a reference SNP. Strand complements are not guessed. Finite negative unbiased LD-score estimates are allowed; aggregate LD and weight LD are clamped to at least one for weighting only, as in upstream.

annotations.tsv has term_id, term_name, role, count. The first row is the unique all baseline covering every reference SNP. Other roles are nuisance or target. Every annotation is fitted simultaneously. Counts must be positive integer common-reference-SNP counts, not regression-row counts. Identical binary annotations cannot be assigned distinct coefficients or arbitrary different LD scores; remove an alias only through a prespecified scientifically coherent model revision. annotation-intersections.tsv has term_id and a column for each annotation ID, giving the complete symmetric reference intersection matrix. Diagonals equal annotation counts; the all-SNP row equals those counts. Bounds, symmetry and positive semidefiniteness are checked. These checks cannot establish that a declared reference was generated correctly. Continuous annotation/baseline-LD models, ancestry mixtures, sex chromosomes and alternate S-LDSC-CTS separate target models need a suitable external analysis rather than a relabeled binary model.

The regression fits E[chi_square_j] = intercept + N_j * sum_k(tau_k * LD_jk). For category C, total heritability is sum_k(M_k * tau_k) and category heritability is sum_k(M_C_intersect_k * tau_k). Consequently, overlapping category heritability differs from tau_C * M_C. Enrichment divides category heritability proportion by its reference-SNP proportion. The primary nominal test compares average per-SNP heritability inside C with its complement using the complete coefficient covariance and a two-sided t distribution with B degrees of freedom, matching the pinned overlap estimator. Nominal conditional coefficient tests are retained separately and do not enter this target family. BH/BY/NONE applies jointly to all registered targets. NONE is nominal testing. No best baseline, annotation subset or model is selected from enrichment P values.

Defaults exclude autosome 6 positions 25,000,000–34,000,000 inclusively as an explicit broad MHC region; replace excluded_regions with build-appropriate registered regions or an empty list with scientific justification. Reference counts and intersections retain their declared full universe. After reference, allele and region matching, the default exclusive chi-square cap is max(80, 0.001 * maximum_valid_matched_N), or supply chi_square_max before analysis. snp-qc-exclusions.tsv retains mismatch, missing-source, region, invalid-statistic and high-chi-square reasons. Coverage before the high-chi-square filter is measured against nonexcluded regression-reference SNPs; the SNP and chromosome minima apply after filtering. Row-count, source completeness and QC declarations remain scientific provenance, not proof of calibration.

The estimator normalizes per-SNP N by its mean, uses the aggregate initial partitioned LDSC weights, and holds those weights fixed in equal-count genome-ordered block deletes. It does not reuse the iterative unpartitioned estimator. Singular, collinear, unstable full or deleted designs cause an explicit unresolved stage; no ridge repair or column removal occurs. The default limits are 2,000,000 LD regression rows, 128 annotation columns and 10,000,000,000 estimated arithmetic work units. Exceeding a limit does not truncate SNPs or targets. These are computation/row bounds, not a memory or throughput guarantee: dense table parsing and LD matrices currently require memory, and large real genome-wide scale acceptance remains to be done. Small numerical fixtures lower coverage minima for verification; such inputs do not establish reliable biological inference.

Successful outputs include gwas-enrichment.tsv, all conditional coefficients in sldsc-coefficients.tsv, the full coefficient covariance, block deletes, regression-snps.tsv, immutable input snapshots and gwas-enrichment-analysis.yaml. Category proportions/enrichments use ratio block-delete uncertainty. Nonpositive/weak total heritability, nonpositive delete totals or an unestimable eligible target withhold all official adjusted P values and leave official_family_complete: false. Estimates remain available for diagnosis. Negative conditional effects and out-of-range proportions are retained, with their interpretation limits. Fewer than 200,000 regression SNPs adds a precision/coverage caveat. Complete target rows enter the study finding inventory with their FDR, enrichment uncertainty and source caveats. Their aggregate fit context includes total heritability/SE/Z, intercept/SE, regression-SNP/chromosome coverage, per-SNP N range/mean, the reference population/build/release and the target correction family. Raw LD and full GWAS input files are not embedded in these dossiers. Later AI appraisal can weigh this evidence without treating category enrichment as a causal or independently replicated story.

Previously completed enrichment can instead be registered as supplied_results.kind: gwas_enrichment, with logical term_id, p_value, its method, scope, source provenance and full testing family. Existing adjusted_p values and enrichment estimates/uncertainties are preserved. Selected-only exports require adjusted values explicitly traced to the full source family and its tested count. The supplied stage satisfies this goal without LD inputs or a statistical refit; the import receipt states that the external analysis was not reproduced.

Each source is an autosomal, allele-resolved VCF/PLINK/BGEN cohort matrix with aligned prefit-selected participants and the same registered phenotype/build, case/control definitions and mask annotation release. Within each cohort/stratum, the case total k is fixed. For fixed log-odds predictors eta, an allocation z has probability proportional to exp(sum(z_i * eta_i)) among allocations with sum(z_i) = k. Equal offsets give uniform label allocations. Unknown continuous slopes, kinship and survival models are not estimated or silently omitted. Import a complete, model-specific calibrated set analysis when this conditional null is unsuitable.

The cohort/stratum intercept profiles to its case count with the fixed offsets. The score center is that restricted-null logistic mean; it is not asserted to be the finite conditional expectation. Complete finite or sampled outer tails calibrate the chosen fixed score statistic. All-case or all-control strata contribute no information; a native cohort must retain both outcome labels and at least one informative stratum. Offset spans above 700 within a stratum are rejected as outside the implemented numerical range.

Genotypes/dosages are fixed predictors. Missing calls are mean-imputed within the fixed prefit cohort, while MAF/MAC eligibility uses observed called alleles, not imputed pseudo-counts. Observed monomorphic rows remain available for other cohorts' joint sets; scope-wide monomorphism is excluded separately. Eligibility, minor-allele recoding and frequency weights are recomputed for each selected cohort/discovery/all-cohort/omission scope. All-sample HWE is optional and explicitly identified; it is not a case/control-specific HWE protocol. Genotype, imputation, external-coefficient and sample-selection uncertainty are not propagated. Caller-specific QC, ancestry calibration and assay validation remain required scientific work.

The primary statistics are squared burden, a SKAT-style quadratic kernel, a rho-grid adaptive kernel statistic, ACAT-V-style variant/collapsed-score combination and the six-component ACAT-O combination using beta(1,25) and uniform weights. Default burden weights are equal; default kernel weights use the existing raremetal-beta frequency floor 2/N, and ACAT-V uses beta(1,25) weights. acat_mac_threshold defaults to 10 for the low-MAC collapsed component. The SKAT-O and ACAT references motivate these statistics; this finite conditional implementation does not claim R SKAT or asymptotic ACAT numerical equivalence.

Adaptive/Cauchy transformations use internal mid-tail ranks. Those ranks and the raw Cauchy statistic are never reported as association P values. All five final tests receive outer calibration:

  • Exact mode evaluates complete weighted upper tails including ties. Genotype patterns compress equivalent participant allocations, preserving their combinatorial/offset probabilities. allocation_states counts grouped allocations, not individual label assignments. Outside complete enumeration, that count can be capped at maximum_exact_states + 1.
  • Monte Carlo freezes transformations on an independent pilot, then samples the main null with a fixed seed and draw count. Final P is (tail_draws + 1)/(draws + 1). Clopper-Pearson 95% bounds concern the true conditional tail of that frozen-pilot statistic, not a confidence interval for the plus-one estimate or a propagation of model/multiplicity uncertainty. The conditional Monte Carlo reference explains why the resampling law and inclusion of the observed statistic matter.
  • All statistics retain 40 fraction bits to define roundoff ties consistently. Exact underflow can display P = 0 while log_p_value remains finite. It is a representational limit, not a true zero tail probability. Sampled tests have a nonzero resolution floor. constant_evaluated_null describes the evaluated support/draws; a sampled constant is not proof of a constant full null.

auto uses exact enumeration when its state/cell bounds permit it and otherwise uses the registered sampled method. Explicit exact never silently switches. Work limits count estimated numerical operations, and cell limits bound key matrices/workspace estimates; neither is a process-RAM or wall-time guarantee. The default retained variant bound is 2,000 across a source export, so this is not yet a genome-wide streaming rare-set implementation. Exceeding a limit retains a waiting branch rather than truncating variants or choosing favorable sets. Failed fits conservatively charge their allowed work; changing work budgets can reuse identical completed fits.

require_complete leaves a scope family unresolved when a required marker is unobserved in a selected cohort; absence is not assumed reference homozygosity. An observed marker failing registered outcome-independent QC is excluded jointly before that coverage check. Explicit intersection uses the measured passing intersection and retains every exclusion. A zero-eligible-variant mask is recorded separately from an unresolved eligible fit. Every scope corrects all eligible masks and requested tests jointly with registered BH/BY/NONE. BH needs its usual dependence assumptions; overlapping sets do not establish them. Any unresolved eligible fit withholds that scope's entire adjusted-P family. Raw completed tests and diagnostics survive, and a separately complete primary family remains in the aggregate findings inventory when other scopes wait.

Discovery-only tests freeze selection for validation. The all-cohort primary and leave-one-cohort-out fits are separate scopes, with the registered minimum cohort count. These are joint conditional tests, not inverse-variance pooling of binary Gaussian scores. Burden is unsigned test-only evidence in this branch: no odds ratio, beta, SE, direction, Q or I-squared is estimated. Replication of a gene/mask does not establish the same causal variants or mechanism. A requested burden direction requirement remains unavailable rather than being fabricated.

Private conditional-samples.tsv and row-aligned conditional-genotypes.tsv remain local. Aggregate rare-results.tsv, rare-primary-results.tsv, rare-replication.tsv, omission/influence tables, binary-null-diagnostics.tsv and binary-mask-eligibility.tsv retain sample/case/control counts, calibrated P/log-P, family status and numerical precision. Private participant rows never belong in AI evidence payloads. Completed per-gene fits have sealed identities covering software, fixed null, data/mask hashes, weights, calibration and seed. Raising per-fit/total work limits reuses those identical completed fits, even from an incomplete prior family. Changed scientific inputs invalidate reuse. Damaged derived caches are retained, identified and recomputed from verified inputs; corrupt raw inputs are not repaired automatically.

With validation_family: discovery_subset, register universe: intersection. The discovery reference is a complete discovery-only source. Multiple discovery cohorts require a source-declared matching discovery-pool composition. Only primary-test tuples enter the overlap display. Both the original source adjusted P and the new validation-family adjusted P remain visible. No discovery P or source adjustment is redefined by the display.

Registered LD evidence for distinct principal findings

Several significant SNPs can describe the same correlated signal even when their gene annotations or user-supplied story labels differ. Register local LD evidence to add a separate redundancy constraint to the finding inventory. The statistical results, source FDR, eligibility, full candidate inventory and existing story_group labels remain unchanged. Both AI principal-finding selection and human-supplied principal prose reject two slots sharing a registered redundancy_groups component.

yaml
project:
  finding_grouping:
    enabled: true
    minimum_r_squared: 0.8
    maximum_distance_bp: 1000000
    require_complete_coverage: true
    maximum_variants: 200000
    maximum_pairs: 2000000
    references:
      - id: ancestry_matched_ld
        genome_build: GRCh38
        population: EUR
        release: my-reviewed-reference-v1
        hypotheses: [gwas_trait]
        variants: references/ld-variants.tsv.gz
        pairs: references/ld-pairs.tsv.gz
        coverage: complete_window
        window_bp: 1000000

Each reference explicitly selects one or more hypotheses. A hypothesis can select only one reference. Tables can be plain TSV or gzip-compressed TSV. The variant catalog needs variant_id, chromosome, position, ref, alt; an optional genome_build column must agree with the declaration. Coordinates are positive, one-based reference positions with explicit distinct DNA alleles. Accepted assemblies are GRCh37/hg19 and GRCh38/hg38. Pair tables need variant_a, variant_b, r_squared, with identifiers resolvable in that catalog. Use squared genotype correlation in [0,1], not signed correlation. Conflicting aliases, duplicate undirected pairs with different values, unknown variant endpoints and invalid values leave grouping unavailable.

All reference variants participate, including unmeasured or nonsignificant mediators. Edges join variants on the same chromosome within the registered distance and at or above the r-squared cutoff. Deterministic connected components supply redundancy IDs. For example, A--B and B--C above the cutoff put A and C in one component even if A--C is below the cutoff and B is absent from the association results. A chain can span more than the edge window. This is a conservative transitive redundancy constraint. It does not estimate a causal signal, establish one mechanism, or prove independence between different components. It is different from the P-ranked index-variant procedure described in the official PLINK clumping documentation.

Coverage has three explicit dispositions:

  • complete_window: the program checks for an observed finite LD value for every within-window pair in the supplied catalog, including zero and below-cutoff values. This checks the supplied catalog, not its completeness against the population's entire variant universe.
  • thresholded_window: declare window_bp, minimum_reported_r_squared and, where needed, reporting_comparison. The source reporting cutoff must be below the grouping cutoff; equality requires greater_than_or_equal. A source exported at strictly greater than the same cutoff cannot establish coverage at the equality boundary. This disposition relies on reviewed source-declared export completeness; JLinAlg does not reproduce it from participant genotypes.
  • positive_edges_only: observed links are usable descriptively, but absence of a pair establishes no zero-LD value or independence.

NA, NaN, . and empty LD values remain unavailable. Unknown within-window pairs invalidate complete coverage even in a thresholded export. A source window shorter than the analysis window also cannot establish coverage. The strict default requires an adequate source and reference membership for every eligible primary single-variant finding. Missing references, identity conflicts or work bounds retain the complete inventory and supplied results while holding impact assessment before any model request. Resolving the registered input permits a normal resume. Nothing silently selects a favorable subset of successful references or findings.

Set require_complete_coverage: false only in a reviewed protocol that accepts descriptive partial reference components. Known positive edges still constrain shared slots; unmatched findings and missing pairs remain unknown, and the mandatory limitations accompany the dossier. Setting enabled: false or registering no references leaves the existing story-label rules in effect; it does not certify those labels as independent genetic signals.

Known source build, position, REF/ALT, effect-allele, species and recognized ancestry conflicts are held for review. Unrecognized population labels do not certify ancestry compatibility. An externally supplied primary uses its own registered scope rather than unused raw input datasets. Identical canonical variants and positive links across hypotheses or reference populations are conservatively joined; that join is not independent replication. Different assemblies remain distinct. References exclusively scoped to retired hypotheses are not opened or added to cache inputs.

finding-grouping/grouping.yaml, variant-dispositions.tsv, pair-dispositions.tsv, finding-membership.tsv and components.tsv record the checks and assignments. Source tables are snapshotted and hashed with a reference receipt. Public aggregate dossiers cite those receipts and carry the caveat; local paths are removed from model payloads. Editing or supplying an LD file invalidates the inventory and dependent editorial work while an unchanged supplied meta-analysis remains cached. Automatic ancestry-matched reference download, native genotype-to-LD extraction and fine-mapping are separate capabilities; this operation accepts explicitly registered local LD tables.

Registered adjusted subgroup interactions

subgroup_interactions tests whether an association effect differs between two prespecified groups. It is separate from the descriptive distribution plots and Welch comparisons in participant_qc. A difference between subgroup P values does not establish an interaction; compare effects in an appropriate model (Altman and Bland).

Register the contrast before examining its test results. For an independently sampled bulk matrix with a quantitative outcome, a hypothesis can include:

yaml
outcome: BMI
covariates: [age, sex, ancestry_pc1]
inputs: {discovery: [cohort_a]}
analysis:
  mode: manual
  goals: [association, subgroup_interactions, impact_assessment]
  association: {model: ols}
  subgroup_interactions:
    independent_rows: true
    method: ols-hc3
    groups:
      - id: sex
        column: sex
        levels: [F, M]
        rationale: Prespecified effect modification question for this study.
    nuisance_interactions: all_two_way
    adjustment: BY
    alpha: 0.05
    minimum_group_samples: 10
    minimum_group_mac: 20

The two levels are ordered: reference first, comparison second. A numeric contrast instead declares cutoff and comparison (greater_than by default, or greater_than_or_equal, less_than, less_than_or_equal). It cannot also declare categorical levels. Report its source variable and a scientific rationale; do not search thresholds for a favorable P value. Register derived_from: [BMI] when a grouping variable is constructed from BMI. A group defined by the outcome, or declared to derive from it, produces neither an interaction P value nor a Welch comparison of that outcome. Its distributions and unavailable-test dispositions remain. Undeclared derivations cannot be reliably inferred from an arbitrary column name; their disclosure needs review.

For feature X, group indicator G and encoded covariates C, the default full model contains intercept, G, C, C×G, X, C×X and X×G. The tested parameter is the X×G coefficient. Including both covariate interaction sets guards against the specific interaction confounding described by Keller; it does not establish that all confounding is controlled. No three-way interaction is fitted. Reference and comparison slopes apply at the complete test sample's centered covariates, in original feature units. Logical column mappings and hypothesis covariates are inherited. A categorical grouping variable is removed from the nuisance list because its main term is already fitted; the continuous variable underlying a threshold contrast remains when registered as a covariate. Non-numeric covariates receive treatment encoding; categorical_covariates can explicitly encode numeric category codes. The recorded terms identify reference levels. group_only omits C×X and none omits both interaction sets; either requires an explicit policy rationale and changes the scientific model.

The current native inference routes are:

Method Test and uncertainty
ols-hc3 Strict full-rank OLS, HC3 covariance and residual-df t approximation. HC3 does not solve clustering or guarantee finite-sample calibration.
ols-classical Strict full-rank OLS with homoskedastic Gaussian residual-df t inference.
logit-lrt Independent Bernoulli logit full versus nested constrained maximum-likelihood fits, with the same observations, offset and nuisance terms; asymptotic chi-square(1) tail.
firth-lrt Full-design Jeffreys-penalized fit versus the X×G=0 constrained fit retaining that same full-design penalty; asymptotic chi-square(1) tail.
inherit OLS selects HC3; explicit binomial/logit GLM selects ordinary logit or an explicitly declared Firth route. Missing or unsupported models remain held.

Binary models retain the registered case_value, control_value and fixed offset_column. Their reported ordinary-Fisher SE/Wald intervals are separate approximations, not profile-likelihood intervals. Firth is based on bias reduction, not a universal exact small-sample calibration guarantee. Ordinary separation, failed optimization and insufficient numerical budgets remain unresolved; no automatic Firth fallback selects a different method. A one-class complete outcome is unavailable. Effects, uncertainties or interval bounds that cannot be represented in the original feature units also remain unresolved; a finite standardized test tail cannot rescue an infinite coefficient or invalid interval.

Native fitting requires the explicit independent_rows: true assertion and a verified completed participant-QC producer matching current matrix, phenotype and sample-file bytes. Declared related/repeated participants, pedigree/GRM, unsupported mixed/survival/exact-conditional models and single-cell/spatial unit designs need a suitable reviewed adapter or supplied result. The assertion is not evidence that dependence was actually ruled out. A custom HWE sample panel also requires an interaction-compatible reviewed QC export. Broader sex/PAR, ploidy, kinship and source-specific calibration remain outside this adapter.

Every selected dataset×group×feature belongs to the registered scope; an optional explicit features list narrows it prospectively. Primary association P values and histogram differences never select the interaction family. Complete observed feature samples are used, with sample support checked in both groups. Genotype tests inherit single-marker QC and recompute within-group MAC; by default each group needs MAC >=20, even when pooled MAC passes. Failed QC and insufficient support retain explicit exclusions. Structurally unestimable tests that passed QC remain in the denominator. Pending fits, absent registered features, stale inputs or an unknown universe withhold all native interaction adjusted P values and candidate flags; observed raw fits remain available.

The correction family is joint across this hypothesis's applicable datasets, contrasts and features. The default is BY; BH, Bonferroni and explicit nominal NONE are available. Separate hypotheses are separate families; a study-wide cross-phenotype correction is not inferred. Multiple cohorts using overlapping participants are not independent replications merely because their interaction fits share a correction family. Default bounds are 1,000,000 attempted fits, 250,000,000 conservative work units, 100 parameters, 300 iterations and tolerance 1e-8. An exhausted bound holds the family instead of adjusting a truncated subset.

subgroup-interactions.tsv retains counts, group MAC where relevant, the signed comparison-minus-reference difference and CI, P/logP, statistic, df, both group slopes/SE, inference, test status, correction denominator and mandatory caveats. subgroup-interactions.yaml records policy, source hashes, participant-QC proof, design terms and prerequisites. participant-membership.tsv contains local participant identifiers and exclusions. Only aggregate canonical rows enter finding dossiers. Eligible interaction evidence can reach impact review when the primary association is nonsignificant; its significant label and primary artifacts remain unchanged. Incomplete and excluded rows retain context and limitations; they do not become interaction discoveries.

Required columns are feature_id, dataset_id, group_id, reference_level, comparison_level, beta, se, p_value; retain adjusted_p from the complete source family when using that declaration. Each dataset/group/feature identity is unique, and a dataset/group's contrast orientation must agree across features. Optional canonical counts, slopes, inference, scope and caveat fields survive validation; arbitrary participant notes do not enter canonical dossiers. The source family and adjustments remain external evidence, not reproduced fits. Registered genotype sample QC and projected PCs

analysis.genotype_sample_qc connects a declared common-autosomal hard-call panel to participant_qc, sample eligibility, optional genotype PC covariates, native association and aggregate finding evidence. It extends the default sample call-rate checks. The profile is disabled unless configured; enabling it requires a declared QC-panel genome build and scientific rationale. It is a bounded native implementation for the documented inputs, not complete assay or genome-wide production QC.

For example, an imputed association matrix can use a separate upstream-QCed observed hard-call panel, with exact selected sample-ID alignment:

yaml
datasets:
  - id: cohort_a
    type: gwas
    stage: processed_matrix
    files:
      matrix: cohort.bgen
      sample: cohort.sample
      phenotype: phenotype.tsv
      qc_genotypes: observed-common-snps.vcf.gz
    metadata:
      qc_genome_build: GRCh38
    columns: {sample_id: id}
hypotheses:
  - id: H
    description: Prespecified quantitative association and sample QC.
    inputs: {discovery: [cohort_a]}
    outcome: BMI
    covariates: [age]
    analysis:
      mode: manual
      goals: [association, impact_assessment]
      association: {model: ols, genotype_kind: imputed, minimum_info: 0.8}
      genotype_sample_qc:
        genome_build: GRCh38
        rationale: Prespecified common-autosomal QC and population-structure model.
        relatedness_action: exclude
        maximum_excluded_fraction: 0.10
        pca_components: 2
        include_pcs: true

This example chooses a quantitative independent-error model and an explicit related-sample exclusion rule; it is not a model recommendation for an arbitrary BMI study. A related cohort may require an appropriate mixed model instead. The original phenotype/genotype files remain unchanged. Resolution appends GPC1, GPC2 to the effective covariates, while the base contract retains its source covariate list. Generated columns cannot overwrite existing columns or be remapped to a different physical column. They apply to genotype participant matrices; mixed participant modalities require separate hypotheses.

The profile also runs when explicitly configured with manual goals that omit association, so users can complete missing QC without refitting existing analyses. A summary-result input cannot reconstruct participant QC. Without qc_genotypes, the main matrix supplies the panel. The current panel reader uses the supported VCF/BCF hard-call representation, or an explicitly declared unspecified hard-call contract with compatible locus metadata. Imputed dosages, even integral values, are not silently rounded into observed calls. A separate qc_samples file supports panel formats requiring external sample IDs. A missing selected sample holds the scope; extra panel samples do not replace the registered analysis population. QC and association panels can have distinct build declarations because they need not share variants; QC coordinates and registered exclusions must match the declared QC-panel build.

The executed flow is:

  1. Intersect phenotype and matrix IDs, check unique IDs and source complete cases, then apply the registered sample call-rate rule to the observed hard-call source. Its denominator is diploid biallelic autosomal SNPs after registered region exclusions and before MAF/marker-call-rate/LD filters. Complete imputed dosages cannot conceal poor observed call rates; structural sex-chromosome absence does not enter this denominator. Generated PCs need not exist yet. An already impossible native sample/memory/PCA bound stops before the full call-rate scan. An interrupted scan cannot exclude participants.
  2. Stream the complete permitted QC source. Restrict panel eligibility to human autosomes, unsplit biallelic SNPs, observed diploid hard calls and registered marker call-rate/MAF and region rules. Every examined marker retains a disposition. This does not remove that marker from association or rare sets.
  3. Choose the smallest SHA-256 priorities from the complete eligible universe, using the registered seed and locus/allele/ID identity. This prospectively defined marker sample is independent of source order and phenotype P values; it is not the first rows of an interrupted scan. Sort the sampled markers by chromosome/position/ID and greedily retain them unless a previously retained marker within the physical window exceeds the declared pairwise-complete r².
  4. Count shared observed hard calls for every sample pair. Retain heterozygote, opposite-homozygote and identical-call counts, KING equation 9 as context, and the equation 11 between-family estimator for the decision rule. Low shared support or zero/insufficient heterozygosity leaves a pair unavailable, not unrelated. Negative estimates remain visible.
  5. Apply the registered relatedness action. Report per-sample panel call rate, heterozygosity and robust median/MAD warning score; heterozygosity warnings never automatically delete participants.
  6. When requested, fit genotype PCs on the deterministic unrelated basis and project all current candidate samples with those basis frequencies/weights. Append generated PC columns only with include_pcs: true. Write the approved phenotype table only after all registered prerequisites pass.

The estimator uses the between-family rule for all pairs, as documented for PLINK 2 KING, with equations from Manichaikul et al.. Relatedness is flagged strictly above the registered cutoff. A negative screen does not prove unrelatedness or override a declared pedigree/related design. The default cutoff 2^(-3.5) screens approximately second-degree or closer relationships; numerical thresholds and support floors require study-specific appraisal. The minimum marker count is an eligibility floor, not a power or calibration guarantee.

Relatedness action Executed behavior
review (default) Hold when an estimable pair exceeds the cutoff; keep local diagnostics and request a design decision.
exclude Greedily keep samples in descending panel call-rate order, breaking ties by ID, provided they have no above-cutoff edge to an already kept sample. This deterministic independent set is not guaranteed maximum. Hold if proposed exclusions exceed the registered fraction.
model Keep all candidate samples only with an explicit supported quantitative GRM LMM route and files.grm, or the separately supported rare-score REML route. Downstream consumers still validate covariance inputs and fits. No binary mixed-model calibration is inferred.

Known pedigree/relatedness requires an appropriate declared model even if a panel screen or proposed pruning appears favorable. Repeated observations need a separately reviewed observation/covariance model. Duplicate-like genotypes cannot distinguish technical duplicates from monozygotic twins; review identity and pedigree evidence before interpretation.

PCA uses a genotype GRM standardized by sqrt(2 p (1-p)), where frequencies are estimated on the unrelated basis. Missing calls use that basis mean. Unit-norm basis eigenvectors define the scores; stored weights project all candidate samples, including held-out relatives, into the same basis. The mean, scale, weights, eigenvalues and variance fractions are retained. Numerically unavailable rank, invalid eigen residuals or a requested boundary splitting a tied eigenspace hold the operation. There is no automatic reduction in the number of covariates. The PCs can describe population, batch or family structure; they do not assign ancestry labels. See Price et al. and the PLINK PCA cautions.

Precomputed PCs can be supplied as ordinary phenotype-table covariates. Keep their provenance, include their column names in hypotheses[].covariates, and set pca_components: 0, include_pcs: false to complete missing panel QC without regenerating them. The method record explicitly reports PCA as not requested. With positive pca_components and include_pcs: false, native PCs are generated for diagnostics but do not silently change the regression. This is reuse of declared covariates; it does not independently validate their original PCA.

Association consumers apply per-marker quality filters. QC-only work does not require irrelevant main-matrix imputation metadata. Reuse external sample QC and PCA, and complete missing work

The source build accepts completed genotype sample-QC and PCA records through analysis.genotype_sample_qc. It validates the source artifacts and their scope, retains external attribution and runs only the missing work selected by the study contract. This is a normalized source-report interface, not an automatic parser for arbitrary tool exports or independent scientific certification of their results.

Available work Configuration and behavior
Missing QC and PCA Default source: native, pca_source: native. Run the registered bounded native route.
Completed QC and PCA source: supplied, pca_source: supplied. Reuse source decisions and scores; do not run native call-rate selection, KING or PCA.

The external report schema defines the normalized version-1 packet. It records:

  • The dataset, QC genome build, analysis ID, source status and exact current association-matrix SHA-256. Binding identifies the analysis matrix and source population; it does not assert that upstream QC used the same marker file.
  • Source software/versions, an observed-autosomal hard-call call-rate scope, threshold and source population count. The source threshold cannot be weaker than the registered analysis sample-call-rate requirement.

The sample-decision table must cover every matrix sample exactly once, including samples that currently lack a phenotype. Its columns are:

text

This is a tab-separated header, not space-separated input. status must be complete for accepted decisions. decision is keep or exclude; excluded rows use call_rate, relatedness or other_qc as their reason. Kept rows use an empty reason or retained. Observed call rates must be finite in [0,1], and retained samples must pass the declared source threshold. Relatedness-pruning losses remain subject to the registered exclusion fraction. A model or review action cannot claim relatedness-pruning exclusions. Keeping relatives still requires an appropriate explicit quantitative GRM model; known pedigree or repeated observations retain their separate design requirements.

The independent-basis assertion and membership list are not prerequisites for QC-only reuse or already completed external PCA. If they are missing when native PCA is requested, accepted QC exclusions remain intact while PCA waits. An absent list is unavailable information, not a fabricated zero-person basis. The native fit uses its intersection with current phenotype/covariate eligibility, retaining every source-QC-kept candidate for projection even if not a basis member. It does not run KING again or remove another sample merely to make a smaller native PCA problem fit.

The supplied score table uses sample_id and the component names declared in pca.columns, for example PC1, PC2. Requested columns must be finite, IDs unique and all source-QC-retained samples covered. Extra projected scores may belong to source-QC-excluded members of the same matrix population. JLinAlg normalizes requested components to the registered output names (GPC1, GPC2 by default), joins by ID and never overwrites existing phenotype columns. include_pcs: false retains requested imported scores as diagnostics without silently adding covariates. Changing the phenotype subset does not refit, recenter or redefine the source PCs or their reported basis.

An incomplete QC universe, mismatched matrix/sample scope, hash mismatch, unresolved pair support, missing scores, invalid values or exceeded import budget holds approval. There is no silent intersection, automatic replacement fit or promotion of a partial source report to a complete scientific analysis. If only PCA is pending, accepted QC exclusions remain in the local diagnostics while association waits. Explicitly choosing native missing-PCA completion can finish that stage without re-executing source QC. Independent branches can continue under their existing prerequisite rules.

The report itself has a two-megabyte metadata bound. Normalized UTF-8 TSV records allow at most 256 columns and 65,536 characters per line; embedded tabs/newlines or quoting are not part of this format. Work limits are computational bounds, not runtime or memory-use promises. Native missing-PCA completion keeps the native panel, LD, memory and eigensolve/projection limits.

Cross-mask rare-set and gene omnibus

rare_set_omnibus forms a new set/gene hypothesis from registered component tests, retaining original mask/test results and adjustments. The default supplemental stage combines one primary test per mask using Bonferroni minimum-P, then applies a separate BY family in each primary/discovery/cohort scope. component_tests: all includes every registered test; no best observed test is selected. Automatic mode proposes the stage for rare-set sources; manual mode runs an explicit omnibus goal or a requested primary omnibus. Unrequested supplemental work does not hold an otherwise completed manual rare-only analysis. An explicit tests list requires component_tests: all; primary identities come from the sealed source. enabled: false makes the optional stage not applicable.

yaml
analysis:
  mode: manual
  goals: [rare_variant_analysis, rare_set_omnibus, gene_ontology, literature_search]
  rare_omnibus:
    selection: primary
    unit: gene
    gene_map: reviewed-set-to-gene.tsv
    masks: [lof-001, damaging-missense-001]
    component_tests: primary
    method: bonferroni_min
    adjustment: BY
    alpha: 0.05

Default unit: set keeps source IDs. unit: gene needs reviewed tab-delimited feature_id, gene_id, gene_symbol mappings or sealed source annotation; a reviewed symbol can identify a gene when a stable ID is absent. Several sets may map to one gene: all their components enter that gene's omnibus before correction across genes. Ambiguous mappings fail; unmapped sets remain visible and hold correction.

For K components, Bonferroni minimum-P is min(1, K * min(P)). Optional method: acat uses equal-weight Cauchy combination with finite natural-log tails. This approximation requires valid component P values. P=1 triggers the registered Bonferroni fallback, as in SAIGE-GENE+. Liu et al. describe ACAT; this stage does not reproduce SAIGE-GENE+'s mixed-model fitting.

Each source set needs the registered mask/test grid in every scope. Missing or failed components remain unresolved, never P=1. Conditional tests of frozen network wiring

network_preservation_null is a separate, opt-in stage. It tests a prespecified reference edge pattern against a conditional target-label null. Descriptive module preservation, GO enrichment, association discoveries and WGCNA Zsummary remain separate results. The frozen-reference/permutation motivation follows Langfelder et al.     method: auto

    draws: 9999

    alpha: 0.05
    exchangeability_rationale: Scientist-authored justification for this conditional label null.
    # strata_file: registered-node-strata.tsv

Use the exact aliases of the native or supplied graphs. In automatic mode, enabled: true requests this stage; an explicit goal also requests it. The default is disabled. A missing scientific exchangeability rationale holds the test rather than treating all gene labels as exchangeable by default. A label or nonempty rationale does not independently certify the scientific assumption.

Let U be all nodes shared by the reference and target graphs, M the frozen reference module restricted to U, and E the reference edges within M. For each legal within-stratum bijection pi of U, the statistic counts edges (i,j) in E whose mapped pair (pi(i),pi(j)) occurs in the target graph. The default signed_edge_overlap also requires the target sign to match the reference sign. edge_overlap ignores sign. Weight magnitudes are not tested. Module membership and reference wiring stay fixed; the whole common-node universe is eligible for relabeling, including nodes outside the module.

The target graph's topology and signs are retained under relabeling. Optional strata are fixed before inspecting target preservation results and have columns node_id and stratum. Every shared node needs one unique assignment. Missing assignments never fall back to unrestricted permutation. Extra assignments outside a comparison's shared universe are unused. Missing module nodes remain missing; they do not become zero correlations. The existing source comparability, coverage, minimum-size, graph and membership bounds apply first.

auto enumerates the entire product of within-stratum permutation groups when it fits exact_maximum; otherwise it uses the fixed registered sampled draw count. Explicit exact waits if enumeration exceeds that bound. Exact P is the fraction of all legal permutations with statistic at least the observed value, including ties and the identity. Sampled draws are independent uniform within-stratum permutations with replacement, and P = (b + 1)/(B + 1). It is never a zero or a tail extrapolated beyond the draw resolution. These rules require the null's group-invariance assumptions; see Hemerik and Goeman (2018).

Sampled results retain a 95% exact binomial interval for the conditional extreme tail fraction, using beta quantiles as in the Clopper-Pearson procedure. This measures Monte Carlo precision, not participant-sampling uncertainty, and is not a simultaneous interval across modules. Exact results repeat their exact P as both interval limits. A small draw budget may be unable to resolve significance after multiplicity correction; the software does not extrapolate smaller P values or stop sampling early after observing a favorable result.

The separate testing family contains all planned reference-module/target rows for this hypothesis and one registered statistic. Definitively non-estimable rows reserve denominator positions. Missing sources, unresolved comparisons or work contracts withhold all adjusted P values and discoveries, while retaining available raw tests. BY is the default for dependent comparisons. BH requires its own dependence assumptions; Bonferroni controls familywise error and NONE is nominal. These are not association FDR values or a joint cross-phenotype family. Neither the primary graph/cohort set nor association candidates change.

max_work defaults to 100000000 declared label-position/edge-query work units; max_null_rows defaults to 100000 histogram rows. Bounds apply to the complete requested matrix, not a preferred module prefix. They are computational contracts, not guarantees about wall time or support for genome-wide scale. Native quantitative and binary score development can now repeat preprocessing and penalty selection inside nested validation folds. This addresses the optimism that arises when the same validation errors both select a model and describe its performance. The design follows the separation described by Varma and Simon and the official grouped-validation guidance. It does not establish performance in a real population from software fixtures.

For quantitative evaluation, prediction_link: identity requires an explicit frozen intercept/rationale and the separate frozen baseline comparator. For binary raw-score discrimination, use family: binary, prediction_scale: raw and prediction_link: none; no probabilities are invented. For binary probability metrics use prediction_scale: probability, prediction_link: logit, a source intercept/rationale, and a frozen probability baseline. The optional prediction_linear_column supplies an already frozen covariate contribution. Target outcomes, IDs, partitions, groups and registered related phenotypes cannot be that component. Case/control probabilities do not establish population absolute risk or clinical calibration. Survival score evaluation/development still requires a censoring-aware route; frozen scores can support appropriately registered related-trait follow-up.

Metadata use globally unique record IDs plus source and exact FID/IID. Shared IIDs across families/cohorts are allowed. Repeated physical genotypes within a source require the same partition and declared resampling unit, and cannot be declared independent rows. Existing group/partition and training-ID overlap checks also apply. Neither unique IDs nor source labels prove unrelatedness or exclude discovery-GWAS overlap. Each registered source must contribute complete eligible evaluation records; the workflow holds instead of dropping a whole cohort because its calls, outcomes or frozen predictions are unavailable.

Default bounds are 1,000,000 model variants, 50,000,000 scanned source variants, 1,000,000 samples per BED source, 1,000,000,000 decoded genotype cells shared across sources, 256 MiB compressed/decompressed weights, 1,024 MiB BIM/FAM input per source, estimated 512 MiB retained metadata per model/reader, and 65,536 bytes per line. Set the corresponding maximum_* fields to tighter limits as needed. The native BED reader checks dimensions, header, metadata, duplicate IDs and selected-row padding. Genotypes and weights enter cache identity through their content hashes, and hashes are checked again after application. Inputs are not rewritten; large genotype inputs are referenced and hashed, with raw weights snapshotted locally. Byte/hash scanning and metadata validation are additional I/O work; the cell count describes decoded genotype rows, not total CPU work.

Local outputs include genetic-model-coverage.tsv, genetic-variant-alignment.tsv, genetic-participant-disposition.tsv, genetic-score-application.yaml, participant scores, held-out metrics and the registered related-trait family. Failed prerequisites retain local diagnostics and completed alignment/coverage prefixes without official participant scores or evaluation metrics. The finding inventory forwards whitelisted aggregate model/application context only; genotype vectors and sample identities stay local. A caller's model/strand/frequency/independence statements remain source declarations requiring scientific appraisal.

Previously completed performance or related-trait families can still be supplied through typed supplied_results. Supply frozen participant scores when only related testing is missing. If both stages are supplied, the study does not open the genotype files or reconstruct the score. This preserves the laboratory's complete-only-missing-work contract.

Frozen scores from VCF, BCF and BGEN

The complete frozen-weight study route also accepts VCF, compressed VCF, BCF and BGEN, and can combine them with BED cohorts in one registered evaluation. The same model, source-unit normalization, frozen prediction, observed-call eligibility, held-out metrics and separate related-trait family apply. The new source fields extend the BED contract:

yaml
genotypes:
  weights_genome_build: GRCh38
  source_column: cohort
  iid_column: genotype_id
  sources:
    - {id: cohortA, bfile: genotype/A, genome_build: GRCh38}
    - {id: cohortB, file: genotype/B.vcf.gz, genome_build: GRCh38}
    - id: cohortC
      file: genotype/C.bgen
      genome_build: GRCh38
      samples: genotype/C.sample  # only needed without embedded BGEN IDs
  prediction_link: identity
  intercept: 1.2
  prediction_rationale: Frozen quantitative source intercept and original units

Each source requires exactly one bfile or file. Supported inferred suffixes are .vcf, .vcf.gz, .vcf.bgz, .bcf and .bgen. For an unconventional filename, set format: VCF, VCF_GZ, BCF or BGEN explicitly. BED continues to match exact source/FID/IID tuples. Variant-file headers contain one unique sample ID per column, matched through iid_column; FID is not used for those sources. Identical IIDs in different sources are disambiguated by source_column. Repeated records for a physical source/IID require the same partition and declared resampling unit and cannot be declared independent. Every active metadata record must have an exact genotype match; a silent population intersection is not substituted.

Keep supplied external development/training IDs in the same global record-ID namespace used by the local overlap check, or retain an explicit identity map before interpreting a match/non-match. Source labels and different local record IDs do not establish independent people or exclude discovery-GWAS overlap.

VCF/BCF use declared FORMAT/DS when available, falling back to called GT. GP/PL fields alone do not supply dosage in this reader. BGEN layout 2 supplies expected ALT dosage from phased/unphased probabilities; its existing decoder supports uncompressed, zlib and zstd data. The score counts ALT or 2 - ALT according to the model effect allele. It does not infer strand or change the frozen model. Human autosomal, exact-build and complete-allele requirements remain in force.

A selected multiallelic decomposition holds: complementing one ALT dosage would otherwise also count other ALT alleles. An observed non-diploid genotype in an active participant also holds. Finite DS with unknown observed ploidy requires the source's explicit diploid_dosage_declaration, for example a documented autosomal diploid imputation export with GT withheld. That statement remains a caller declaration. Unknown ploidy for a missing call does not establish an observed haploid genotype. The local alignment audit and aggregate context record assumed-diploid dosage cells. They do not certify biological karyotype. Unselected VCF/BCF multiallelic rows can be decoded and counted; the current BGEN reader requires biallelic source records throughout the file.

BGEN files without embedded IDs require samples: an Oxford two-header-line .sample file or a headerless sample-ID list using the existing sample parser. Oxford files use ID_2. A sidecar supplied alongside embedded IDs must match their ordered identities exactly; it cannot override a conflict. Sidecars are bounded, hashed and included in cache identity. Reordering VCF/BCF/BGEN sample headers preserves the matched participant ordering.

Before genotype decoding, a separate admission scan checks bounded headers, record framing, decompressed sizes, sample dimensions and the complete source inventory. BCF 2.1/2.2 are streamed with compression detected from file magic, including standard BGZF .bcf files. This fixes the former suffix-based core reader path, which could send gzip bytes straight to the BCF codec. The direct core reader also supports ordinary gzip streams. The scoring admission scan is specific to this study route; it does not add these resource checks to every other VariantSources consumer.

The scan then admits the whole operation's registered cell/work budgets before score accumulation. Sequential sources count all source samples times every emitted ALT row, including nonmodel variants and unused source participants. The entire stream is exhausted, even after all model members have matched, to detect later duplicate loci and malformed trailing data. BED seeks model rows, so its decoded-cell contribution is source samples times model variants. Source inventory work units sum max(physical records, emitted ALT rows) per sequential source and BIM rows per BED source; source_variants_scanned reports that budget counter. Per-source reports retain both physical and emitted counts where they differ. No score, cohort or test prefix is promoted after an incomplete source.

Additional defaults are maximum_source_mib: 65536 per raw genotype file, maximum_decompressed_mib: 131072 per sequential source, maximum_header_mib: 64 and maximum_record_mib: 64. The existing one-billion cell default remains, but an explicit maximum_cells can now admit up to 50 trillion cells with long counters. Metadata/record sizes and retained-header estimates are admission limits, not a JVM heap or elapsed-time guarantee. Preflight, hashing and probability decompression add I/O/CPU work beyond the decoded-cell counter. For large sequential files, register adequate budgets or supply an independently prepared source subset containing every frozen-model member. Do not select that subset using target outcomes or a target MAC cutoff.

The new source_format, counted_allele and ploidy_status alignment columns make orientation explicit. Legacy source_a1/source_a2 fields represent BED A1/A2 or variant-file REF/ALT; the counted allele is BED A1 or file ALT before the recorded reversal. Generic source-format and assumed-diploidy counts enter the finding inventory; sample IDs, genotype vectors and free-text source declarations remain local. Before/after hashes bind source and sample sidecars. Typed supplied performance or related families still skip their completed work; both supplied stages can be used with missing genotype files. When only related testing is missing, frozen genotypes/weights can be reapplied without evaluating the outcome again, or frozen participant scores can be supplied directly.

Molecular assay QC and supplied decisions

Supported bulk molecular matrix consumers now receive a separate assay_qc producer before participant selection, association (including Cox), native correlation networks, adjusted subgroup interactions and direct-matrix risk scores. The stage reads a feature-by-sample CSV/TSV and its optional paired measurement-detection table. It reads no phenotype or outcome. Matching dataset and resolved policy share one source producer across hypotheses. A completed supplied analysis or metadata-only supplied graph does not trigger raw assay QC. A standalone manual goals: [assay_qc] is also supported.

The default is audit: retain all samples/features and record proposed QC flags. Explicit mode: filter materializes a new matrix; original input bytes remain unchanged. These generic defaults are starting controls to review against the assay protocol, not validated thresholds for every molecular platform:

yaml
analysis:
  mode: manual
  goals: [association, network_analysis]
  association: {model: ols}
  assay_qc:
    source: native
    mode: filter
    value_scale: continuous
    maximum_feature_missing: 0.2
    maximum_sample_missing: 0.2
    minimum_observed: 3
    minimum_sd: 0
    drop_constant: true
    invalid_values: hold
    detection_kind: none

value_scale accepts unspecified, continuous, nonnegative, counts or proportion. All retained numeric values must be finite; the latter three add range/integer checks. Counts must be exact integers no larger than 9,007,199,254,740,991 per cell. Count totals use exact integer arithmetic, including an overflow-safe accumulator, rather than rounded floating point sums. This is measurement QC, not count-model normalization. Standard empty/NA/NaN/null/dot cells remain missing. Invalid/nonrepresentable values hold the stage by default. Only explicit mode: filter, invalid_values: mask replaces invalid native cells with NA; it never rounds counts, clips values or imputes measurements.

Sample missingness always uses every original source feature. Feature QC always uses every original source sample. Decisions are made once; removing features does not recompute sample denominators, and removing samples does not restart feature selection. Source missingness, proposed masking, feature means, sample SDs, scaled moments, exact constant flags and log SDs are local audit outputs. A rounded zero SD is not used to infer an exactly constant feature. Source statistics do not describe a phenotype-specific model's actual N.

For platform detection, register files.assay_detection with identical sample IDs/order and feature IDs/order. detection_kind: p_value passes a cell at p <= detection_threshold (default 0.01); detected accepts only binary 0/1 and passes 1. Detection bounds and cutoff comparisons preserve the decimal source value, including probabilities below double precision and values just outside [0,1]. Missing detection fails detection. Reordered, missing, extra or invalid detection records hold the whole stage. Audit mode records flags without changing measurements; filter mode masks failed cells and applies the fixed QC rules.

Already completed lab QC can supply decisions for the current supplied matrix:

yaml
assay_qc:
  source: supplied
  supplied_report: inputs/lab-qc.yaml
  supplied_samples: inputs/lab-sample-decisions.tsv
  supplied_features: inputs/lab-feature-decisions.tsv
  dataset_overrides:
    proteins: {value_scale: nonnegative}

The report must identify schema_version: 1, dataset_id, exact current matrix_sha256, sample_count, feature_count, input_state: before_qc or post_qc, and method: {name: ..., version: ..., parameters: {...}}. Each TSV/CSV decision table has sample_id or feature_id, decision: keep|exclude, and an optional reason. Complete exact coverage of the current matrix is mandatory; missing, extra or duplicate IDs are not silently intersected. A post-QC matrix can keep every currently supplied ID without recovering unavailable original raw files. Upstream exclusions remain source-reported history. Excluded feature/sample cells do not need to pass the current retained-value contract. Kept cells do.

Supplied reports and decisions are copied and hashed. Native thresholds and moments are not recomputed for supplied decisions, and inherited native controls are not represented as executed. Reuse validates identity, coverage, structure and retained numeric values; it does not independently certify the lab's methods. Only aggregate source-population QC context enters finding appraisal; decision reasons and participant/feature vectors stay local.

The producer seals assay-qc.yaml, assay-feature-qc.tsv, assay-sample-qc.tsv and, when applicable, assay-matrix.tsv. Consumers verify its completed state, producer ID, dataset, resolved policy, original source hash and all sealed output hashes. Invalid or incomplete source scopes and zero retained samples/features hold consumers. Separate policies for one dataset get separate producers. enabled: false explicitly bypasses this stage. Supplied association/enrichment/MR/network results retain their own historical populations; current source QC does not retrospectively validate them.

No imputation occurs in assay QC. Association already has its own within-analysis mean-imputation behavior, while score imputation/scaling is learned inside the appropriate development fit/fold. Score features remain independently prespecified: if QC excludes a required predictor, the entire score is held instead of being refitted on a favorable feature intersection. Fixed source denominators prevent validation-driven feature selection from changing training sample QC. Outcome-free QC alone does not prove statistical independent filtering, assay chemistry validity, model validity, FDR calibration or independent external validation.

maximum_features (2,000,000), maximum_samples (1,000,000), maximum_cells (1,000,000,000), maximum_source_mib (65,536), maximum_record_mib (64) and maximum_retained_mib (512) bound source scans and estimated retained metadata. The actual admissible combination can be smaller than each separate maximum. This adapter covers plain CSV/TSV bulk matrices; platform chemistry, batch effects, normalization, contamination and donor/cell-aware models require their own reviewed preparation or compatible supplied results.

  • impact: require a complete provisional assessment and comparative selection when capping is necessary. Unavailable or invalid responses leave allocation waiting. They cannot silently authorize a statistical prefix instead.
  • p_value: explicitly retain the deterministic source-P ordering.

When every eligible target fits, all are retained without an additional AI interaction. Completed supplied literature also skips the native allocation stage. This policy applies separately within each hypothesis's literature scope; the final manuscript impact review remains study-wide.

The provisional stage uses bounded public phenotype/field labels, allowlisted feature/gene identifiers, original P/FDR and available finite signed summaries. Missing public phenotype context holds AI allocation. It exposes missing scale, mechanism and source appraisal as uncertainty rather than inventing them. Original source methods and free-text provenance stay in their existing local artifacts. The same impact-purpose opt-in, provider, local-loopback and disclosure rules apply. Provisional review adds interactions before final manuscript ranking; the call budget applies separately to these two stages.

Every target receives a bounded assessment, including its evidence link, provisional priority and missing evidence. Comparative rounds then reduce the assessed pool to the registered number of review slots. Complete leaf assessments and eliminated candidates stay in the audit. This advisory procedure does not prove a globally optimal ranking or a biological mechanism. Unknown prior literature can be a reason to investigate a target; it is not evidence against it.

The native operation retains:

  • literature-priority/candidates.jsonl: the uncapped allowlisted projection and stable candidate identities for AI allocation.
  • literature-priority/selection.yaml: all assessments/comparisons, selected IDs, pending needs, attempted/reused interactions and observed requests sent.
  • literature-selection.tsv: the complete statistical inventory, its original statistical rank, separate review_rank, selection basis and retrieval status.

If the request budget, comparative payload, policy or response is unresolved, target-specific retrieval waits and all targets retain an explicit pending disposition. Independent field/method searches can continue. A pending target is neither outside the cap nor a negative literature result. Increase an interaction budget through a native study amendment, then repeat study auto; matching sealed node responses are reused without altering historical runs. If the compact comparison cannot reduce the pool, increase the declared payload bound rather than dropping an unexamined prefix.

Phenotype-null GSEA and reusable null rankings

gsea.null_model: phenotype now has two executable routes. Native analysis uses one bulk molecular cohort at a time and the registered independent Gaussian identity OLS model. The second route consumes complete observed and joint null gene rankings produced with another appropriate model, including a pooled model. A completed supplied ranked_gsea result continues to bypass fitting and allows only missing pathway/module work to run.

Native analysis is an additional, registered cohort analysis. It recomputes the complete eligible ranking from the QC population; it does not use a significance-selected list or turn one cohort's permutations into a pooled/meta-analysis null. It uses the same PhenotypeData/Formula machinery as matrix association for outcome orientation and treatment-coded covariates. Molecular missing values are mean-imputed within the aligned analyzed samples. All-missing, constant or nuisance-explained features and ambiguous/unmapped gene annotations retain explicit dispositions. A numerical predictor-variation threshold is applied before outcome ranking. Multiple probes per gene require a declared mean/median collapse, repeated identically in every draw.

yaml
schema_version: 1
project:
  id: phenotype-gsea
  title: Cohort-specific phenotype-null GSEA
  description: Complete an independent quantitative-trait pathway analysis
resources: {directory: resources, network: offline, downloads: deny}
cohorts: [{id: A}]
datasets:
  - id: expression-a
    cohort: A
    type: expression
    stage: processed_matrix
    species: human
    feature_id_type: gene_symbol
    files: {matrix: expression.tsv, phenotype: phenotypes.tsv}
hypotheses:
  - id: quantitative-trait
    description: Association of the measured expression features with the trait
    outcome: trait
    covariates: [age, sex]
    analysis:
      mode: manual
      goals: [ranked_gsea, pathway_network, network_modules]
      association: {model: ols, family: gaussian}
      gsea:
        null_model: phenotype
        phenotype:
          independent_samples: true
          exchangeable_errors: true
          strata_column: sex
          rationale: Review the residual assumptions and strata for this study
        gene_sets: collection.gmt
        minimum_size: 15
        maximum_size: 500
        maximum_exact_states: 0
        permutations: 10000
        seed: 31
        maximum_work: 250000000
        adjustment: BY

The two declarations express assumptions the scientist must assess; the software does not establish independence or exchangeability from them. A declared stratum must also occur among the nuisance covariates. An omitted stratum permits permutations across all analyzed samples. This route requires at least ten samples by default and at least two full-model residual degrees of freedom. minimum_samples, maximum_samples, maximum_features, maximum_cells and maximum_design_columns are explicit native resource controls. Complete model refits and enrichment work share maximum_work; exceeding it holds the stage with no favorable subset or smaller draw count.

Freedman–Lane permutes reduced-model outcome residuals, adds nuisance fitted values and recomputes the full signed partial-t ranking. Every gene shares the same row permutation, preserving the dependence induced by the fixed measured features. With general nuisance covariates this is an approximate procedure, even when every residual permutation is enumerated. The registered errors must be exchangeable within strata. See Winkler et al., 2014 for nuisance adjustment and exchangeability assumptions, and the Broad GSEA guide for the distinction between phenotype and gene-set nulls.

When the product of within-stratum factorials fits maximum_exact_states, the native route enumerates that entire residual-permutation census, including identity. Otherwise it uses the declared number of seeded Monte Carlo draws with replacement. Native kinship, repeated-measure, non-Gaussian, offset and custom-formula adapters remain prerequisites. These cases need an appropriate complete external null-ranking ensemble or a completed supplied GSEA stage. There is no automatic unadjusted-label or gene-set-null fallback.

To reuse a complete external ensemble, replace phenotype with explicit ranking and null_rankings:

yaml
null_model: phenotype
ranking:
  file: observed.tsv
  coverage: complete
  tested_genes: 20000
  provenance: {producer: Your registered complete gene-level model}
null_rankings:
  file: null-rankings.tsv
  draws: 10000
  sampling: monte_carlo  # or exhaustive, only for the complete registered census
  coverage: complete
  observed_sha256: REPLACE_WITH_THE_64_HEX_DIGIT_OBSERVED_FILE_SHA256
  method: Your joint resampling procedure
  model: Exact model, contrast, sample population and feature preprocessing
  exchangeability: Appropriate joint-null assumptions and block structure
  provenance: {producer: Your software version and immutable source receipt}

The null file is UTF-8 TSV with the exact header draw_id, gene_id, statistic. Each unique draw ID occupies one contiguous block and contains every observed gene exactly once, with a finite statistic. Gene row order may differ across draws. Missing, extra, duplicate or mismatched genes/draws hold the whole correction family. The observed-file SHA binds the null ensemble to the exact ranking bytes; both files enter cache identity and are snapshotted. Monte Carlo ensembles must contain independent draws from the registered joint null; an exhaustive census must contain equiprobable states. This format does not carry unequal state-probability weights or an MCMC autocorrelation correction. Use an appropriate independent simulation or completed source inference for those designs. Source model, exchangeability and exhaustive-coverage declarations remain claims to review. These checks do not reproduce the external model's calibration. Whole-stage supplied results remain useful when null rankings are unavailable.

Both routes produce the canonical full-family ranked-gsea.tsv, leading edges, effective GMT and optional running-ES curves consumed by pathway graphs/modules. Each term gets its own null ES distribution under shared gene rankings. Positive/negative tails, same-sign normalization, draw/tail counts, P resolution and Wilson Monte Carlo intervals are retained. BH/BY/NONE correction is applied over the complete eligible family; this is not Broad's pooled-NES empirical GSEA FDR. Undefined draws/scores suppress official family correction. Native null-rankings.tsv and native-observed-ranking.tsv can seed a later aggregate-only reuse project; participant sample audits remain local.

Continuous GWAS annotations and conditional effects

gwas_enrichment.annotation_mode: mixed adds a joint native S-LDSC model containing binary and continuous annotations. It supports centred or signed continuous scores, including continuous nuisance variables. The existing binary default keeps its fixed aggregate-annotation weighting convention. Mixed mode uses fixed initial weights based on the first all-SNP LD column and its reference count, so changing a continuous score's units does not change the weighting model. All registered columns remain in every fit and delete-block calculation; there is no outcome-driven nuisance selection or automatic column dropping.

Use the complete GWAS/LD/reference contract in the GWAS enrichment guide, adding this explicit mode and the new annotation metadata:

yaml
gwas_enrichment:
  annotation_mode: mixed
  summary:
    file: complete-gwas.tsv
    coverage: complete
    tested_snps: 600000
    population: YOUR_MATCHED_POPULATION
    genome_build: GRCh38
    calibration: one_df_chi_square
    model: YOUR_REGISTERED_GWAS_MODEL
    qc: YOUR_GWAS_QC_AND_CALIBRATION_RECORD
    ascertainment: quantitative
  reference:
    population: YOUR_MATCHED_POPULATION
    genome_build: GRCh38
    release: YOUR_IMMUTABLE_REFERENCE_RELEASE
    common_variant_definition: YOUR_COMPLETE_COMMON_REFERENCE_UNIVERSE
    regression_snp_definition: YOUR_GENOME_WIDE_REGRESSION_PANEL
    annotation_model: ALL plus all registered binary and continuous target/nuisance columns
  ld_scores: matched-ld-scores.tsv
  annotations: annotation-metadata.tsv
  overlap: reference-cross-products.tsv
  blocks: 200
  adjustment: BY

In mixed mode, annotations needs term_id, term_name, role, annotation_type and sum. The role is all, target or nuisance; annotation type is binary or continuous. The first and only all row must be the binary all-reference-SNP baseline. Here is an illustrative format, with values that must be replaced by the actual reference moments:

text
term_id  term_name            role    annotation_type  sum
ALL      All reference SNPs   all     binary           1000000
BINARY   Registered category  target  binary           200000
SCORE    Registered score     target  continuous       0

The sum of a binary annotation is its SNP count. A continuous sum can be fractional, zero or negative; it is not a SNP count. The file registered as overlap contains the complete uncentred reference cross-products Q[j,k] = sum_i a[i,j] * a[i,k], with one term_id row and one column for each registered annotation ID. It must cover the same full reference universe as the sums. For the illustrative metadata above, one possible moment matrix is:

text
term_id  ALL      BINARY  SCORE
ALL      1000000  200000  0
BINARY   200000   200000  25000
SCORE    0        25000   1000000

Actual files are TSV/CSV with named columns. Native validation checks finite/symmetric moments, baseline identities, binary intersections, population variances, positive semidefiniteness and reference-model rank. The supplied ld_<ID> columns must correspond to those same annotation definitions; a noncollinear LD table cannot rescue a dependent reference model. Signed continuous LD scores are allowed. Include the appropriate prespecified LD/MAF/functional nuisance annotations: an all-SNP baseline alone does not establish adequate architecture adjustment. Correct population, build, annotation release, reference universe and GWAS calibration remain source declarations to assess scientifically.

A continuous target's primary test is the two-sided normal approximation for its conditional coefficient, accounting for all registered annotations. Its standardized effect is tau_star = coefficient * population_SD(annotation) * reference_SNPs / total_h2. The SD comes from the complete reference moments, not the matched regression subset. Delete-block coefficient/total-heritability ratios provide the standardized-effect SE, including denominator uncertainty. The primary P value uses the raw coefficient's jackknife SE; it is not obtained by dividing tau-star by its ratio SE. These are conditional association-model summaries, not proof of a functional mechanism. See Gazal et al., 2017 for continuous annotation effects and their standardization.

Binary targets retain category-versus-complement t(B) tests and overlap-aware category heritability. Their conditional coefficients and standardized coefficients are additional context; coefficient_p is a secondary unadjusted test for binary rows. Continuous rows retain NA for binary category proportions, enrichment and complement tests. annotation_type, inference_target and method identify each row's estimand. All prespecified targets share one complete BH/BY/NONE family, with nuisance columns excluded from that testing denominator. Weak/nonpositive total heritability, invalid delete ratios or unestimable target tests withhold every official adjusted value.

Correction uses natural-log tails. log_p_value, log_adjusted_p and coefficient_log_p retain strong associations whose linear columns underflow to zero. They are natural logarithms, not minus-log10 scores. Use the log values for scientific tail reporting. The canonical gwas-enrichment.tsv adds raw/standardized coefficient estimates and SEs, annotation sum/SD, inference labels and mandatory caveats. sldsc-standardized-block-deletes.tsv exposes the standardized delete estimates, alongside the existing coefficient covariance, raw deletes and regression-SNP audits.

A completed external gwas_enrichment table can be supplied without GWAS summary or LD files. New numeric and inference-label columns, original family adjustment, log tails and row caveats survive import into finding dossiers. A declared continuous row must use the conditional-coefficient inference target and cannot claim binary enrichment statistics. Negative uncertainties, nonfinite numeric values and positive log probabilities are rejected. External analysis/calibration is not independently reproduced. Whole-stage reuse still completes only missing downstream work.
