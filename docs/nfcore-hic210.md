# Original nf-core/hic 2.1.0 workflow

`nfcore-hic210-tools` runs the complete selected original restriction-digestion Hi-C workflow for a new paired-end cohort. It captures the entire input cohort and FASTA, executes the original source, then uses native Java to check every retained valid-pair projection and every raw integer pixel of the selected balanced Cooler maps. The command requires a packaged executable JAR built from the current source.

The profile pins all 126 original files at commit `fe4ac656317d24c37e81e7940a526ed9ea812f8e`, 17 Git executable declarations, 14 exact container images and 30 process/import aliases. Original source files remain unchanged. A separate configuration supplies local images, an executor and a writable per-task `MPLCONFIGDIR=.matplotlib`. The selected engine is Nextflow 22.10.6; this selection does not establish a paper's unreported engine edition.

## Prepare exact prerequisites

Execution requires x86_64 Linux Java 17 or later, including Linux Java inside WSL, a native Linux session directory, enough space for complete captured inputs and outputs, and permitted unprivileged container execution. Complete these separate setup operations before analysis:

1. Use the [source setup](literature/NFCORE_SOURCE_WORKFLOWS.md) with profile `nf-core/hic-2.1.0`. The request's `source_directory` points to the exact extracted source directory. Generated or extra source files are refused.
2. Use the existing [managed Nextflow setup](literature/NFCORE_FOUNDATION.md) for profile `linux-x86_64-nextflow-22.10.6`, retaining its completed setup report. The current packaged command `nfcore-tools --export-runtime-setup NEW_DIRECTORY` exports that setup kit; consult `nfcore-tools ENGINE --help` for engine execution commands.
3. Prepare the exact private Apptainer 1.5.5-1 runtime described in the [container guide](literature/NFCORE_CHIPSEQ200.md). Its full payload and all selected image namespaces are checked before execution. Namespace permissions must already be available; analysis never changes host security settings.
4. Export and run the separate Hi-C image installer:

```sh
java -jar "$OMICS_JAR" nfcore-hic210-tools --export-image-setup ./new-hic-image-setup
python3 ./new-hic-image-setup/setup.py \
  --home /private/new-hic-images --report /private/new-image-report \
  --cache /private/hic-image-cache --allow-install --allow-download
```

The image helper requires Linux/WSL Python 3.11 or later. Home, report and cache must be disjoint canonical paths. Use a new report every time. Download and install flags are explicit; omit the download flag to use exact SHA-256-named cache files. Omit both flags to check an existing completed home. Corrupt cache files and incomplete downloads remain retained. The resulting `declaration.json` supplies the request's `image_set`. This helper installs images only; it admits no analysis. Keep upstream images, source, raw outputs and scientific inputs private according to their applicable terms.

## Declare the complete cohort and analysis

Copy [the complete request example](../examples/nfcore-hic210/request.json). Replace every prerequisite, FASTA and FASTQ path and select the scientific settings appropriate to the actual experiment. The example's HindIII and yeast-control resolutions document software-control settings; they are not recommended human-analysis parameters or inferred author settings. Paths must be absolute Linux paths. The reference label records provenance only: it neither certifies assembly identity nor selects an iGenomes genome. Supply the complete explicit FASTA; reference indexes and restriction fragments are generated by the original workflow.

Each sample has a literal `id` and a nonempty `libraries` array of complete paired FASTQs. Technical libraries remain under their biological sample and are never counted as independent replicates. Do not omit libraries, shorten reads or select a smaller chromosome population to satisfy capacity. The original checker requires matching `.fastq.gz` or `.fq.gz` mate suffixes. Unsupported source-interpolated IDs/basenames are skipped without renaming; source-compatible letters, digits and `_.-+:=@%` are accepted. Original names and their captured paths remain recorded.

All 20 science fields are explicit. The supported restriction presets are `hindiii`, `mboi`, `dpnii` and `arima`; custom digestion and DNase need separate contracts and are skipped. TAD callers can be `insulation`, `hicexplorer`, or both as a comma-separated selection. No request can disable mapping, balancing, multiresolution maps, decay, compartments, selected TAD callers, MultiQC or version reporting to bypass a failure. The original optional `hicpro_maps` branch is selected explicitly. Resolution strings contain distinct positive integers; an empty `res_zoomify` retains the original automatic zoom selection.

Declare executor/task resources, complete-table capacities and engine/process capture limits for the entire cohort. Task limits must fit the executor. Capacities are checked bounds, not operating-system memory or disk reservations; provision the host/VM and front-end JVM heap as well. Capacity failures retain diagnostics and admit no complete result.

```sh
java -Xmx3g -jar "$OMICS_JAR" nfcore-hic210-tools \
  --request request.json --home /private/exact-nextflow22-home \
  --setup-report /private/completed-engine-report --out /opt/new_owned_hic_session

java -Xmx3g -jar "$OMICS_JAR" nfcore-hic210-tools --verify /opt/new_owned_hic_session
```

Use a new session with an existing canonical parent. For a known terminal attempt, `--resume SESSION --home ... --setup-report ...` retains the same producing JAR, source, captured inputs, settings and original path. A request or capacity change requires new paths. A preparation failure without `init.json` also requires new paths. Never restart a live or indeterminate session. An already completed original engine can be reused to finish wrapper checks; prior failed attempts remain retained.

## Results, warnings and required actions

**Require the latest wrapper attempt's `COMPLETED.json` and successful typed `--verify` before using results.** An inner engine marker alone is insufficient. Read `WARNINGS.md`, any `FAILURE.json` and `failure.stacktrace`, original engine trace/logs and export-process diagnostics.

- **SKIP3 / exit 3: analysis skipped.** An exact prerequisite, platform or permitted capability is unavailable. Complete the named setup separately where allowed, supply the exact permitted offline prerequisite, or retain the skip. Analysis performs no downloads or installation.
- **FAIL2 / exit 2: no complete result admitted.** Preserve all attempts. Correct the named input, integrity, numerical, process or capacity problem, using new paths for changed immutable context. Partial engine outputs are retained evidence and do not constitute a completed analysis.
- **Completed selected contracts.** Java streams the entire paired FASTQ cohort and complete literal FASTA; checks all source mapping and pair-classification partitions; checks every valid-pair read ID, order, coordinate and exact seven-field source projection; and rebuilds each selected symmetric-upper raw map. Every exported bin and raw integer pixel must agree, with checked count mass and complete reference geometry. Bin-weight domains are checked without independently refitting balancing.

**NaN balancing weights remain explicitly unassessable.** They are never filled or converted into biological zeros. The source's balanced text dumps use their own `na-rep=0`; the original Cooler files and exported weights remain available to distinguish that formatting from an estimated zero. Sparse software-control data can yield empty original HiCExplorer TAD files; no negative biological conclusion follows. Original missing/null version tokens and other warnings remain visible.

The remaining fits, multiresolution files and plots execute and remain fully captured, but this adapter does not independently reproduce their numerical models. The full graph control uses both TAD callers and the original default `hicpro_maps=false`; it does not validate every optional digestion/HiC-Pro branch. P228 reports Arima, HiCExplorer, MAPQ 10 and GRCh38; its unresolved HiC-Pro attribution, Unicode Bowtie option and unreported engine are preserved in the [source-role audit](literature/NFCORE_SOURCE_WORKFLOWS.md). The yeast software controls do not reproduce that human paper.

Saved verification recomputes the selected contracts from complete captured bytes and exported arrays on Windows or Linux. It does not rerun fits, decode HDF5 again, readmit the host, authenticate execution history or certify biological accuracy. Hashes establish integrity, not authenticity. Preserve the entire session when possible; an archival copy for verification must retain the root context/JAR, all wrapper attempts, and the original engine's complete standalone attempt captures with its latest pointer. Cell Ranger remains excluded. The broader nf-core family and the 250-paper implementation goal remain open.
