# GSEApy execution adapter development

The original runtime, typed request/input validation, process transport and
native ranked/null arithmetic are being integrated. **The analysis command and
complete Java admission audit are unfinished.** Do not use raw original CSVs,
backend summaries or a source-control receipt as an admitted tool analysis.
GSEApy remains missing in the catalog. Totals remain **87 new scoped
integrations**, **90 including existing adapters**, and **254 missing tools**.

The separately validated [native local statistics component](GSEAPY_STATISTICS_DEVELOPMENT.md)
is already usable. It is distinct from this unfinished execution adapter.
The canonical executable is unchanged. New development JARs preserve their
native parent entries and do not register a finished GSEApy command.

The four original editions are **1.0.4, 1.1.2, 1.1.3 and 1.1.8**. Official PyPI
wheels, their corresponding source distributions, Python sources, compiled
backends and MIT licenses are retained. Each edition is installed into a
separate namespace over the read-only project Python 3.11.17 scientific base.
NumPy 1.26.4, SciPy 1.11.4 and pandas 2.2.3 remain bound. Version 1.0.4 has no
GSVA entry point; neither the version nor a paper's unknown analysis mode is
inferred. Each original package is loaded in a fresh interpreter.

Setup is separate from analysis. The four wheels are bundled and intact setup
can run offline. It requires explicit installation permission, NEW case-sensitive
paths and the exact successful base receipt. No CellPhoneDB analysis is needed
to reuse that base. A damaged or missing bundled kit member is a source-integrity
failure: retain that kit and re-export a NEW intact one. A download flag does
not repair an old scientific binding. The base is never modified in place.

**SKIP3 skips dependent analysis** when the compatible permitted base, platform,
storage or installation requirements are unavailable. Read the named setup
error, obtain the exact permitted dependencies and retry NEW paths, or retain
the skip. **RUN installs nothing. FAIL2 admits no case from an incomplete
requested batch**, including earlier completed cases. Preserve all inputs,
failures, provisionals, original/process logs and receipts. Never refresh old
source/runtime binding hashes to relabel a failed analysis as successful.

Execution uses the explicitly declared **original-class interface**. GSEApy
1.0.4's public ssGSEA convenience wrapper does not forward several named
arguments to its class constructor. Earlier public-wrapper controls are retained
as legacy behavior, not proof that every requested setting was used. The new
worker calls the unchanged original classes, checks constructor bindings and
captures effective options. Original ssGSEA represents zero permutations as
None before run and resolves it to zero during run; both states are retained.

Original phenotype GSEA in **1.0.4, 1.1.2 and 1.1.3** records a **raw signed
running curve** while its ES and null scores use absolute power weights.
Edition **1.1.8** weights the metric before both calculations. These are
version-specific source quantities.
Native arithmetic audits each equation separately. Do not replace the original
curve with a weighted curve or silently change the original leading-edge
annotations derived from it. Generic GSEA helpers are not interchangeable here.

The native ranked helper also checks normalization, sign-conditional nominal
P values, pooled-tail FDR and columnwise FWER conditional on original draws.
It does not generate independent permutations. Source missing-sign fallbacks,
strict versus inclusive tails and possible undefined negative FWER are retained.
There is no add-one correction, BH replacement or automatic monotonic FDR
adjustment. Permutation-free ssGSEA normalization uses the complete term/sample
score family together. Source nonfinite diagnostics must remain visible.

Current original controls cover local prepared-library Enrichr, preranked GSEA,
phenotype and gene-set GSEA permutations, rank/log-rank ssGSEA, and Gaussian,
Poisson and direct-ECDF GSVA. The worker observes original backend summaries
before report formatting and saves complete data-only arrays, frames, original
outputs and full-precision TSV exports. It never unpickles user data or patches
scientific function bodies. Effective startup/hash-seed and owned-process
receipts are retained. Process supervision samples wall/output limits and
cleans owned workers; it is not hard OS memory/CPU containment.

Diagnostic pilot runs are explicitly labelled as lacking complete runtime and
scientific admission. Full reference runs additionally compare complete runtime
and base inventories to their bound baselines before and after execution.
Failed worker assertions and earlier provisional cases remain retained.

Remaining work includes the main analysis command, complete input/output and
policy audits, source-preprocessing/identifier diagnostics, wider option and
source-error controls, real timeout/capacity/cancellation checks, portable
export/skip tests, a complete user example, evidence sealing and catalog role
registration. GSVA kernel fitting and Rust RNG/draw generation remain upstream.
Historical remote Enrichr service/library recovery, two-tailed paper-method
discrepancies and unspecified GSEA/GSVA modes are not silently inferred or
claimed reproduced. No complete adapter, full package or paper reproduction
credit is awarded at this stage.

The current foundation checkpoint passed **33 original-class workflows**, with
complete runtime inventories unchanged. Java arithmetic checks **228 walks,
12 original-null families and eight complete ssGSEA families**, comprising
**3,444 numeric states per JVM** on Windows Java 21/25 and Linux Java 21.
The native ES/dense-walk comparison uses `2e-12 * max(1, abs(source value))`;
the captured NES/P/FDR/FWER and complete ssGSEA normalization comparisons are
exact, including zero and nonfinite kinds. Original null draws and GSVA kernel
fitting remain upstream. This is conditional arithmetic checking, not an
independent statistical or biological validation.

Thirteen invalid/unsupported native inputs, immutable-array contracts,
signed-versus-weighted exact boundary examples, zero-mass diagnostics and
missing-sign FWER behavior also pass on each JVM. These boundary assertions are
source-anchored native contracts, not additional original edge executions.
Native normalized-null auditing currently requires finite sort inputs; retain
any original nonfinite score family and its explicit source-only disposition.

The kit export, overwrite refusal and help commands pass on all three JVMs.
A real forbidden-install setup returns SKIP3, records recovery instructions and
creates no runtime prefix. No original analysis runs in these setup contracts.
To export this validated foundation kit from the project root:

```powershell
$gseapyJar = 'build/literature-review/gseapy-runtime/workflow-build-7/omicsmatic-0.3.7-gseapy-workflow-development.jar'
java -cp $gseapyJar org.jlinalg.cli.GseapySetupCli --export build/NEW-GSEAPY-KIT
```

Read the exported SETUP.md and the
[base runtime guide](CELLPHONEDB_WORKFLOW_DEVELOPMENT.md). Export alone installs
nothing. The analysis CLI remains unfinished; do not treat this export command
