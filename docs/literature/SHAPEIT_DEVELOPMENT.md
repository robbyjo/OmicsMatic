# SHAPEIT implementation status

**Current source and the locally built JAR now provide `shapeit-tools` for one controlled SHAPEIT5 common-stage workflow.** Read [SHAPEIT_COMMON_WORKFLOW.md](SHAPEIT_COMMON_WORKFLOW.md) for a copyable recipe, exact runtime setup restrictions, completion checks and recovery. The command stages complete indexed BGZF BCF inputs, authenticates an exact original c34d runtime and its private loader/library closure, admits selected ordinary diploid GT data, launches owned original fitting and checks every output genotype and applied scaffold constraint. The catalog now counts this tested common-stage capability as a scoped upstream adapter. Source-paper editions and the wider SHAPEIT workflow remain unfinished. No released JAR, GitHub publication or deployment of this new command is claimed.

**Legacy SHAPEIT2 runtime analysis is SKIPPED.** No SHAPEIT2 binary was downloaded, installed or executed. Its [original academic terms](https://mathgen.stats.ox.ac.uk/genetics_software/shapeit/shapeit.html) restrict use and redistribution separately from SHAPEIT4/5. Before running a legacy analysis, supply a permitted, eligible installation and identify its exact original build. The Australian paper reports `v.2.12`, which does not uniquely establish an r-build; the Japanese paper separately reports `v.2.837` and `v2.R837`. General installation permission does not identify those binaries or supply missing license eligibility. Preserve the skipped status until both requirements are resolved.

**The historical singleton-posterior workflow remains unvalidated.** The [paper-linked BRaVa wrapper](https://github.com/BRaVa-genetics/snakemake_pipeline_for_phasing/tree/dacb4647a27fa792cd03b14beb2cba3a1f74d7c9) calls for SHAPEIT5 5.0.0 to obtain posterior probabilities for singletons, and its rare-phasing script refers to a local `shapeit/contig` module. The captured repository commit predates the paper, but the paper does not itself pin that commit or the module's binary. Current 5.1.1 controls do not establish this historical behavior. Retrieve and verify the required original source/runtime and posterior output before reproducing that step; skip dependent analyses while it is unavailable. Do not substitute a newer release's singleton behavior or silently omit posterior values.

The ten reviewed paper uses distinguish MVP-supplied pre-phasing, reference and cohort-only phasing, phase-informative reads, common-marker scaffolds, rare variants, downstream posterior filtering and reused external phased datasets. All ten primary XML records and paragraph hashes were checked, with five additional supporting paragraphs. The catalog now contains 744 reviewed uses and 212 supporting pointers; semantic completeness review remains open.

The native API reproduces the initial biallelic target-reader state in original SHAPEIT4 4.1.3 and SHAPEIT5 source commit `c34d4db3e99a2f7e23deb727671ae260901a5886` (banner 5.1.1). It retains exact GT wire values and original sample order, bounds complete populations, rejects changed observed dosage and invalidates an audit permanently after an error. It also exposes two original-reader departures that require scientific review:

- A BCF missing value with a phase bit is `1`; these source readers test missingness against literal `0`. A phase-marked missing allele can therefore be interpreted as reference. The API preserves and counts this behavior.
- A vector-end pad is distinct from a missing allele. A haploid cell in a diploid buffer is retained explicitly. The initial buffer state does not establish correct chromosome-X or later haploid processing.

Raw BCF first-allele phase bits cannot always be reconstructed through a VCF text round trip. The internal `ShapeitBcf` reader now retains these bits directly from BCF2.2, together with physical INFO/FORMAT payloads, integer widths, Float32 bits, padding and sample order. It supports bare BCF and BGZF, checks complete framing, CRCs and EOF, fingerprints the source before and after reading, and fails explicitly when declared capacities are insufficient. Callback rows are provisional until a complete report returns. This reader is not yet connected to a public phasing command. Complete row selection, reference/scaffold joins, phase-set constraints, pedigree/haploid processing, common/rare boundaries, chunk ligation and actual runtime admission still require their own verified workflow. Genotype preservation does not certify phase accuracy, convergence or study suitability.

These codec controls do not establish phasing accuracy or a public adapter.

The raw reader also exposes each complete record's SHA-256 over its original length words, fixed fields, shared block and individual block. Tests compare these identities directly with the untouched bytes of all twelve fixtures and confirm that a quality-only change affects the record identity without changing the genotype hash. Header contig dictionaries and declared INFO tags are retained as immutable metadata. These identities are preparation for file-to-join linkage; they do not establish that linkage.

The internal `ShapeitRawIndex` and `ShapeitJoinedRecords` now link complete raw BCF records to version 2 captures from the original XCF/HTSlib join. The capture binds the exact requested region, canonical region/target intervals, physical record identities, sample order and before/after resource fingerprints. The native linker preserves every INFO/FORMAT byte and checks AC/AN getter values, original record types and biallelic flags against the raw records. It emits the native selector's events; twelve end-to-end controls reproduce every original scanner mask and selected-site order for the corresponding inputs and options. It consumes the original join instead of reconstructing HTSlib pairing.

The disk index stores complete compressed record DTOs and fixed-size coordinate entries. Only one bounded coordinate bucket is retained per input; an on-disk bitmap accounts for physical occurrences. Identical records remain separate occurrences, assigned their original source ordinals in FIFO order within an identical wire identity. Different contig-dictionary orders and arbitrary coordinate lookups do not require loading a whole chromosome's genotype records into memory. Completion requires the full requested-region census, complete capture EOF and unchanged sources, indices, spool files and XCF companions. Default spool limits are 16 GiB total record/index storage, 64 MiB per decoded record, and 250,000 rows/256 MiB of coordinate metadata, in addition to the raw reader's independent sample, record and cell capacities. These are internal development APIs; public capacity and runtime admission controls remain unfinished.

**Skip dependent analysis after a linkage, source-integrity or capacity failure.** Callback data remain provisional until the complete report returns. Preserve original inputs and failed spool/link directories, correct the reported cause and use fresh output directories. Where capacity is insufficient, provision enough disk and Java heap and raise all affected limits for the complete population. Do not sample, truncate duplicate records or reuse a failed directory to turn a partial run into success. FAM tokenization preserves the original ASCII-space/tab, LF and terminal-CR behavior, including inspectable empty or duplicate sample names; this does not admit those names as valid study identities. Whitespace-only FAM lines reach an undefined original splitter boundary and are refused before dependent analysis.

**WARNING: original reference-assisted output AN is not the target allele denominator.** In the controlled c34d runtime, output GT and AC contain target samples, but AN includes target and reference haplotypes. With 10 targets and 40 references, the original output reports AN=100 although the target genotypes contain only 20 allele slots. This occurred on all 377 output rows from the three reference-assisted controls. Preserve the original BCF. Use the audit's separately verified `target-allele-counts.tsv`, which reports target AC/AN alongside source AC/AN, for a target-specific calculation. If a downstream application requires retagged BCF, create and validate a separate derived file with explicit provenance; do not silently alter the original or treat its AN as target AN.

**WARNING: successful execution and scaffold counters do not establish scaffold use.** A retained control with no matching scaffold sample names exits successfully while applying zero constraints. Partially missing target calls can discard an observed allele during imputation; the output audit counts that exposure rather than claiming it preserved the discarded allele. Supply appropriate complete phased reference/scaffold data and separately verified ploidy policies before dependent study analysis.

`org.jlinalg.genetics.ShapeitGeneticMap` now parses and maps the original three-column genetic-map format for SHAPEIT4 4.1.3, SHAPEIT4 4.2.2 and SHAPEIT5 c34d4db. The first line is discarded and the rate column is ignored. Duplicate knots stay in their original order: exact assignments use the last matching knot, while interpolation retains the original neighboring points. Left extrapolation uses the whole-map mean slope. Values are normalized by subtracting the first selected variant's value; the default without a supplied map is 1 cM/Mb. The parser retains original C-locale numeric-prefix coercions, signed zero, hexadecimal values and NaN payloads for inspection. Non-finite parsed data cannot be admitted as a numerical map.

**Skip dependent phasing at an unresolved original map boundary.** Bounds-checked builds of the actual original functions confirmed an out-of-range target-vector read in 4.1.3 when every variant precedes the map, and an out-of-range knot-vector read during right extrapolation in all three inspected profiles. A normal build may appear to return a value; that does not establish defined source behavior. The Java method reports these cases explicitly. Supply a scientifically appropriate complete map covering the selected variants, or separately validate a corrected upstream runtime before running the affected analysis. Empty maps, empty selected populations, whitespace-only parser lines and original signed-counter overflow also have explicit diagnostics. Preserve the original input and failure evidence; do not invent map knots or silently discard variants to obtain a passing run.

For an already verified, complete input population, the native numerical API can be used as follows:

```java
var limits = org.jlinalg.genetics.ShapeitGeneticMap.Limits.defaults();
var map = org.jlinalg.genetics.ShapeitGeneticMap.parse(
    java.util.List.of("position rate cM", "0 ignored 0", "1000 ignored 1"), limits);
var mapped = org.jlinalg.genetics.ShapeitGeneticMap.interpolate(
    map, new int[] {100, 500, 1000},
    org.jlinalg.genetics.ShapeitGeneticMap.Profile.SHAPEIT4_4_2_2,
    org.jlinalg.genetics.ShapeitGeneticMap.Arithmetic.FUSED_BINARY64, limits);
double[] relativeCm = mapped.relativeCentiMorgan();
```

Capacities apply to complete populations and may be explicitly raised with sufficient Java heap. A capacity failure does not authorize sampling or a successful partial analysis.

`org.jlinalg.genetics.ShapeitCommonVariants` now reproduces the common-stage scanner's mask on an already verified original synchronized stream. It preserves target/reference overlap, scaffold-only and reference-only exclusions, original per-record format rules, the target-plus-reference 50-sample guard, exact uppercase SNP filtering and Float32 MAF comparisons. Equality at the threshold is retained; paper wording such as `MAF > 0.001` remains distinct from this source behavior. Signed and typed-missing int32 values retain their original uint32 conversion; the API flags those conversions, zero AN, inconsistent counts and non-finite derived MAF instead of replacing them with counts calculated from GT.
