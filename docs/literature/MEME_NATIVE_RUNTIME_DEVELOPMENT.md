# Native Tomtom source, host and health admission

**Native runtime components are implemented. The public execution workflow
remains unfinished and uncredited.** The catalog remains at 65 new scoped
integrations and 262 missing integrations; Cell Ranger remains excluded. The
[preceding preparation/text checkpoint](MEME_PREPARED_COMPARISON_DEVELOPMENT.md)
retains its complete original source and synthetic execution evidence.

`TomtomRuntime.admit` obtains a fresh in-memory ticket for one exact original
5.5.9 home and one requested capability: `TEXT` or `FULL_REPORT`. It verifies
the source/build receipts, complete installed payload, current native process
and CPU identity, required process helpers, transitive reported ELF/library
bindings, loader/configuration files and declared RPATH search trees. Original
configured-prefix binding is enforced: moving binaries is not assumed to work.
No installation is performed by admission or analysis.

Full-report capability additionally checks the actual original report helper's
Perl interpreter, its fixed source imports, all configured module search roots,
loaded module files and native XML-parser/library bindings. It preserves both
configured root symlinks and exact canonical versioned targets. It repeats the
import probe after dependency closure, then runs the requested full reports.
Text capability omits the external Perl/report checks. Both use a clean process
environment, private owned process directories and the existing strict Linux
process supervisor.

Each capability runs two fresh original synthetic health fits: ED forward and
Kullback with both target orientations. Every one of the ten columns in all nine
reported rows per fit must exactly match the retained original 5.5.9 reference.
The inputs are independently retained original motif files, with no models
derived from output. XML/TSV contracts apply to full reports; the original text
table contract applies directly to text mode. Requested full-report health also
requires the generated HTML carrier. The tiny reference databases do not certify
P-value calibration or biological accuracy.

The ticket verifies the current host, source evidence and completed admission
namespace again before and after supervised downstream calls. It accepts only
the typed requested recipe and its complete unchanged input context. A capability
mismatch is a named skip before launch; the output mode is never changed
automatically. A ticket itself does not admit user data, a fitted result, an
analysis bundle or a public integration. Copied JSON and completion markers
cannot create the private in-memory current-host ticket.

The [frozen runtime proof](meme-native-runtime-development/VALIDATION.json)
records 206 actual-JAR focused checks per JVM on Windows Java 21/25 and Linux
Java 21, with no skipped tests. Every one of the 49 component class files
matches a fresh strict Java 17 compilation. Thirteen classes and five runtime
resource files are added; all prior archive entries remain identical. The new
resource directory's empty JAR marker is checked separately; repository
`.gitattributes` files are source-pinned and omitted by Gradle's copy policy.
Gradle tests and Javadoc pass, and the canonical executable remains unchanged.

The native controls obtain two genuine current-host capability tickets, run
four fresh health fits and two downstream synthetic fits, and verify that no
owned workers survive cleanup. They reject a changed admission namespace and a
different requested capability, and retain a missing-home dependency skip with
no completion ticket. The text receipt has no external Perl capability; the
full receipt binds its exact configured and canonical Perl roots. These are
synthetic controls; no user study is admitted.

Source provenance binds the official 56,535,171-byte archive, all 615 original
C/H file hashes, the exact reference builder, every successful build/version
step and its whole unchanged log, the original source-pin manifest and every
installed file. The original copyright notice and health references are retained.
These checks establish integrity and provenance, not a signature or independent
authentication of an arbitrary supplied build report.

The failed portable Linux-path interpretation, initial JAR-layout verifier
assumption and full-report canonical-root omission are retained. The earlier
passing 204-check/native candidate remains historical evidence. The final
candidate additionally distinguishes missing import dependencies from capacity,
integrity and cleanup failures. Existing shared source/hash/reflection policies
were not weakened.

## Warnings and required actions

**Public user execution is still pending.** Complete the explicit setup/export
interface, requested report-family audit, portable final bundle verification,
public CLI, runnable example and catalog closure before claiming a completed
Tomtom integration. No public `tomtom-tools` command is provided by this
checkpoint. Use a permitted original tool while those gates remain open.

**Unavailable or forbidden dependencies require `SKIP3`.** Supply the exact
original home/build receipts and named helper or resource on a permitted Linux
x86_64 host. Use Linux Java inside WSL when appropriate on Windows. Full reports
require permitted Perl, XML::Parser::Expat and report dependencies; requested
text mode does not require that report capability. If installation or execution
is forbidden, retain the warning and skip the dependent analysis. Admission and
analysis never download, install or change the requested output mode.

**Integrity, cleanup and capacity errors require `FAIL2`, not a dependency
repair.** Inspect the named failure, retained process stdout/stderr/ledgers,
`metadata/host.json` when available, all source/build logs and `WARNINGS.md`.
Only a clean original import failure that identifies a missing Perl module/XML
loader dependency becomes a dependency skip. Memory/CPU/file limits, changed
inputs or host files, failed cleanup and arbitrary import errors remain failures.
Correct the named cause and retry into NEW private canonical Linux paths. Keep
every failed attempt. An invalidated completion marker is retained under an
unadmitted name and cannot authorize execution.

The configured home embeds its original absolute prefix. Rebuild into the
intended location when needed; do not relocate it and rewrite evidence hashes.
