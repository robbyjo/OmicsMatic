## Source findings that affect implementation

Pinned original Seurat 5.6.0 commit:
`75dfa8603befe31505e6287d32dc86c607732bd6`. Fifteen downloaded source files
and their official URLs/hashes are indexed in the snapshot's `SOURCE.json`.
This is an incomplete intake, not a completed runtime source guard. Fetch and
inspect `src/pca.cpp`, `R/RcppExports.R` and the actual RunTSNE implementation
before completing that guard.

- `RunPCA` with `approx=TRUE`, dense scaled input and empty dots first tries
  `EigenGramPCA`; an original internal failure may fall back to IRLBA. Explicit
  IRLBA options such as `tol`/`maxit` bypass that Gram branch. Record the actual
  branch and fallback; do not describe every approximate run as IRLBA.
- Exact PCA calls `prcomp(t(object), rank.=npcs, ...)`, whose default includes
  centering. It may retain a full standard-deviation spectrum: the saved exact
  profile has 80 SDs for ten PCs. Preserve that spectrum and distinguish the
  exact and approximate feature/rank bounds. Do not assume their centering
  semantics are identical.
- Original SNN weight is `shared / (k + (k - shared))`; pruning retains weights
  equal to the threshold. Zero-overlap pairs remain absent even at threshold
  zero. Source neighbors can include self, and SNN can include its diagonal.
- Multiple modularity resolutions use the original multi-resolution routine;
  separate repeated calls can alter RNG semantics. Preserve source labels,
  including possible `singleton` labels, and explicit resolution mappings.
- The prototype explicitly selects the `igraph` Leiden backend. It is not a
  substitute for a requested unavailable `leidenbase` backend. The saved UMAP
  run does not request a reusable model; an RDS containing external pointers
  is not automatically a portable projection model.
