# chromVAR toolbox workflow

Current workspace source exposes `chromvar-tools --request UTF8_JSON` for three modes: original BACKGROUND preparation, native Java DEVIATIONS and Java-only VERIFY of either capture type. The [complete public example](../../examples/chromvar-tools/README.md) supplies every count, reference, range, bias and annotation input. Start there, inspect warnings/status after each analysis and use new output paths.

Use `java -jar JAR chromvar-tools --help` for a summary and `--source-report` for exact paper-edition function/resource hashes and source qualifications. JSON paths resolve against the request directory. In this environment use an ASCII command-line request-file path for Windows Java25; Unicode input/output paths and peak/cell IDs inside UTF-8 requests are tested. The public command selects the mode and the appropriate captured engine without transforming scientific inputs or settings.

Native DEVIATIONS accepts explicit count, annotation and background populations, with optional expectations/groups. Native GC computes `(C+G)/(A+C+G+T)` on supplied uncompressed indexed-reference ranges; ambiguity, masks and gaps are excluded and an empty denominator retains `NaN`. BACKGROUND accepts an explicit bias table or the native reference route, then uses the unchanged source sampler and repeats through the installed current public R Matrix interface. Seeded indices and complete RNG states must agree. See the [background schema, settings and capacities](CHROMVAR_BACKGROUND_DEVELOPMENT.md), [deviation schema and value kinds](CHROMVAR_DEVIATIONS_DEVELOPMENT.md) and [native GC API](CHROMVAR_GC_DEVELOPMENT.md).

**SKIP3 / required action:** BACKGROUND requires R4.6.1, chromVAR1.34.1, Matrix1.7.5, nabor0.5.0, Rcpp1.1.2, RcppArmadillo15.6.2-1 and jsonlite2.0.0 plus their dependencies. R records the Armadillo version as `15.6.2.1`. Set `rscript` and the three private library fields `r_motif_library`, `r_signac_library`, `r_base_library`. These inherited field names describe search paths; this workflow does not require a Signac object/package, and the paths may repeat one complete private library. Supply/install only where permitted. The command performs no automatic installation. If unavailable or installation is forbidden, keep the dependent analysis skipped; do not manufacture a background or proceed without a valid separately prepared matrix.

**FAIL2 / required action:** preserve captures and partials, inspect `WARNINGS.md`, status, manifest, diagnostics and worker logs, correct the named cause and retry into new paths. Invalid identities/reference/index, nonpositive pooled counts, nonfinite or constant bias, insufficient covariance rank, exceeded capacities, worker failure and timeout admit no result. No imputation, peak filtering, contig aliasing, setting substitution or overwrite occurs. Actual dependency skips and owned-worker timeout cleanup are tested.

**VERIFY scope:** native count/reference/GC preparation is recomputed and source, requests, input hashes, runtime declarations, settings, dimensions, index ranges, published/worker agreement, recorded RNG-state agreement, warnings and inventory are checked. R sampling is not rerun and RNG is not independently generated in Java. A retained synthetic adversarial fixture demonstrates that coordinated fabricated worker and published indices followed by rehashing pass structural verification. Hashes provide integrity evidence, not authenticity, proof of execution or biological validation.
