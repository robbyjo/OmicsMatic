# StringTie development: exact native runtime admission

**StringTie user analyses are still unfinished.** This checkpoint adds working
Java admission of the exact original executable on the current Linux host,
including fresh supervised synthetic health. It does not expose a public
assembly, estimation or merge workflow. StringTie remains missing in the
250-paper catalog: 67 new integrations, 70 including three existing adapters,
and 260 missing tools. Cell Ranger remains excluded.

## Warnings and required actions

**SKIP3 means dependent analysis must be skipped.** A missing or forbidden exact
runtime, helper, library, native Linux filesystem, procfs identity or execution
capability is named in stderr and, when an owned work directory can be created,
`WARNINGS.md` and `FAILURE.json`. Read those files and the retained original
process logs. Supply the exact requirement only where installation and execution
are permitted, using the [standalone setup instructions](STRINGTIE_INTAKE_SETUP_DEVELOPMENT.md).
On Windows, execution requires Linux x86_64 Java inside a permitted WSL distro
or another supported Linux host. Setup receipts can also be checked on Windows.
Do not select another edition silently or use setup completion as analysis
completion.

**FAIL2 means no runtime or result is admitted.** Invalid or changed inputs,
payloads, receipts, process failures, failed scientific audits, cancellation,
exhausted capacities and finalization errors preserve an incomplete attempt and
recovery instructions. Preserve every partial, read the named cause and retry
into NEW work paths. Existing work directories are not overwritten. A successful
runtime-health directory has `COMPLETED.json`, its exact manifest/file inventory,
and no `INCOMPLETE.json` or `FAILURE.json`. A later changed file invalidates the
admission token. Hashes establish integrity, not authenticity.

**Runtime health does not admit a user fit or certify biological accuracy.**
The health population has 840 artificial mapped alignments, 120 spliced reads,
four guide transcripts, seven exons and three genes. Every edition fits this same
small population using one thread and reference-only estimation. Results are
compared with the already retained exact-edition original controls; native BAM,
GTF, gene/Ballgown table and source-normalization audits also run. Uncovered
targets, original precision, paths, gene-reduction residuals and denominator
uncertainty remain explicit. Counts and coverage are not independently inferred
from reads, and no biological validation is claimed.

No download or installation occurs during admission. The original licenses and
seven exact payload profiles remain unchanged. Missing dependencies are not
replaced automatically.

## What was implemented

`StringTieSetupEvidence` checks all members of a complete original setup report.
It binds the exact profile/version, installer and runtime lock, permissions used
for acquisition, complete report hashes, original payload declarations and
protected marker hash. Copied report paths remain opaque provenance: portable
verification never opens the producer's home, kit, cache or report paths.

`StringTieRuntime` then checks the actual managed home against that receipt:
complete namespace, exact executable/license bytes, protected marker, private
Linux modes and single-link regular files. It captures the current host's
CPU/kernel/process identity, helper files, declared loader configuration and
recursively reported ELF dependency closure. Consumed RPATH/RUNPATH directories
are checked as complete bounded trees, including when absent. This is the
declared dependency closure, not an attestation of the whole operating system or
arbitrary plugins. Live verification repeats around owned processes and before
final completion.

Version probes, library probes and the fresh original fit use the existing
supervised Linux process engine with an explicit clean environment, private
HOME/TMPDIR, process identities, cleanup, wall and resource limits. The process
engine records the original command, stdout, stderr and ledger. Aggregate RSS is
sampled; it is not a hard aggregate memory limit. These small-health capacities
are not general user-analysis capacities or JVM heap guarantees.

`StringTieHealth` compares all six original tables byte for byte and all GTF
scientific rows against the pinned edition. GTF comments containing invocation
paths remain in the raw output and are excluded only from that predeclared
scientific-row comparison. All native output/normalization checks run without
rounding corrections or forced TPM sums. The runtime completion guard is removed
as the final filesystem commit; errors revoke provisional manifest/completion
files and retain prominent diagnostics.

## Validation and retained evidence

The exact Java17 development artifact, source pins, parent identity and complete
evidence archive are recorded in
[`stringtie-runtime-development/VALIDATION.json`](stringtie-runtime-development/VALIDATION.json).
The canonical/released JAR is unchanged. This checkpoint has not been pushed,
released or deployed, and literature Pages remain withheld.

* 1,335 tests passed without skips on Windows Java21, Windows Java25 and Linux
  Java21: the previous 1,307 controls plus 28 new portable-receipt controls.
* All seven exact editions passed fresh supervised native fits: 1.3.0, 1.3.6,
  2.1.2, 2.1.7, 2.2.1, 3.0.0 and 3.0.3. An eighth fit verified rejection after
  completed admission evidence was changed. That deliberately damaged test
  bundle is retained as invalid evidence, not a reusable admitted runtime.
* Missing runtime and actual forbidden access under UID65534 produced SKIP3.
  Wrong-edition setup, bounded host-capacity failure and cancellation produced
  FAIL2 with retained guards, diagnostics and no successful completion. Windows
  Java21/25 rejected native execution as SKIP3 without creating a work directory.
* Strict compilation and Javadoc passed. All 19,598 entries in the prior
  intake/setup artifact remain byte-identical; only nine new Java classes were
  added. Earlier scientific sources, setup resources and all 396 catalog
  checksums remain unchanged.

The first live validation fit passed its scientific checks but failed when the
report attempted to serialize a normalization record through a restricted shared
JSON writer. That attempt, its source snapshot, raw original fit and failure logs
remain retained. The successful second attempt explicitly encodes the report's
decimal bounds and gene diagnostics; no shared serializer or scientific checker
was weakened. The receipt-fixture preparer also stopped before writing a ZIP
when its initial member-count assertion was wrong (89 instead of the actual 73);
the corrected complete 16-receipt fixture is retained.

The runtime test driver is development infrastructure, not a user-analysis CLI:

```powershell

```

This exact development replay requires the seven previously installed private
homes recorded in the evidence. It never installs missing dependencies. For
another environment, export/install the exact standalone kit first and use the
forthcoming typed workflow rather than treating this test driver as an analysis
interface. Retained private test work is under
`/var/tmp/omicsmatic-stringtie-native-20261103-1` (failed attempt) and
`/var/tmp/omicsmatic-stringtie-native-20261103-2` (successful controls); no worker
is left running and no original setup home was modified.
