# Typed Tomtom preparation, text audit and original component runs

**Development components only; the public execution adapter remains unfinished
and uncredited.** The catalog remains at 65 new scoped integrations and 262
missing integrations. Cell Ranger remains excluded. This phase extends the
[raw motif input checkpoint](MEME_INPUT_CONTRACTS_DEVELOPMENT.md), whose frozen
archive retains the previously tested sources and evidence.

`TomtomRecipe` makes the exact current 5.5.9 profile, complete query/target file
roles, distance, pseudocount, overlap, strand, internal-alignment, score mode,
cutoff, background and text/full-report mode explicit. Unknown flags/settings
are rejected. The original forbids external/uniform `-bfile` selection for ED,
Kullback, Pearson and Sandelin distances; the recipe rejects those combinations
without replacing the requested background. All input/output and supervised
process capacities are validated before an original process can launch.

`TomtomInputs` captures unchanged raw files plus the recipe, independently parses
every captured model, applies source background selection, checks combined
population capacities, and records original paths separately from safe staged
command filenames. `input-ledger.json` and `motif-ledger.jsonl` preserve complete
file/model identities, metadata/defaults and normalization dispositions. Matrices
remain in the unchanged raw files. The protected namespace includes empty
directories, file bytes and modes. A completed context rechecks originals and
the complete captured namespace. Command/output expectations must match the
typed invocation, including the settings not separately printed in original XML.

`TomtomResults.readText` checks the complete original ten-column table against
independent input models and settings. It checks IDs, requested orientations,
source preprocessing/consensus, offset/overlap geometry, P-times-complete-target
E arithmetic, cutoff envelopes, duplicate pairs, whole-table footer/command and
the complete declared Cartesian pair ledger. It preserves float32-to-six-digit
P/E/q tokens and rounding envelopes. There is no synthetic XML or full-report
rerun. Absent pair values remain unavailable; q-values must not be recalculated
from reported best-match rows. Text mode has no independently printed original
XML model or double-precision cross-check, and the receipt says so explicitly.

The [frozen development proof](meme-prepared-comparison-development/VALIDATION.json)
binds 180 focused checks per JVM on Windows Java 21/25 and Linux Java 21, with no
skips. Every one of the 36 component class files matches a fresh strict Java 17
compilation. Only the deliberately evolved TomtomResults source family changes
relative to the prior checkpoint; eleven classes are added. All other earlier
archive entries remain identical. Gradle tests and Javadoc pass. The canonical
executable remains unchanged.

Forty-nine fresh synthetic original 5.5.9 protocols use this actual development
JAR's typed recipes, unchanged capture and strict owned-process primitive:
twenty full reports, twenty corresponding text runs, eight additional text
distances, and a larger Kullback text comparison with the stated P067 distance,
pseudocount and minimum-overlap options. That last fixture has 366 declared
pairs and two reported rows. Paper inputs, the historical unspecified Tomtom
edition and upstream TF-MoDISco trimming are not reconstructed by this fixture.
Every process has a zero exit and no surviving owned workers. Each output table
and full-mode XML contract passes; original report assets, warnings and native
censuses are retained. The original payload and all consumed input bytes/modes
are rechecked. These runs do not yet bind the full current ELF/helper/loader/Perl
dependency closure, so they are component evidence rather than admitted user
analyses or a runtime health ticket.

The archive retains two failed first-pass candidates: the owned JSON serializer
refused a sequence-package record, and a text-only fixture's optional row-count

## Warnings and required actions

**No public `tomtom-tools` command or completed user workflow exists yet.**
Runtime admission and explicit installer/export support, requested report-family
semantics, portable final bundle verification, public CLI, runnable example and
catalog closure remain open. The synthetic test entry point is not shipped in
the executable. Do not treat its receipts as authority to run user analyses.
Use a permitted original tool until the remaining gates are implemented.

**Unavailable or forbidden dependencies mean a named skip.** These components
never install software. Required action: retain the warning/error and identify
the Java/runtime/helper/resource/permission that must be supplied on a permitted
host. Skip the dependent analysis when installation or execution is forbidden.
Text output must not acquire an unrequested Perl/HTML requirement. Full reports
must preserve errors from their requested report helpers even if a main program
returns zero.

**Unsupported source populations are not repaired silently.** Duplicate IDs
within a file, ALLR zeros with zero pseudocount, and query widths above 100 need
a complete source-exclusion/failure ledger before execution. Text rows cannot
disambiguate duplicate target IDs across databases: explicitly select a full
report or retain the analysis as skipped. The output mode is never changed
automatically. Raw snapshots retain the failed populations. The input reader's
HTML, XML-edition, alphabet, score-only and source-truncation limits remain as
documented in the previous checkpoint.

**Original precision and interpretation warnings still apply.** Preserve
stderr, literal zero/underflow values, complete declared and reported families,
and the format-specific STREME XML mappings. Small synthetic databases do not
validate source P-value calibration or biological accuracy. Hashes establish
integrity rather than authenticity. Sampled aggregate RSS is not a hard
aggregate memory bound; process ledgers retain the exact enforced capacities.

On malformed inputs, changed files/namespaces, inconsistent settings, capacity,
process, cleanup or finalization failure, preserve the entire partial attempt,
correct its named cause and retry into NEW capture/output paths. There is no
release, push, deployment, full-paper reproduction or whole-goal completion
claim in this checkpoint.
