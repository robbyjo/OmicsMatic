# PoPS development scope and required actions

**OPEN: no catalog credit.** This is a finite prepared-matrix Java API with
qualified native v0.2 ridge/OLS and feature selection. The user-facing workflow,
bounded feature-file streaming, captured-input replay, v0.1 and original LassoCV
adapters, and cumulative catalog admission remain unfinished. Build current
source and use the example linked in `POPS_NATIVE_DEVELOPMENT.md`; released
v0.4.0 binaries lack this API. Do not infer author commands or reproduce author
analyses from these controls. P236 is a newly recovered score-reuse observation
pending admission; P239's POPS is a lipid and is excluded.

**Retain failures.** The NPY binding failure stopped before model fitting. The
pre-optimization benchmark was intentionally stopped after profiling; its old
code/JAR and process evidence are retained. The qualified implementation uses an
independently tested eigenvalue-only solver. The original no-feature and
unregularized-indefinite-covariance analyses are expected failures with no model.
Never replace their outputs with corrected or fabricated values.
The first private-file readback failed on a Linux symbolic link within the
declared runtime exclusion. The revised consumer prunes that exclusion before
enumeration; the prior consumer source, failure and traceback are retained.

**SKIP3: prerequisites unavailable.** Native fitting needs no Python runtime.
Original control re-execution requires the exact recorded Python/packages.
Install only where allowed; otherwise skip that dependent analysis and state
the missing interpreter/package/version and exact recovery action. Saved-record
verification can be used without installing the original environment. Restore
named private records/primary XMLs when requesting their optional readback; a
missing prerequisite supplies no completion marker.

**FAIL2: verification/analysis failure.** Preserve raw inputs and errors, resolve
the named cause and retry new output paths. Do not repair matrices, substitute
versions, replace NaN marginals with zeros, or change historical verifier hashes.
Version 0.1 is a different workflow and must not be run as v0.2. Downloaded PoPS
tables are score reuse and must not be labeled local PoPS estimation.

The new development consumer checks all existing files against the unchanged
82162f75 baseline and the explicit new files/evidence. The historical whole-catalog
verifier was run unchanged in a genuine clean 82162f75 checkout. Historical
verifiers may reject later extensions; use the new explicit consumer. No verifier
functions, scientific sources or Git identities are overlaid. No biological or
whole-paper validation is established.
