# Native Signac grouped-peak preparation

`org.jlinalg.sequence.SignacPeakPreparation` implements fragment splitting for the paper-described Signac `CallPeaks` workflow. It retains the original Linux `split.cpp` behavior shared byte-for-byte by Signac 1.9.0, 1.14.0 and 1.17.1. This is a preparation API, **not an implemented MACS statistical peak caller or complete CallPeaks interface**. The [synthetic example](../../examples/signac-peak-preparation/README.md) runs with Java only.

The primary paper audit identifies explicit CallPeaks roles in P039 (Signac 1.9.0, MACS2 2.2.7.1) and P051 (Signac 1.14.0, MACS2 2.2.9.1). P153 separately reports MACS2 2.2.9 peak extraction before Signac FeatureMatrix. These roles require original MACS peak calling; the project's generic threshold peaks do not supply that algorithm. Grouped peak calling and coverage visualization remain requirements before full Signac integration. Signac remains missing in the catalog; the credited totals remain **70 new scoped integrations, 73 including existing adapters, and 258 missing named tools**.

## Warnings and recovery

| Condition | Required action |
| --- | --- |
| **Preparation only** | No peaks, p values, FDR or biological conclusions are produced. Run a separately admitted MACS workflow before interpreting peak results. The API does not install external software or create a scientific capture manifest. |
| **SOURCE_GROUP_LABEL_COLLISION** | Original Linux Signac replaces spaces and `/` with `_`, which can collapse distinct labels. Their fragments are pooled as in the source, with every original label retained in the result and an explicit warning. Review the grouping; do not claim separate tests for merged labels. |
| **Missing final newline** | Exact selected record bytes are preserved. When successive source files append to one group, an unterminated record can join the next record. Preserve and inspect the input; do not silently add a newline or admit malformed downstream results. |
| Invalid input, capacity or cancellation | The API throws an exception. No complete result object is returned; owned partial files can remain. Retain the attempt, correct the named input/resource/grouping cause and retry into a **new** destination. Inputs and existing output directories are preserved. |
| **SKIP3: downstream runtime unavailable/forbidden** | Skip dependent peak analysis until the exact permitted MACS runtime is supplied. Preserve setup warnings and logs. Where permitted, install into new private homes; never edit upstream source or shared scientific libraries to force a result. |

## Inputs and source behavior

Each `Source` identifies a local plain or gzip fragment file and an optional explicit one-to-one mapping from object cells to raw barcodes. A null map explicitly declares identical raw/object IDs. `CellGroup` supplies selected object cells in order. Every file is scanned in full; output groups follow the first occurrence of their source-normalized label in that ordered selection. Files append in supplied source order, and duplicate records remain duplicates. Each file can map the same raw barcode to its own object identity.

Input coordinates are zero-based, half-open nonempty intervals. Records have consistently five fields—chromosome, start, end, barcode and read support—or six with strand `+`, `-` or `.`. The fifth field is retained verbatim and never multiplies records. Native admission requires finite-domain nonnegative decimal integers, exact UTF-8, bounded lines and headers before all records. Malformed numeric fields, corrupt gzip and truncated source-buffer records are refused rather than reproducing C++'s permissive or undefined parsing outcomes. No coordinate/name/value repair occurs.

The API preserves complete selected data-line bytes and their original LF/CRLF/no-newline endings. Initial `#` headers are excluded, matching the split source. Output filenames use explicit safe codes `g1.bed`, `g2.bed`, etc.; `Group` separately retains the original-to-source group labels, file and selected record count. The transport code does not rename a biological group.

The Linux profile is explicit on every Java platform. The independently run original Windows R/C++ text stream inserts an additional carriage return before each LF; a CRLF input can therefore become CRCRLF. That platform difference is retained in the fixture rather than silently normalized or claimed equivalent. Native results on Windows and Linux match the unchanged original **Linux** splitting bytes.

Defaults allow two million selected cells, 128 groups/open outputs, original `buffer_length=256`, one billion records and 250 GB decoded bytes per source, and 250 GB total written bytes. A complete raw line must fit `buffer_length-1`, including its line ending; increasing the explicit buffer changes that source option. Limits are admission bounds, not a claim that the JVM heap can hold all allowed mappings. The API does not authenticate caller-owned input stability or reference assemblies; a complete capture workflow must supply those checks.

## Original controls and current validation

Seven original split controls cover unmapped/unobserved cells, object-to-barcode mappings, multiple sources, duplicate records/read support, source-name collisions, explicit strands, CRLF and unterminated-record appending. The full installed Signac 1.17.1 C++ was run on Windows. The unchanged retained Signac 1.9.0 `split.cpp` was compiled and run on Linux using stubs **only** for Rcpp progress output and its interrupt callback; no parsing, grouping or file-writing instruction was replaced. This is an extracted source-core comparison, not a full Linux Signac R installation. Source hashes establish equality of that C++ file in 1.9.0, 1.14.0 and 1.17.1; earlier source editions differ and are not credited by this profile.

Separately retained original R controls execute the unchanged 1.9.0 CallPeaks parser/command construction and its `combine.peaks` branch with explicitly supplied synthetic peak tables. These isolate coordinate conversion, empty output, broad/narrow columns and interval reduction; they **do not perform or validate MACS statistical calling**. The original parser accepts an empty peak table. The empty list of returned groups fails reduction, a distinct domain. Those outputs remain expected references for the complete adapter.

All **32 tests** pass in normal Gradle and against the actual development JAR on Windows Java 21/25 and Linux Java 21. They compare exact original Linux bytes for plain/gzip versions of all seven controls, and exercise malformed inputs, output-byte/group limits, cancellation, unchanged inputs and existing-output refusal. Every parent JAR entry is unchanged. The separate development build leaves the canonical executable unchanged. See [the fixture receipt](../../src/test/resources/org/jlinalg/sequence/signac-peak-preparation/CAPTURE.json) and [the development checkpoint](signac-peak-preparation-development/VALIDATION.json).

## MACS reference work and remaining integration

Official PyPI source archives for MACS2 2.2.7.1, 2.2.9 and 2.2.9.1 are retained with publisher SHA256 comparisons. Exact unchanged builds are being prepared in separate private Linux environments. Their installation attempts and explicit skips/failures are retained under `build/literature-review/signac-runtime/peaks-reference-setup-*`; installation alone admits no peak analysis.

MACS2 2.2.7.1's setup tests `float(sys.version[:3])`, which misreads Python 3.11 as 3.1. The private build therefore uses original Python 3.9.20 and a recorded older packaging toolchain without editing MACS source. A checksum-verified CPython archive retains all original bytes; its unused terminal database is explicitly omitted from the extracted home because case-only aliases form loops on Windows-backed storage. Symlinked venv interpreters preserve the private shared-library lookup, and GCC is selected explicitly because the original CPython build's default clang is unavailable. These are recorded build/runtime choices, not the papers' complete historical environments or a general portable installer claim.

The exact source parses five-column BED as forward-strand records at their start positions; BEDPE uses actual whole-fragment intervals. Read-support values do not weight either mode. The complete adapter must preserve that distinction, typed scoring/settings, per-group/source inputs, source output geometry/statistics, reduction provenance, bounded owned processes, warnings/recovery and independent original MACS controls. Public dispatch, full paper-role curation and coverage visualization remain unfinished. No additional catalog credit, release, push, deployment, full-project test suite, full historical package, biological or whole-paper validation is claimed. Cell Ranger stays excluded and the full 250-paper implementation goal remains active.
