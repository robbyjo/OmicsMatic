# Remaining iDEP integration review

The count runner is a development implementation, not a completed catalog
admission. Its selected current source, original returns and all failed attempts
are preserved in the development checkpoint. No new integration credit is
claimed.

Before admission:

* Complete the separate main-source baseline integration. The unchanged
  SingleR predecessor verifier still refuses the merged study-source changes.
  Preserve that refusal; do not change its baseline or saved hashes simply to
  make the legacy gate pass.
* Qualify additional original caller/session behavior. The checked headless
  all-zero input raises an original Shiny notification error, with no result.
  Keep this error as an error. A session-aware route needs its own genuine
  upstream session, captured notification behavior and original comparisons.
* Broaden controls for exposed VST/rlog branches, aggregation methods, missing
  values, identifiers, design/interactions, input formats and source caps. The
  current paired success controls cover CSV input, disabled mapping, supplied
  max_sd mapping, and one explicit design; they do not qualify every option.
* Review original/effective request coherence in replay. Normal capture deep
  copies all scientific options and relocates paths, but the verifier does not
  yet compare all original JSON options with their effective counterparts.
  Detect contradictions separately from the explicitly absent authenticity
  claim.
* Review provider structural coherence: INSPECTED versus READY fields, declared
  package/dependency roots and complete runtime-index membership. The actual
  checked provider contains 297 packages / 15,604 locked files. Malformed or
  deliberately resealed provider records need additional contradiction controls.
  Hashes do not authenticate an upstream binary.
* Review input path aliases before qualifying them. Source format selection can
  depend on filename extension; current capture resolves the input path before
  selecting its captured basename. Regular-file controls do not establish
  equivalence for a symlink with a differently suffixed name.
* Provide a separately checked installation recipe and any additional operating
  system profiles. The current public entry point audits an existing permitted
  Windows R4.6.1/iDEP2.4.4/DESeq2 1.52.0 runtime and installs nothing. Linux and
  automatic dependency provisioning remain unqualified.

Retain the P050 literal iDEP.96 and unknown deployed source/DESeq2 version.
Project-selected iDEP2.4.4, explicit example cutoffs, locale, RNG and supplied
reference data do not recover author defaults or reproduce that paper. Full GUI,
whole-tool and biological validity remain unqualified. The 250-paper objective,
including the remaining semantic review and missing software families, remains
active.

A separate [genuine-session count profile](IDEP244_SESSION_COUNTS_DEVELOPMENT.md)
now develops session notifications, original/effective request coherence,
provider structural checks and literal input-extension capture without changing
the preserved headless profile. Its controls and limits have their own evidence;
