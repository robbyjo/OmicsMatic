# Original edgeR model evidence

This is scoped development evidence for prepared-count edgeR 3.40.2,
3.42.4 and 4.10.7 on the declared **Windows R 4.6.1** environment and recorded
dependencies. Start with the [method/file guide](../EDGER_MODELS.md),
[synthetic example](../../../examples/edger-models/README.md) and
[remaining work/resume instructions](../EDGER_MODELS_CHECKPOINT_2026-11-20.md).

R/edgeR versions and selected original function bodies/formals are checked.
Dependency identities are recorded; these profiles do not authenticate every
dependency/native binary or establish parity for an untested dependency
environment. Such an environment needs its own original source comparisons.

The final normal source-built producer has 23,471 preceding decoded JAR
members unchanged and 14 additions. No production class overlay is used for
its qualification. The saved evidence records:

- 33 original compositions and **338 exact complete-object comparisons**
  against independent stock exported-API calls. Prepared/estimated DGELists,
  fits, tests, top tables and RNG states match; maximum numeric error is zero.
  Original messages and warning content are retained.
- Two independently reproduced historical null fits at **251 iterations with
  `failed=FALSE`**. Finite stock tables from those requests are refused under
  the current checks. Current 4.10.7 converges on the same input; no edition
  is substituted. Earlier unguarded captures remain historical evidence.
- 55 checks per Windows Java 21/25 and Linux Java 21, with empty PATH and
  missing R bindings, plus all 33 final captures verified on the other two JVMs.
- Actual example RUN/VERIFY/REPLAY, exact result and complete model-RDS replay,
  and real Windows nested/junction and Linux symlink parent protection.
- Owned parent/child cleanup on timeout and output overflow, with independent
  OS liveness checks; an exact-version private package copy with an altered
  function is refused before fitting. Windows live-file length is queried
  through a file handle, avoiding stale directory-entry sizes during writes.
- The preceding native reader, 15 unchanged canonical files and all 820
  existing manifest entries. This milestone assigns **no catalog credit**.

Read the saved data without R, Git or JVM execution:

```text
python -B tools/literature/verify_edger_models.py --out build/edger-model-proof-NEW
```

Optionally add `--jar PATH` for all 23,485 decoded members of the **exact
qualified** producer. Add `--materialize` to reconstruct every saved logical
file under `NEW_OUT/evidence/`; original file contents and capture seals are
unchanged. The archive stores duplicate bytes once by SHA-256. This is storage
deduplication, not a rewritten scientific result. A materialized complete
capture can be passed to the Java command's `--verify` without R.

`QUALIFICATION.json` pins the source files, archive, logical file map and
unique blobs. `READBACK.json` records the initial saved-reader audit.
`PORTABLE-CONTROLS.json` separately records Windows/Linux reader validation,
materialized Java verification and four refusals per host: existing output,
missing packet, changed archive and changed XML with updated archive/blob
hashes. None refreshes original evidence hashes.

The evidence includes complete final original/reference model objects,
original conditions, process logs, XML reports, source payloads and selected
failed/superseded attempts. Complete ignored builds, original runtime installs
and the full development history remain private and require separate permitted
machine transfer. The checkpoint lists exact paths. The saved reader does
not parse binary RDS models or independently refit NB/QL statistics.
