# CADD score-component handover

The complete 250-paper implementation goal remains active. This milestone adds one **scoped native CADD 1.6 component family**, bringing the catalog to **184 scoped families: 37 native and 147 upstream**. It does not qualify the CADD prediction model, genome-wide reference deployment, CADD-SV, or a whole author workflow.

The primary-source audit covers 19 CADD/CADD-SV paper roles in 34 body contexts. Four genuine uses missed by the original method-sentence extractor were recovered in P105, P172, P176 and P186. The paper cohort remains unchanged. Eighteen reviews are new; P192 expands an existing review without duplicate credit. Current totals are **1,924 reviewed uses, 814 pending uses and 2,738 observations**, with 453 labels, 492 provider definitions and 247 missing labels. The frozen journal totals remain 71 Nature, 104 Nature Genetics and 75 AJHG.

The [guide](../../cadd-tools.md) describes the two native operations. LOOKUP captures the original VCF unchanged, records every original allele, supports literal matching or explicit original CADD preparation, preserves all duplicate hits from the first explicitly matching table, and records missing scores as skipped dependent prediction. CALIBRATE preserves raw tokens and uses the complete declared conversion table. Saved verification recomputes all native result files from retained inputs and query candidates without external score files or programs.

Validation includes 19 passing contract tests; all 11,167 boundaries, neighboring representable doubles, interval midpoints and additional edge cases in each complete original GRCh37/GRCh38 conversion table; 89,358 calibration rows on each host; nine complete original/synthetic lookup cases on each host, with 63 source score hits; and 15 packaged refusal/tamper controls. Windows and Linux results are byte-identical, and each host verifies all 11 bundles produced on the other host. The complete six-variant upstream example is retained for both assemblies; strict VCF wrappers add header/QUAL/FILTER/INFO fields without removing original variants or alleles.

The unchanged source controls use CADD-scripts commit `d0a49aeabba01b75d1f0d1061a2f20c1404d1337` (wrapper 1.6.1, score edition 1.6), CPython 2.7.15, pysam 0.11.2.2 and its reported samtools/htslib interface version 1.4.1. The source emits a dictionary-search diagnostic for the NaN probe in each assembly. That stdout remains intact; the native rows explicitly retain the unassessable NaN/NA behavior. This is a component comparison, not a complete CADD environment or model run.

The initial native development build failed a saved-source comparison because a Java set was compared with a serialized JSON array. That was fixed and the failed producer/capture retained. The first oracle install overconstrained Python to an unavailable patch release; the second installed a legacy pysam extension without its required OpenSSL 1.0 ABI. Both failures remain retained. A new isolated environment with the original version-prefix constraints and required legacy ABI completed the unchanged source controls. Existing runtimes and host libraries were preserved.

**Warnings and required actions:** require exit 0, `results_admitted=true`, a fresh saved verification and review of `WARNINGS.md`/`analysis-status.json`. SKIP3 means the dependent analysis was skipped: restore the named permitted exact prerequisite or retain the skip. FAIL2 means no complete result: preserve diagnostics, correct the named data/hash/index/schema/capacity cause and retry new output. Missing, source-omitted and nonfinite alleles remain unassessable. Never fill them with benign/zero scores, alias contigs, swap alleles, change versions or reduce inputs to obtain a result.

The complete official CADD1.6 GRCh38 all-SNV table and companion gnomAD indel table are being acquired privately with official MD5 and complete SHA256 verification. **Genome-wide reference qualification is pending.** The live intake is tracked under private `build/tool-audit-913/download-process-1` and `scores-download-1`; inspect the existing process and completion receipts before taking action. Preserve live transfers, all attempts, complete archives, source scripts, conversion tables, original inputs, failed evidence, producing JARs, the private oracle runtime and scientific captures. Do not restart a live or indeterminate transfer solely because it is slow.

Next, qualify the complete downloaded resource bytes and compare complete intended inputs against the original lookup. Retain unmatched indels as unassessable; a population-indel table does not cover every possible indel. Generating new raw scores requires the complete original annotation/model environment, which is a separate outstanding capability. CADD1.4, CADD1.7, CADD-SV1.1, the BRaVa dbNSFP/VEP recipe and its downstream masks also remain outstanding. Prioritize these alongside the next high-impact gaps rather than treating the component count as full-tool completion. Cell Ranger stays excluded and MaxQuant stays pending with runtime analyses skipped.

No release or literature Pages deployment is requested. Publication and mandatory compiler-temporary cleanup are recorded in the subsequent completion receipt; active reference downloads and required evidence remain retained.
