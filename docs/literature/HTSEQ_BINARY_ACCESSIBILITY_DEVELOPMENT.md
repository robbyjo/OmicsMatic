# Native binary peak-by-cell accessibility development

`HtseqBinaryAccessibility` implements explicit prepared-read presence in Java: a peak–cell coordinate is one when at least one supplied read block overlaps that supplied peak. It reuses the checked immutable HTSeq interval-set index. No Python is needed for native execution. The [runnable example](../../examples/htseq-binary-accessibility/README.md) retains duplicate-read behavior, zero axes, explicit ordering and a capacity refusal.

This is the primitive described by P099's custom HTSeq accessibility scripts. The paper does not state its HTSeq edition, complete ATAC script or effective barcode/read filtering. The Java implementation is compared to actual HTSeq 2.1.2 `GenomicArrayOfSets` steps, followed by an explicit binary-presence reduction. It does not establish paper-exact custom-code equivalence or assign a current version to the historical workflow. The original `htseq-count` gene command is [a separate adapter](HTSEQ_FILE_COUNT_DEVELOPMENT.md).

Supply features, the exact peak-row order, the exact cell-column order and prepared reads. Every declared peak identity must have an interval; every feature identity must occur on the peak axis. Multiple intervals or repeated intervals for one peak contribute set membership. A read can mark several overlapping peaks. A peak–cell coordinate remains one after any number of overlapping reads, intervals or blocks. All-zero peaks/cells and empty dimensions remain explicit. Unknown cell identities and duplicate axis labels are errors; labels are not trimmed, renamed or merged.

Coordinates are exact, nonnegative, zero-based half-open Java `long` values. Zero-length feature insertion and read blocks are refused. Stranded models require explicit `+`/`-` query strands; unstranded models combine strands. The caller supplies block/strand interpretation. There are no implicit mate transforms. Interval-set union is applied across all supplied blocks; unmatched chromosomes/blocks do not erase other overlaps. This does not apply the separate gene counter's whole-unit unknown-chromosome rule or ambiguity/NH policies.

The immutable result exposes the supplied axes, read/overlap statistics, an immutable row-major sparse coordinate view and checked zero-based `accessible(row,column)` queries. Every sparse coordinate has value one. The result does not claim unique molecules, read depth, fragment counts or biological accessibility beyond the supplied read-presence definition. Empty/zero outputs are not negative biological findings.

**Refusals and required action:** invalid axes, cell assignments, coordinates/strands, exceeded logical budgets or cancellation admit no partial matrix. Retain inputs and the exception, correct the named cause and retry. The library does not create an attempt/status folder; callers must retain failed attempts. Missing-runtime skips do not apply to this Java-only method. Any upstream-dependent preparation must separately emit SKIP3 and skip affected analysis when its exact permitted runtime is unavailable or installation is forbidden; provision that runtime only where allowed and retry into new paths.

The default limits are 2,000,000 peak rows, 100,000 cell columns, 10^12 supplied reads and 2,000,000 nonzero coordinates. Absolute maxima are 2,000,000 peaks, 1,000,000 cells, 10^12 reads and 2,000,000 nonzeros. The inherited interval limits separately bound feature records, blocks, matches, spans and labels. Repeated hits to an existing coordinate do not consume additional nonzero capacity, but every supplied read consumes read capacity. These are logical bounds, not resident-memory or full-paper matrix-size guarantees. Larger matrices require another explicitly implemented/storage-tested workflow; no truncation or silent densification occurs.

Original-library controls retain 32 successful synthetic populations, 742 prepared reads, 234 binary nonzero coordinates and 1,278 original interval spans, plus two genuine original interval refusals. Controls include overlapping/adjacent peaks, duplicate features/reads, exact row/cell order, strands, empty inputs, unknown chromosomes, Unicode identities and coordinates above 2^53. The reduction is newly written over actual upstream interval steps; it is not recovered author code or an execution of the original gene counter.

The separate binary development JAR adds only this class family and its source-profile metadata to the file-counting candidate. The method also appears unchanged in the final [HTSeq tools development artifact](HTSEQ_TOOLS.md). Its 43 actual-JAR tests pass without skips on Windows Java 21/25 and Linux Java 21, including every retained original-library matrix/refusal and the stated contracts. The checked example passes on all three JVMs. The canonical/released JAR is preserved. This method does not establish whole-paper reproduction, biological certification or whole-goal completion. Cell Ranger remains excluded.
