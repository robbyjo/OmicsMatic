# scvi-tools integration: development status

**The public neural-model adapter is unfinished. scvi-tools remains outside the completed tool count.** The Java APIs below provide input and likelihood audits; model fitting still uses the original upstream software in private validation controls.

Two public native Java audit APIs are available:

- `org.jlinalg.singlecell.ScviGeneProjection` records exact gene order, shared genes selected before reference training, or explicit zero padding and removal of query-only genes. It retains every missing/removed identifier and both index mappings. Gene symbols, stable identifiers and cross-species orthotypes are not automatically interchangeable.
- `org.jlinalg.singlecell.ScviLikelihood` evaluates the default scvi-tools 1.3.0 NB/ZINB scalar kernels in float64. It preserves additive epsilon and the original softplus threshold. The `auditNegativeBinomial` and `auditZeroInflatedNegativeBinomial` methods also report numerical conditioning. These methods do not train a VAE or predict cell labels.

**Numerical warning:** the initial 11,664-case source grid includes 5,184 cases with a large cancellation diagnostic. Extreme-count evaluations differ from original float64 arithmetic by as much as 64 log-likelihood units. Preserve those discrepancies; a generous rounding envelope is not proof of accuracy. The 320 tested parameters from an actual trained model agree in float64 to about 1.1e-14, while native float64 and original float32 results differ by up to about 9.9e-6. Never silently substitute a float64 audit value for the original training loss.

**Required action:** inspect the returned conditioning flag and retain flagged values and warnings. Use the original model's dtype and loss for training. If the required runtime, model family, paper version, input layer or reference trust cannot be established, skip the dependent analysis until those requirements are supplied and validated.

The source review distinguishes SCVI integration, SCANVI annotation/query transfer, exploratory comparisons and SysVI on transformed expression. In particular, P062 reports SysVI after Pearson normalization; it must not be converted into an NB raw-count scVI workflow. Some papers do not specify their model count layer or annotation model. Those choices require review.

Private synthetic CPU controls exercise SCVI training, SCANVI reference/query transfer, SysVI with standard-normal and default VampPrior settings, and saved-model reloads. They preserve 96 reference cells, 32 query cells and explicit gene padding/order. The provider uses scvi-tools 1.3.0, PyTorch 2.6.0+cpu and Python 3.12.3. This does not reproduce the complete historical 1.0.3/1.2.0 environments or P062's reported Python 3.10 environment, certify preprocessing or establish biological accuracy/convergence.

Classification exports must preserve the learned registry/column order, which need not be alphabetical. The synthetic models return `type_B, type_A`; all 128 native probability argmax labels are checked against the original hard predictions using that order.

Protected matrix/covariate admission, application of native gene projections and closed scientific request types are now validated internally. The current CPU profile also has live native runtime admission, complete synthetic health checks and saved-model metadata/state inspection. Remaining public gates are complete saved-model reconstruction and user-workflow verification, command routing and runnable examples. The eleven source-use drafts are validated separately and have not yet changed the public catalog. The prior catalog remains 703 reviewed uses and 203 supporting pointers.

The likelihood port retains the [upstream BSD license](../../LICENSES/scvi-tools-BSD-3-Clause.txt), also bundled in the executable JAR under `META-INF/licenses/`.

## Protected matrix and covariate inputs

Internal native admission now handles gene-by-cell Matrix Market data, one exact UTF-8 identifier per gene/cell line, and a metadata TSV headed by `cell_id`. Plain UTF-8 and explicit gzip encodings are supported. Every gzip member, CRC and physical trailing byte is checked. Original bytes are copied and hashed; complete gene/cell populations and source paths remain in the audit. No normalization, highly variable gene selection or cell filtering occurs.

Choose the matrix meaning explicitly:

- `RAW_COUNTS` requires nonnegative integer counts. Duplicate coordinates are rejected or summed exactly before checking float32 representation. Zero-library cells fail with their identity; they are not removed. These numeric checks cannot prove that values came from a genuine raw-count layer.
- `SIGNED_EXPRESSION` permits the positive, negative and zero values needed by SysVI. Duplicate summation, when requested, follows source order in float64. Float32 rounding requires explicit permission; every changed coordinate and underflow to zero is recorded. Signed zero-expression cells remain present.

Metadata rows are joined to every matrix cell by exact ID and written in matrix order. Missing, duplicate or unknown cells fail. Batch, categorical, continuous and label roles are explicit; unused columns and literal `NA` strings are retained. Continuous covariate rounding has its own permission and complete conversion ledger. Reference labels, unlabeled-only queries and queries restricted to an explicit reference-label set have distinct contracts. Observed category counts never establish the model's learned class order. Cell summaries use exact count totals or float64 sums of canonical float32 values; they do not replace upstream tensor reductions.

Preparation checks complete input, decoded-byte, sorting, retained-memory and workspace capacities. Source or staged-byte changes and unexpected members invalidate preparation. Hashes check integrity, not authenticity. **`PREPARED_MATRIX_ONLY` and `PREPARED_COVARIATES_ONLY` do not mean a neural analysis completed.**

The earlier input checkpoint passed 31 exact-package tests per JVM and preserved all 416 latent rows and 128 classification rows through five original model controls. The projection/request checkpoint passed 56 exact-package tests per JVM, and the runtime checkpoint passed 100. Current validation passes **114 exact-package tests on each of Windows Java 21/25 and Linux Java 21, with no skips**, including 14 saved-model metadata/state tests. The complete matrix/covariate/projection controls produce 64 identical canonical data and ledger files across those profiles. Six closed scientific requests also serialize identically across JVMs. These are synthetic numerical controls, not paper preprocessing or biological validation.

**The public model command, complete saved-model reconstruction and complete user-workflow verification remain unfinished. Required action:** keep the dependent public model analysis skipped until those gates exist. Exact CPU runtime admission, native export auditors, reviewed model byte preparation and metadata/state inspection are internal validated components. Review the actual count layer or signed-expression provenance and every conversion ledger before downstream use. Current replay controls use `benchmark=False` and retain upstream performance warnings; do not infer GPU or large-study performance from these fixtures.

## Applied gene projections and closed model requests

Internal `ScviProjection` applies shared-gene selection to both datasets **before reference training**, in reference gene order. Fixed-reference queries instead use the fitted gene list with an exact-order policy or explicit zero padding/removal of extra genes. A fitted reference cannot be shrunk to the query intersection. Every retained, padded and removed identifier, source index, cell identity and before/retained/dropped cell sum is recorded. Projected matrices are re-admitted completely: a raw-count cell that becomes empty fails by ID, while a signed-expression zero row remains present. Source, derived and complete workspace populations are checked together. The configured maximum gene count does not reserve memory for genes that are absent.

The fixed-reference control matches all 32 query cells and 40 genes against original `SCANVI.prepare_query_anndata`, including two zero-padded and two removed genes. Shared-gene controls retain 96 reference and 32 query cells over 38 genes. Independent original subsets and native projections produce identical SCVI embeddings, SCANVI embeddings/probabilities/labels and query training histories. The shared control uses five layers, ten latent dimensions, 20 annotation epochs, 100 samples per label and 100 query epochs; its four base SCVI epochs, toy data and remaining settings are explicit synthetic choices. It does not reproduce P019's complete analysis or establish convergence.

Internal `ScviModelRequest` keeps count networks, SysVI signed-expression networks, priors, classifier settings, train/validation splits, seeds, optimizer values, KL warmup and query-freezing policies typed and separate. It retains investigator declarations of the layer, preprocessing, gene selection and cell population; declarations do not prove provenance. Historical release names remain exact, and do not authorize substitution of the installed 1.3.0 provider for 1.0.3 or 1.2.0. Serializing a request neither admits a runtime nor trusts a saved model. Query requests explicitly require reference trust. Model fitting never accepts arbitrary Python code or a free-form keyword dictionary through this contract.

The six Java requests have been consumed by **eight actual original model stages**: SCVI, SCANVI reference/query transfer, both SysVI priors and the shared-gene SCVI/SCANVI/query sequence. All 640 latent rows (5,280 values) and 256 classification rows match previous full original controls bit for bit. Learned class order remains `type_B, type_A`. All eight stages retain finite training metric histories through the original dictionary logger. The new candidate retains every one of the preceding projection JAR's 18,471 members byte for byte and adds only the request classes.

These components remain internal. `PREPARED_GENE_PROJECTION_ONLY`, `runtime_admission_required` and `model_analysis_completed=false` do not certify a completed public neural analysis.

## Verified SysVI 1.3.0 source boundaries

**Default VampPrior can fail on valid matrix dimensions.** The original 1.3.0 code draws pseudoinput **cell** indices using the number of **genes** as the random upper bound. A preserved control with three cells, seven genes, five components and seed 77921 draws `[4, 5, 2, 2, 2]` and the unmodified original constructor raises `IndexError`. Explicit reviewed cell indices `[0, 1, 2, 0, 1]` construct successfully, without fitting a model. When genes are fewer than cells, the original automatic pool is restricted by the gene-count bound.

**Required action:** retain the original failure and diagnostics. For a new run, supply explicitly reviewed, in-range zero-based cell indices and record that change to prior selection, or keep the affected analysis failed. Do not silently clamp indices, change the bound to the cell count or claim equivalence to a paper that used unspecified/default prior selection. A list supplied to the original Python constructor must be converted to its expected integer array.

**SysVI disables KL warmup.** The original `train` method resets both epoch and step warmup to zero and warns when another value is requested. The closed Java contract requires an explicit `NONE` choice for SysVI so the requested and executed settings cannot disagree silently. The source/default-Vamp behavior and historical runtime limits still require admission and result warnings in the unfinished public adapter.

See the pinned [SysVI API](https://docs.scvi-tools.org/en/1.3.0/api/reference/scvi.external.SysVI.html) and original `scvi/external/sysvi/_model.py` from the verified 1.3.0 wheel. The successful replay uses the original `logger=None` dictionary logger; an earlier disabled-logger audit failure and the initial noncanonical JSON comparison are retained separately.

## Live CPU runtime and reviewed model bytes

Internal `ScviRuntime.admit` now validates the declared Linux x86_64 CPU profile with Python 3.12.3, scvi-tools 1.3.0, PyTorch 2.6.0+cpu and 22 pinned distribution versions. The live provider fingerprint covers all 28,567 virtualenv members, 1,345 standard-library members and 306 observed executable-file mappings. A live context verifies those source bytes and its complete managed health tree before/after use. The receipt is evidence; it is not a standalone authorization to open arbitrary models or a certificate for the installation or host OS. New executable mappings in a user model workflow still need audit. Historical 1.0.3/1.2.0 whole runtimes remain unadmitted.

The fixed health run actually fits SCVI, SCANVI reference/query transfer and both SysVI priors, then saves and reloads each model it created. Independent native checks inspect all 136 latent stage rows (408 values), 40 classification rows, class order, hard-label argmax, complete training splits, all finite metric histories and 24 low-conditioning float64 likelihood cases. Reloaded outputs must retain the complete float32 values. These one-epoch, 32-reference/8-query-cell controls test the runtime; they do not establish biological accuracy or convergence.

Torch's original distributed JIT import creates a private temporary import directory and a generated `_remote_module_non_scriptable.py`. The probe captures the complete directory before original cleanup, and Java checks every captured member. Arbitrary external Python import paths remain invalid. Owned process tests also demonstrate wall-time failure, cleanup after a parent leaves a worker alive, and workspace-limit failure; all owned workers finish terminal. Limits distinguish hard per-process AS/CPU/file/nofile bounds from sampled aggregate RSS and monitored workspace/process/thread bounds.

`ScviOutputAudit` provides complete ordered checks for latent values, probabilities, learned class headers, hard labels, train/validation/test cell membership and metric/epoch histories. It rejects missing/extra/reordered cells, nonfinite or undeclared-precision output, incomplete probability mass, duplicate split membership and extra records. A nonfinite value in the final row of the actual health export is rejected. These APIs still need wiring to the complete user model workflow and its admitted registry.

**Saved models require explicit source trust.** Internal `ScviModelBytes` requires a bounded named source review, an exact SHA-256 and an explicit decision permitting original pickle code execution. It copies only the selected binary file, retains original/copy/review hashes, charges source and protected bytes together and refuses subsequent changes or unexpected members. Unreviewed/declined loading stops before a preparation directory is created. Five self-created original health models pass this byte preparation. **No third-party model was opened by these controls.**

**Required action:** review the genuine source of a model before authorizing its loader. A hash proves integrity, not authenticity. `PREPARED_REVIEWED_MODEL_BYTES_ONLY` does not prove the model's actual release, family, gene order, registries, architecture or precision. Those values must be inspected through the admitted original provider and compared with the request before fitting or query transfer. If trust cannot be established, leave dependent model loading skipped. The complete public saved-model workflow remains unfinished.

Missing, forbidden or unsupported exact runtimes are distinguished from integrity/execution errors. The eventual public workflow must report the former as **SKIP3**, preserve the affected analysis as skipped and explain how to supply the permitted profile; it must report the latter as **FAIL2**, retain diagnostics and require a new output path. Current native methods expose typed exceptions; the public command's unified warning/exit handling and copyable recipes remain to be implemented. Failed initial serializer and temporary-import admission attempts are retained rather than relabeled as passed.

## Saved-model metadata and complete state inspection

Internal `ScviModelMetadata.inspect` runs the fixed inspector only after explicit model-byte trust and live runtime admission. It derives the saved release, model family, trained flag, ordered genes, expression layer, registered cell count, batch/label/covariate registries and resolved architecture from the original checkpoint. It compares those facts with the reviewed declarations and applicable typed request. Category types and source order remain explicit: integer `0` differs from string `"0"`, and learned class order is not sorted. SysVI inspection retains the actual saved VampPrior cell indices and does not replace its original selection behavior.

Java independently checks the complete tensor population, including shape, dtype, offsets, hashes, finite floating values and exact boolean bytes. Every state-tree tensor reference must be accounted for once. Non-tensor state, including the original `pyro_param_store`, remains present. Float64 or mixed floating state is recorded and rejected by the float32 analysis profile; inspection does not silently cast it. The fixed inspector and shared provider helper are staged and integrity-checked, and execution identity is checked against the live admitted runtime.

A fresh original CPU control trains and reloads all five health models, then inspects their explicitly reviewed checkpoints: SCVI, SCANVI reference, transferred SCANVI query, SysVI with a normal prior and SysVI with a VampPrior. The native audit covers all **230 tensor entries, 7,657 tensor elements and 30,708 tensor bytes**, preserves the `type_B, type_A` class order and confirms the registered 32 reference or eight query cells. No third-party model is loaded. A failed earlier helper-name collision is retained separately; the successful retry uses a new output directory.

**`VERIFIED_MODEL_METADATA_ONLY` is not completed inference or a complete original neural-network reconstruction. Required action:** retain explicit source trust and require the original strict model loader and complete output checks before any future public query or model analysis. The public adapter remains unfinished and scvi-tools remains outside the completed tool count.
