## What admission now does

`RepeatRuntime.admit` uses a NEW canonical ASCII runtime home separate from the
sealed payload. It captures the complete declared host, prepares fixed health
fixtures and one owned resource/cache tree, runs every original control for the
profile, captures the host again, and requires matching host identities. It
then independently re-reads the retained commands, source copies, zero exits,
cleanup records, complete raw query census, ordered annotation fields and all
expected masked sequences before sealing the runtime.

`RepeatRuntime.open` rechecks the full retained evidence and captures actual
host dependencies into a NEW external verification directory. A runtime must
reopen in a separate JVM. Inventory request order is canonicalized across JVM
map seeds; actual Perl/Python lookup precedence remains in its original order.
Hash-cache counters do not define dependency identity.

The owned-tree seal includes complete file bytes, modes, actual access flags,
empty directories and exact names. Only manifest.json and ADMITTED.json are
excluded from their own recursive inventory; their binding hashes are checked
separately. Symbolic links, missing/extra members, failure markers and changed
metadata are rejected. Retained source members are derived from the pinned
payload, not accepted from their own ledger. Historical working configuration
still permits only the recorded LIBDIR value transformation.
