# CellBender CPU background-removal workflow

The development command `cellbender-tools` runs the **unmodified original
CellBender 0.4.0** CPU full, ambient or swapping model with the MCKP estimator.
Java independently audits the integer counts, populations, identifiers and
filtered outputs before admitting results. This is a bounded integration; GPU,
other estimators, checkpoint import/resume, H5AD input/layer selection, read
quantification, downstream QC and historical/full-paper reproduction remain
outside its validated scope. Cell Ranger remains user-excluded and is not run.

## Required software and permitted setup

Use Ubuntu 24.04 x86_64, CPython 3.12 and Linux Java. On Windows use Linux Java
inside WSL. The pinned profile uses CellBender 0.4.0, PyTorch 2.8.0+cpu and 113
exact dependency wheels. It records all private files, links, Python standard
library files and linked system dependencies. Each invocation checks the
recorded inventory before and after the original process.

Where downloads and installation are permitted:

```sh
python3 tools/literature/install_cellbender.py --home NEW_PRIVATE_HOME --cache PRIVATE_CACHE --report NEW_INSTALL_REPORT --allow-install --allow-download
java -jar JAR cellbender-tools --method check --home PRIVATE_HOME --out NEW_CHECK_DIRECTORY --no-config
```

Use a real absolute path in place of each placeholder. For an offline install,
populate the cache with the exact locked wheels and omit `--allow-download`.
The installer builds a new private environment; it does not install OS packages
or modify a global Python environment. Without `--allow-install`, it only
verifies/reuses an admitted home. It preserves corrupt caches and unmanaged or
changed homes instead of replacing or resealing them. The BSD-3-Clause upstream
notice is retained in `tools/literature/licenses/` and the private installation.

**If software cannot be installed or run where permitted, SKIP the dependent
analysis.** Exit 3 and `WARNINGS.md` name the cause and required action. Supply a
permitted supported host or a new admitted private home and rerun to a new
directory. A dependency check does not analyze counts. CUDA requests skip with
exit 3 on this CPU profile; they never silently fall back to CPU. Do not use the
redacted 0.3.1 release with its corrected-count integer-overflow defect.

## Declare the input and model

Supply three local gene-by-barcode Matrix Market files, optionally gzip:

```sh
java -jar JAR cellbender-tools --method remove-background --home PRIVATE_HOME --matrix raw_matrix.mtx.gz --features features.tsv.gz --barcodes barcodes.tsv.gz --dataset library-1 --feature-reference genes-v1 --count-kind raw-umi --raw-unfiltered true --feature-type "Gene Expression" --device cpu --expected-cells 100 --total-droplets 400 --out NEW_ANALYSIS_DIRECTORY --no-config
```

Flags and values are separate arguments. `--expected-cells auto` and
`--total-droplets auto` explicitly delegate those estimates to the original
model. Preserve empty droplets. Normalized, fractional estimated or prefiltered
counts cannot substitute for declared raw unfiltered UMI counts. The adapter
retains original IDs, sums duplicate coordinates, sorts cell-major using bounded
chunks, preserves raw zero-count features/barcodes and records selected assay
types. An untyped feature table needs an explicit
`--untyped-feature-type "Gene Expression"`; no assay type is inferred.

The worker creates the original loader's gzip-v3 input with explicit feature
types. This avoids the reproduced H5AD/CSR raw-matrix aliasing defect without
patching the original software. Original raw inputs remain unchanged. A single
coordinate above 2^24 fails because the original float32 fitting cannot represent
every larger integer; no rounding or downsampling is substituted.

Defaults are `--model full --epochs 150 --fpr 0.01 --learning-rate 0.0001
--threads 2 --low-count-threshold 5 --z-dim 64 --z-layers 512
--training-fraction 0.9 --empty-drop-training-fraction 0.2
--posterior-batch-size 128`. Ambient and swapping are explicit model choices.
The unchanged upstream random seed is 1234; one training attempt is used, with a
new checkpoint generated by that run. Multiple FPR outputs, automatic retuning,
supplied checkpoints and retry/resume are not admitted by this command.

`--timeout` defaults to 3,600 seconds for fitting. Default bounds are 200,000
features, 2,000,000 barcodes, 50,000,000 stored input entries, 8 GiB compressed
input-file bytes and 16 GiB staged/output bytes. Inspect `--help` for bounded
overrides. These limits do not guarantee the original model/posterior will fit
available RAM. Byte monitoring tolerates the original report generator moving
temporary files; other I/O failures and linked work outputs remain fatal.
Timeouts and resource failures terminate and join owned processes and retain
their PIDs and cleanup outcome.

`--cellbender-options-file UTF8.json` carries string-valued options. Resource
paths resolve relative to that carrier; direct overrides resolve relative to
the current directory. Use an ASCII launcher/carrier path with Unicode paths
inside UTF-8 JSON on Windows. Unknown flags, recursive carriers, non-string
values and control characters fail explicitly.

## Read the results and warnings

**A completed fit still requires model and QC review.** Inspect `WARNINGS.md`,
`analysis-status.json`, `session.json`, `learning-curve.tsv`, all probabilities,
`original/corrected.log`, the original PDF and HTML report. The adapter checks
finite complete learning curves; it does not certify convergence or accuracy.
Original warnings, including small-input and report-kernel diagnostics, remain
prominent. FPR controls signal-count removal; it is not a differential-expression
or GWAS P-value, or a cell-classification error rate.

| Output | Meaning and required review |
| --- | --- |
| `results.tsv` | Separately named all-input, strict `p > 0.5` called-cell and upstream `p >= 0.5` metric populations |
| `cell-counts.tsv` | Every raw barcode, raw/corrected/removed UMIs, detected features, analyzed flag, probability or `NA`, calls and independently computed removed fraction |
| `feature-counts.tsv`, `feature-disposition.tsv` | Every selected feature's counts and original model eligibility; excluded features are not assumed cleaned |
| `filtered-count-verification.tsv` | Per-called-cell SHA256 checks of gene/count coordinates against the full corrected matrix |
| `counts/`, `full-corrected.mtx`, `filtered-corrected.mtx` | Canonical integer matrices with original identity ledgers |
| `upstream-metrics.tsv`, `model-probabilities.tsv` | Original values retained separately from Java audit summaries |
| `original/` | Full and filtered HDF5, posterior, cells CSV, metrics, log, PDF, HTML report and newly generated checkpoint |

Java rejects introduced/increased counts, negative/fractional/overflowed counts,
changed IDs/order, probability or background-fraction disagreements, mismatched
filtered coordinates and wrong count/population metrics. It distinguishes the
upstream strict filtered/CSV threshold from its inclusive metric threshold and
warns if an exact half-probability changes those populations. For the synthetic
reference, all-droplet raw counts are 178,754 and called-cell raw counts 132,542;
corrected counts are 123,071. Those totals must not be conflated.

Exit 0 means a dependency check or an audited fit, distinguished explicitly by
status. Exit 3 means unavailable dependency; exit 2 means input, process or audit
failure. A failed/skipped run admits no successful `results.tsv`; artifacts are
quarantined under `partial/` with root status, session and actionable warnings.
Existing output directories are never overwritten. **Correct the named cause,
preserve inputs and failed attempts, and use a NEW output directory.**

## Evidence and paper scope

The full-model synthetic run matches the independent original reference across
all 64 full/filtered HDF5 datasets plus the metrics and cell-barcode CSVs. Native
and independent Python checks verify counts, per-cell/per-gene marginals, calls,
filtered subsetting, unchanged inputs and process cleanup. Additional original
ambient/custom-network and swapping/automatic-prior workflows cover FPR 0.05/0,
Unicode paths, untyped RNA declarations, reversed/duplicate coordinates,
external sorting and zero feature/barcode retention. Installer and live process
controls check named skips, forbidden setup, corrupt caches, timeout, output
caps and input failures. These are synthetic checks, not biological benchmarks.
