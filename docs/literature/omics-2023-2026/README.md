# Literature-driven omics toolbox expansion

The requested goal is active: catalog 250 recent primary papers from Nature,
Nature Genetics and AJHG, identify the software they use, and implement missing
workflows. The approved approach combines native Java methods and tested upstream
adapters. Downloads and installation are allowed where the operating environment
permits them. An unavailable dependency must skip the dependent analysis and
produce an actionable warning.

### Rank-based signature scores

`signature-score` streams observations by row from a headered TSV whose first
column is `sample_id`, followed by finite measured feature values. Supply a GMT
file containing signature name, description and unique feature IDs.

```powershell
java -jar build/cli/omicsmatic-0.3.7.jar signature-score --method ucell `
  --matrix src/test/resources/signature-scores/expression.tsv `
  --gene-sets src/test/resources/signature-scores/signatures.gmt `
  --max-rank 30 --out build/review-ucell-example
```

- `ucell`: positive signatures and average descending ranks; normalized
  Mann-Whitney formula used in UCell 2.7.6+. Cutoff cannot exceed the measured
  feature count. Signed suffixes, smoothing and complete package parity remain
  outside this subset.
- `aucell`: normalized recovery AUC with an exclusive rank cutoff. Ties resolve
  in input feature order, which differs from upstream R's randomized ranking.
- `ssgsea`: raw integrated-walk scores with integer average-rank weights and
  configurable `--alpha` (default 0.25). This is not kernel GSVA and does not
  normalize scores across the dataset.

Missing genes default to an error. `--missing skip` explicitly changes the tested
signature; UCell also supports `--missing impute`, assigning absent genes the
cutoff rank. `coverage.tsv` records the measured/absent signature sizes. Rank
calculation is shared across signatures for each row. A cell score is descriptive;
donors or other biological replicates remain the unit of population inference.

The frozen fixtures compare 288 outputs from pinned upstream UCell, AUCell and
GSVA scoring functions. They do not exercise the entire R packages. Source
commits, hashes, R session and refresh script are retained under
`src/test/resources/signature-scores/` and
`tools/literature/verify_signature_scores.py`.

### Genomic interval operations

`intervals` provides intersection, merging, subtraction and union coverage.
Inputs are headered TSVs with `chrom`, `start`, `end`, `id` and optional `strand`.
Coordinates are zero-based and half-open; intervals must be nonempty and IDs
unique within an input. An augmented interval tree avoids an all-pairs scan.

```powershell
java -jar build/cli/omicsmatic-0.3.7.jar intervals --method intersect `
  --input features.tsv --mask regulatory-regions.tsv --genome-build GRCh38 `
  --out build/review-intersections
```

All inputs must use the declared assembly and exact chromosome labels. No
liftover or chromosome renaming is inferred. Coverage counts overlapping masks
only once. Merging joins bookended intervals by default. This is a documented
BEDTools-like subset, not complete BEDTools compatibility. Validation includes
the published BEDTools intersection example, nested/stranded randomized comparisons
against independent brute-force overlaps, boundary cases and full CLI workflows.

### Native exact t-SNE

`cell-embed --method tsne` implements exact two-dimensional t-SNE in Java and
needs no Python installation. Supply a headered TSV with unique `obs_id` values
and finite numeric component columns, typically PCA scores. Preprocessing is
explicit: the command does not normalize counts, select features or run PCA.

```powershell
java -jar build/cli/omicsmatic-0.3.7.jar cell-embed --method tsne `
  --matrix pca.tsv --perplexity 30 --iterations 1000 --seed 1 `
  --out build/review-tsne
```

The API is `org.jlinalg.embedding.Tsne.fit(observations, options)`. It calibrates
Gaussian conditional affinities to the requested perplexity, symmetrizes them,
and optimizes the Student-t map using seeded Gaussian initialization, early
exaggeration, momentum and adaptive gains. Defaults are learning rate 50 (with
the conventional factor-four gradient), exaggeration 12, and
`min(250, iterations/4)` early updates. `--learning-rate`, `--early-exaggeration`,
`--exaggeration-iterations`, and `--min-gradient-norm` make these choices explicit.

Exact optimization uses quadratic memory and computation. Limits are 3–2000
observations, at most 10000 components, `N*N*components <= 200 million`,
10000 iterations, and a 64 MiB CLI input. Use a scalable upstream implementation
for larger data. Perplexity must be greater than one and at most `N-1`. Tied
nearest neighbors can impose a higher minimum; unattainable calibration and
coincident observations produce an explicit failure. Uniform global distance
rescaling prevents overflow and preserves the affinity model; it does not
standardize individual components.

`results.tsv` preserves observation order and has `TSNE1` and `TSNE2` columns.
`session.yaml` records all effective settings, JVM version, initial/final KL,
entropy-calibration error and optimizer stopping reason. `diagnostics.tsv`
records the unexaggerated KL and the current gradient norm. Reaching an iteration
budget is reported as `iteration-limit`, not a claim of convergence. A run that
fails to improve KL retains diagnostics and `WARNINGS.md` and publishes no
successful coordinates. The CLI returns status 2 with clear corrective actions.

Frozen tests compare exact affinities, KL and gradients against scikit-learn
1.8.0, then independently check finite-difference derivatives, scale/translation
invariance, reproducibility, and local-neighbor recovery on structured data.
Reference dependency versions/hashes and refresh code are in
`src/test/resources/tsne/` and `tools/literature/verify_tsne.py`. Optimized
coordinates are not asserted to match a different optimizer. This implementation
follows [van der Maaten and Hinton (2008)](https://www.jmlr.org/papers/v9/vandermaaten08a.html);
it does not implement Barnes-Hut/FFT acceleration or out-of-sample transformation.

### Optional upstream cell representations

The adapter consumes supplied PCA coordinates with an `obs_id` first column.
It does not normalize counts, infer cell identities, or perform population
inference from clusters. It pins upstream package versions and records versions,
seed, graph definition, result identities, input/output hashes and process logs.

```powershell
python tools/literature/install_cell_dependencies.py --allow-install --allow-source-build
java -jar build/cli/omicsmatic-0.3.7.jar cell-embed --method umap `
  --matrix pca.tsv --python build/omics-cell-tools-env/Scripts/python.exe `
  --neighbors 15 --seed 1 --out build/review-umap
```

The installer uses a new private managed environment, retains each installation
attempt and pip report, and never modifies an unmanaged environment. Omit
`--allow-install` when installation is forbidden; dependencies are then explicitly
skipped. Source builds require the additional `--allow-source-build` flag.

UMAP uses the upstream Euclidean embedding. Leiden and Louvain operate on an
explicit weighted union kNN graph; this differs from Seurat SNN or Scanpy fuzzy
graphs. Exact graph construction has a documented work bound. Alternatively supply
the original weighted graph directly:

```powershell
java -jar build/cli/omicsmatic-0.3.7.jar cell-embed --method leiden `
  --nodes nodes.tsv --graph edges.tsv --resolution 1 --seed 17 `
  --python build/omics-cell-tools-env/Scripts/python.exe --out build/review-graph
```

`nodes.tsv` has one `obs_id` column listing every node, including isolates.
`edges.tsv` has `source`, `target`, `weight` columns in that order. Edges are
undirected and weights must be positive and finite. Self-loops, duplicate/reversed
edges, unknown endpoints and zero-edge graphs are rejected. No graph normalization
or neighborhood inference occurs. The canonical graph and original weights are
retained in `graph.tsv`; session metadata records isolates, objective and seed.
Limits are 100,000 nodes, 1,000,000 edges and 128 MiB per table. Do not combine this
form with `--matrix` or `--neighbors`. Both real engines passed a known two-community
fixture with an isolated node and repeatability checks. For P061 this accepts its
weighted confusion-matrix graph after explicit construction; its upstream matrix
construction and biological biclustering interpretation remain separate steps.

Harmony requires
metadata with an explicit batch column and the exact observation universe.

```powershell
  --input build/review-sorted/alignment.bam --picard build/omics-picard/picard.jar `

java -jar build/cli/omicsmatic-0.3.7.jar alignment-tools --method validate `
  --input build/review-deduplicated/alignment.bam --picard build/omics-picard/picard.jar `
  --out build/review-validation
java -jar build/cli/omicsmatic-0.3.7.jar alignment-tools --method alignment-summary `
  --input build/review-deduplicated/alignment.bam --reference reference.fa `
  --picard build/omics-picard/picard.jar --out build/review-alignment-metrics
```

Sorting defaults to coordinate order; `--sort-order queryname` is also checked.
Duplicate marking requires both a coordinate header and actual coordinate order;
it marks rather than removes by default. `--remove-duplicates true` requests removal.
Upstream default base-quality scoring/read-name parsing apply. Choose optical pixel
distance for your instrument explicitly (`--optical-distance`, default 100;
Picard recommends 2500 for relevant patterned flowcells). Review upstream warnings
and `duplication_metrics.txt`; PCR duplicates and optical duplicate estimates need
assay and read-name context. P007 used Picard 3.0.0 for ATAC-seq/CUT&Tag PCR duplicate
removal; our 3.5.0 fixture validation does not establish older-version equivalence.

Alignment summary requires a local FASTA and matching `.fai` and `.dict` sidecars;
their hashes are retained. CRAM/reference retrieval, RNA metrics and read-group
editing are outside this adapter. Default memory is 2048 MiB, sortable records
in memory 100,000 and timeout 3600 seconds; change the typed options to suit the
available resources. Temporary spilling remains inside the retained result bundle.

**Read the status and warnings.** A missing/wrong JAR or unavailable Java skips
with CLI status 3. Installation is explicit: omit `--allow-download` if forbidden;
the helper preserves unmanaged or corrupt installations and explains how to recover.
Execution failures return 2, quarantine partial outputs and publish no `results.tsv`.
Validation runs preserve their findings in `validation.txt`: warnings return 0,
errors return **4**, and both create prominent `WARNINGS.md`. Status 4 means the QC
ran and found errors; correct them before downstream analysis. Other upstream
warnings are promoted to `WARNINGS.md` and the console. Commands, version probe,
package checksum, input/output counts, hashes and logs are retained. See the
[upstream command documentation](https://broadinstitute.github.io/picard/command-line-overview.html)
for biological and sequencing-platform decisions.

The executable fixture also exercised paired reads: two complete pairs with one
duplicate pair; removal retained two aligned records, one of each mate, and full
mate validation passed. Evidence: `picard-paired-validation.json` and its retained
SAM/BAM/metrics bundles. On newer JVMs Picard may emit native-access warnings even
with JDK compression selected. They remain visible in `WARNINGS.md`; use a Java
17/21 runtime through `--java JAVA` if those warnings occur. They do not by
themselves mean the analysis failed.

### Sequencing quality control and adapter trimming

`sequence-qc` executes pinned Cutadapt 5.2, FastQC 0.13.0 and MultiQC 1.35. It
uses typed options, independent input/output validation, retained commands,
dependency versions/environment snapshots, source hashes and upstream logs.
Install only in an allowed environment:

```powershell
python tools/literature/install_cell_dependencies.py --profile sequence --allow-install
python tools/literature/install_fastqc.py --allow-download
```

These helpers use private directories and preserve existing unmanaged data.
The FastQC release archive must match the publisher SHA-256 before extraction;
the installed release retains its license, configuration and dependency files.
Existing verified dependencies can be used when further installation is
forbidden. Failed/forbidden installation returns an explicit skip and recovery
steps; successful installation is separate from successful analysis.

Input reads are unwrapped, four-line IUPAC DNA/RNA FASTQ, plain or gzip, using
Phred+33. The command checks every sequence/quality length and both mates'
identities/order after removing terminal `/1` or `/2`. It does not infer quality
encoding. Each read is limited to ten million bases; processing streams without
retaining the reads in memory.

```powershell
java -jar build/cli/omicsmatic-0.3.7.jar sequence-qc --method cutadapt `
  --python build/omics-sequence-tools-env/Scripts/python.exe `
  --reads R1.fastq.gz --reads2 R2.fastq.gz `
  --adapter3 AGATCGGAAGAGC --adapter3-2 AGATCGGAAGAGC `
  --minimum-length 20 --quality-cutoff 20 --out build/trimmed

java -jar build/cli/omicsmatic-0.3.7.jar sequence-qc --method fastqc `
  --fastqc-home build/omics-fastqc/FastQC `
  --reads R1.fastq.gz --reads2 R2.fastq.gz --out build/read-qc

java -jar build/cli/omicsmatic-0.3.7.jar sequence-qc --method multiqc `
  --python build/omics-sequence-tools-env/Scripts/python.exe `
  --reports qc-reports.tsv --out build/combined-qc
```

Adapter sequences are assay inputs; the examples do not infer the correct
sequence for a library. The Cutadapt workflow exposes regular 3-prime adapters,
3-prime quality trimming, `--cut-left` on both mates, minimum length, overlap,
error rate and cores. Paired reads are discarded together if either mate fails
minimum length. Original upstream processing order applies: a fixed cut inside
Cutadapt is not the same as P001's separate fixed-cut step after adapter removal.
Linked/5-prime adapters and demultiplexing require further integration. Outputs
include compressed trimmed FASTQ, `cutadapt.json`, `cutadapt.log` and validated
read-count summaries.

FastQC is launched through its compiled Java entry point, without a Python
launcher. It retains per-file HTML/ZIP reports and a module-status table, and
checks the report version, filename and read total. **WARN/FAIL quality flags
remain visible in `WARNINGS.md` and are not converted into an execution failure
or automatic read removal.** Interpret the modules in the assay/library context
before using the reads downstream.

The MultiQC manifest has columns `sample_id`, `fastqc_zip`, `cutadapt_json`;
provide one or both paths in each row, relative to the manifest or absolute.
Sample IDs are unique ignoring case and contain 1–100 ASCII letters, digits,
underscore, dot or hyphen. Reports are explicitly copied and hashed; scanning
is restricted to those staged inputs. Naming is explicitly mapped to sample
IDs, then exact identities and unscaled raw read counts are checked against
the sources. This prevents silent overwrites when original FASTQ filenames
coincide. Limits are 10,000 rows, 64 MiB per report and 2 GiB total staging.
The HTML and central raw JSON exports remain available. MultiQC AI summaries,
version checks and MegaQC uploads are disabled. `MULTIQC_*` environment overrides
are excluded from child processes; discovered standard user config files are
hashed in the environment snapshot, and naming/output identity checks still
apply.

Unavailable/incompatible dependencies return status 3 with a persisted skip.
Other failures return status 2. Both retain actionable diagnostics; generated
partial analysis outputs are quarantined under `partial/` and no successful
`results.tsv` is published. A completed FastQC run can carry QC findings while
returning status 0. Use a new output directory after correcting the cause.

Real upstream tests cover exact and partial adapter matches, quality tails,
minimum-length filtering, paired fixed cuts/order, low-quality FastQC flags,
and two-sample aggregation with colliding original filenames and different
read counts. The first MultiQC fixture exposed its 1.35 export-layout change;
the adapter now validates the actual `report_saved_raw_data` export. This is a
documented workflow subset, not a claim that every cited package version or
paper-specific option is reproduced.

### Native post-adapter fixed trimming

`sequence-qc --method trim-fixed` performs fixed-span clipping directly in Java.
It exposes the P001 FASTX-Trimmer role as an independent post-adapter step:

```powershell
java -jar build/cli/omicsmatic-0.3.7.jar sequence-qc --method trim-fixed `
  --reads build/trimmed/trimmed_R1.fastq.gz --first-base 2 `
  --out build/post-adapter-clipped
```

Positions are one-based and inclusive on the supplied read. `--last-base 0`
(default) retains through the end; a specified end beyond the read is clamped.
`--minimum-length` defaults to one. Missing/short retained spans are discarded.
With `--reads2`, both mates use the same span and the pair is discarded if
either fails. Headers and clipped qualities are preserved; plus lines are
canonicalized. Empty retained output produces a prominent warning and count
summary. Invalid inputs quarantine partial outputs and return status 2.

The public API is `FixedReadTrimmer.clip(read, options)`, supported by streaming
`FastqIO.Reader`/`Writer`. Eighty frozen results compare against actual Cutadapt
5.2 fixed-cut/length/filter runs, independently checking coordinates, quality
alignment and filtered identities. Fixtures/provenance are under
`src/test/resources/fixed-trim`; refresh with
`tools/literature/verify_fixed_trim.py`. This independently implemented span
operation uses FASTX-Trimmer-like coordinates; full FASTX-Toolkit programs,
FASTA and Phred+64 modes are outside its contract.

### Explicit R Harmony engine on Windows

The R Harmony 2.0.5 engine installs and runs on this Windows environment. The
failed harmonypy 2.1.0 attempt remains a separate Python-engine skip. Select
the R engine explicitly; no automatic result substitution occurs.

```powershell
& 'C:/Program Files/R/R-4.6.1/bin/Rscript.exe' --vanilla `
  tools/literature/install_harmony_dependencies.R `
  build/omics-harmony-r build/literature-review/harmony-r-dependency allow

java -jar build/cli/omicsmatic-0.3.7.jar cell-embed --method harmony --engine r `
  --rscript 'C:/Program Files/R/R-4.6.1/bin/Rscript.exe' `
  --r-library build/omics-harmony-r --matrix pca.tsv `
  --metadata cells.tsv --batch batch --seed 1 --out build/harmony-r-results
```

Adjust the Rscript path to the installed R runtime. The helper checks the pinned
version, installs only required dependencies in a private library, and preserves
an unmanaged existing library. Replace `allow` with `forbid` to prohibit new
installation. CRAN Windows binaries avoid the Python package's MSVC build issue;
installed package versions, paths and checks are retained. Missing or incompatible
dependencies still skip with status 3 and explicit recovery actions.

Input PCA/metadata are headered TSVs with the same unique `obs_id` universe;
metadata is aligned by ID. At least two nonblank batches and finite nonzero
observation rows are required. Limits are 4–100000 observations, 256 components,
five million input coordinate values, ten million observation-cluster entries,
and 128 MiB per input table. Default clusters are
`min(100,max(2,round(N/30)))`, deliberately avoiding the upstream one-cluster
default on tiny datasets. Parameters include `--theta 2 --lambda 1 --sigma 0.1
--iterations 10 --early-stop true`; this adapter uses fixed positive lambda
and one core. Optional `--clusters` and a nonnegative 32-bit seed are explicit.

Outputs preserve IDs/order and all coordinate dimensions. R session/package
versions, effective settings, the upstream algorithm-options object, exploratory
before/after batch centroids, commands and hashes accompany the corrected
coordinates. The adapter records the requested iteration/early-stop settings
without claiming an independently verified convergence state. Upstream warnings
remain visible. Real tests check deterministic repeat, metadata reordering,
batch-shift reduction and retained independent cell-type signal on a balanced
synthetic fixture. This does not establish parity with Python/legacy Harmony
or prove valid correction when batch and biology are confounded.
