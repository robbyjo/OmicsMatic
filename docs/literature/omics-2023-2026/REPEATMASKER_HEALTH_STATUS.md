## What is fixed and checked

`RepeatHealth` packages 13 controls: four current custom-library controls and
nine historical custom/species/simple-repeat controls. They cover N, soft and
X masks, repeated species-cache use, and both genuine no-hit cases. The 56
fixture members and their lock retain exact input and original-output bytes;
the Java class pins the lock hash. Only resource paths and review text in the
recipes are adapted for the packaged layout. Scientific settings are retained.

Expected outputs come from complete, previously audited original controls;
the retained independent original-parser comparisons establish their source.
Every ordered OUT data field is compared. Every masked FASTA header, sequence
length and base is checked without changing case. Data-row spacing and FASTA
wrapping do not define the scientific identity; upstream header syntax is
retained. Valid no-hit masks and summary tables remain absent. They are never
fabricated. Imported annotation structure alone does not establish completion.

Fresh execution of all 13 controls passes: 26 separately supervised original
processes, 26 complete annotation rows, all expected masked bases, and two
no-hit mask/table absences. Independent Python checks reread complete rows,
masked populations, fixture hashes, both exits and process cleanup records.
The separate more-than-ten-million-base compression control also passes.

The 278-test family passes against the exact private JAR on Windows Java21/25
and Linux Java21. Windows passes272 and skips six Linux-only cases; Linux
passes277 and skips one Windows-only case. Strict Java17 compilation and
private Javadoc pass. Tests reject changed scores/rows, masked bases/headers,
invented no-hit outputs, changed fixtures, extra empty directories and partials.
The retained first whitespace test changed the upstream header as well as data
spacing; the corrected test preserves that source syntax. Production code did
not need a change for that test failure.

original access traces account for every selected successful/missing path,
including real cwd changes and directory-fd paths. Dynamic proc/dev/sys paths

All health controls for one profile use one owned resource/cache tree. Every
protected original resource remains pinned. Complete logical bytes count,
including hardlink aliases. Per-control capacities subtract retained prior
controls and fixture bytes/members, and reserve final metadata/diagnostics.
Whole-health checks include the shared complete resource tree. Process limits
apply per original stage. Full hashing and native audits occur outside the
watched child interval; there is no implied whole-health wall deadline.

`build/literature-review/repeatmasker-runtime/health-progress-3` and its linked

## Required recovery and next gate

**Missing, forbidden or unsupported prerequisites: SKIP3 and skip the affected
analysis.** Provide the exact permitted Linux x86-64 profile, inside WSL on
Windows, and pinned local resources. If installation is forbidden, retain the
warning and leave the dependent analysis skipped. Setup is explicit; analysis
and health checks never install or download software. Read the
[payload setup guide](REPEATMASKER_PAYLOAD_SETUP.md).

**Input, integrity, execution or capacity error: FAIL2; partials are not results.**
Read WARNINGS.md, HEALTH_FAILED.txt or HEALTH_FIXTURES_FAILED.txt, both process
ledgers and retained stdout/stderr. Preserve failed directories and their
source/candidate identities. Correct the named cause or reviewed capacities,
then use NEW paths. Never repair a sealed payload in place or infer biological
absence from missing output or a parent exit0.
