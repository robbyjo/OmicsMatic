# SAIGE numerical findings and required actions

**Use the current development candidate named in `saige-numerical-validation.json`.** It adds a guard for original Step-2 PCG nonconvergence and prominent sparse-storage warnings. The earlier association candidate is retained as historical evidence. The canonical executable and release are unchanged.

**Conditional analysis remains unavailable through the project command.** Native conditional PCG, pseudoinverse and Schur-complement components are implemented and checked against original reference runs, but the conditioning-input and conditional reportability contracts are still unfinished. Do not treat these internal components or successful original exit codes as an available conditional workflow.

## Observed behavior

The admitted, unchanged SAIGE 1.5.2 profile was run on binary sparse, quantitative sparse and binary full-GRM LOCO models. Each reference used 1,000 model participants, the original 10,000-participant genotype source and conditioning markers `rs13,rs79`. Native Java reconstructed 372 printed primary/conditional score and variance fields from raw BED calls and primitive model fields. The exact packaged components passed these comparisons on Java 21 and 25.

| Finding | Controlled evidence | Required action |
|---|---|---|
| Sparse Step-2 storage is not reflected automatically | The supplied symmetric MatrixMarket file stores 5,122 entries. The original R setup exports those 5,122 coordinates, which its C++ Sigma constructor uses literally; reflecting the triangle would require 9,244 entries. Native replay reproduces asymmetric conditioning covariance. | Assess this original profile's sparse numerical behavior. Native-checked nonsparse variance paths are identified in the audit ledger. A suitable full-GRM null/variance-ratio workflow avoids requesting Step-2 sparse Sigma. The adapter preserves original behavior and does not silently symmetrize it or certify covariance validity. |
| PCG can reach its iteration limit while the program still exits successfully | The quantitative conditional reference reports 34 PCG nonconvergence messages: two conditioning-marker calls and 32 target calls. Native replay reproduces the iteration-limit behavior. | Resolve the GRM/model/numerical problem before using affected statistics. In the current `single` command, `non_estimable: error` rejects potentially affected sparse-path rows. With `retain-with-ledger`, their canonical statistics are blank and the original output remains unchanged. The original log does not identify every failed marker, so retention is conservative. |
| Binary conditional SPA output has a factor-two P/SE discrepancy | Five conditional SPA rows across the two binary references print a P value at half the standard two-sided value implied by their effect and SE. The source's conditional SPA print branch divides the value by two; its primary branch does not. | Conditional analysis stays unavailable while an explicit probability/reportability contract is developed. Do not silently reinterpret the printed value as a conventional two-sided P value or multiply it by two in an unreviewed pipeline. Extreme log-probability behavior requires separate handling. |
| Conditioning on the target removes its contrast | `rs79` appears as a target in all three references. Its residual contrast is numerically zero, with unstable near-zero variance and nonfinite uncertainty. | Treat the conditional estimate as unreportable, or explicitly exclude conditioning targets with a ledger. Printed P1 is not an estimable null result. |

These are observations for the pinned original profile and controlled fixtures. They do not establish that every SAIGE version, dataset or execution path has the same behavior. Successful arithmetic reconstruction does not prove covariance suitability, convergence or scientific calibration.

## Current checks and limits

The current candidate passes 122 focused tests in 12 suites, strict Java17 compilation, Javadoc and executable packaging. All 122 tests also pass against its exact packaged classes on Java 21 and 25. Six additional production-audit controls verify real quantitative PCG failure rejection/retention, a healthy binary case, explicitly injected failure messages and nonsparse-path isolation. The injected controls are labeled separately from actual original diagnostics.

Earlier 13 single-association workflows and 526 variant rows remain historical reference evidence. Their retained single-test logs have no matching PCG failure messages. The current candidate separately rechecks binary and quantitative IRNT workflows against those original outputs. Read `saige-numerical-validation.json` for exact candidates, counts, hashes and proof scope.

Read every output `WARNINGS.md`, original log and audit ledger. Correct the named cause and use a new output directory. Missing, forbidden, unsupported or changed runtime dependencies still skip with exit3; invalid input, execution, timeout or requested reportability failure returns exit2. No conditional/gene/LD or Meta-SAIGE command is enabled by this milestone. Cell Ranger remains user-excluded.
